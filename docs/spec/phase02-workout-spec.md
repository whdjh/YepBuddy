# 1. 카운트다운 → 운동중 화면

<aside>
⚙️

- **설계 원칙:** 운동 카드 클릭 → 사전 입력 없이 바로 카운트다운 → 운동중 화면으로 진입한다. 부위/세트수/메모는 운동중에 선택적으로 입력한다.
- **HealthKit 연동:** 운동중 화면 진입 시 HealthKit Workout Session을 시작하고, 운동 종료 버튼 클릭 시 즉시 종료한다. 심박수/칼로리는 HealthKit에서 실시간으로 읽어온다.
- **심박수 디바이스:** Apple Watch 또는 AirPods Pro 3를 지원한다. 디바이스가 착용 중이면 HealthKit에 심박수가 자동으로 기록되므로, 앱에서는 HealthKit 데이터 유무로 디바이스 연결 상태를 판단한다.
- **세션 제한:** 하루 1세션 고정. 당일 완료된 세션이 있으면 운동 시작 불가.
- **상태 관리:** React Context + AsyncStorage로 구현한다. 별도 상태 관리 라이브러리를 사용하지 않는다.
</aside>

## 1.1. 운동 시작 조건

1. **심박수 디바이스 체크**
    - 시스템은 운동 시작 버튼 활성화 전에 HealthKit에서 최근 5초 이내 심박수 데이터가 존재하는지 확인한다.
    - 심박수 데이터가 존재하면 운동 시작 버튼을 활성화한다.
    - 심박수 데이터가 존재하지 않으면 운동 시작 버튼을 비활성화한다. 별도 안내 문구는 표시하지 않는다.
    - 이 체크는 메인화면의 운동 카드가 노출되는 시점부터 지속적으로 수행한다.
2. **하루 1세션 제한**
    - 시스템은 당일(00:00~23:59) 완료된 세션이 존재하면 운동 시작 버튼을 비활성화한다.
3. **두 조건의 관계**
    - 심박수 데이터 존재 + 당일 완료 세션 없음 → 버튼 활성화
    - 그 외 → 버튼 비활성화

## 1.2. 카운트다운 화면 (1-A)

- 사용자가 운동 시작 버튼을 누르면 카운트다운 화면으로 진입한다.
- 전체화면, 큰 원형 프로그레스 중앙에 카운트다운 숫자(3, 2, 1)를 표시한다.
- 부위 아이콘 + "근력 강화 운동" 텍스트를 함께 표시한다.
- 카운트다운은 3, 2, 1 고정이며 설정 불가하다.

### 카운트다운 시점 시스템 동작

- **위치 기록:** 카운트다운 시작 시점에 현재 위치를 1회 기록한다.
    - 위치 권한이 거부된 상태면 위치 기록을 스킵한다. 운동 진행에는 영향 없음.
- **알림 취소:** 예약된 운동 리마인더 알림을 즉시 취소한다.

## 1.3. 운동중 화면 (1-B)

### 진입 시 시스템 동작

- 카운트다운 종료 후 운동중 화면에 진입한다.
- 시스템은 HealthKit Workout Session을 시작한다.
    - Workout Session이 시작되면 심박수가 연속 측정되고, 칼로리가 운동 타입 기반으로 계산된다.
- 시스템은 운동 타이머를 시작한다.
- 시스템은 Context의 `phase`를 `'recording'`으로 설정한다.

### 메인 영역 (스크롤 가능)

- **실시간 심박수** — 큰 숫자 + 하트 아이콘. HealthKit에서 실시간으로 읽어와 업데이트한다.
- **활동 킬로칼로리 / 총 킬로칼로리** — 2열. HealthKit에서 실시간으로 읽어와 업데이트한다.
- **운동 부위 선택** — 칩(Chip) 형태: 가슴 | 등 | 하체 | 어깨 | 팔 | 코어 (다중 선택 가능, 선택 안 해도 됨)
- **부위별 세트수 입력** — 선택된 부위마다 독립적인 세트수를 표시한다. 기본값 10세트. 부위를 선택하지 않은 경우 세트수 입력 영역은 노출되지 않는다.
- **메모 입력** — 텍스트 영역, 플레이스홀더: "운동 메모를 자유롭게 작성하세요..."

### 하단 드로어(Drawer)

- 부위 아이콘 + 타이머(MM:SS.ms)
- **중지 버튼** (전체 너비)
- **운동 종료 버튼** (전체 너비)
- **캘린더 연동 버튼** (전체 너비)

### 자동 저장

- 부위/세트수/메모 변경 시 디바운싱(1초) 후 React Context 상태 업데이트 + AsyncStorage에 자동 저장한다.
- 앱 재진입 시 AsyncStorage에서 즉시 복원한다.

## 1.4. 중지 (일시정지)

- 사용자가 드로어의 중지 버튼을 누르면 시스템은 아래 동작을 수행한다.
    - HealthKit Workout Session을 일시정지한다.
    - 운동 타이머를 정지한다.
- 사용자가 재개 버튼을 누르면 시스템은 아래 동작을 수행한다.
    - HealthKit Workout Session을 재개한다.
    - 운동 타이머를 재개한다.
- 일시정지 중에는 심박수/칼로리 측정이 중단된다.

## 1.5. 운동 종료

- 사용자가 드로어의 운동 종료 버튼을 누르면 시스템은 아래 동작을 순차적으로 수행한다.
    1. HealthKit Workout Session을 종료한다.
    2. 운동 타이머를 정지한다.
    3. 세션 데이터를 AsyncStorage에 최종 저장한다.
        - 저장 정보: 운동 시간, 활동 칼로리, 총 칼로리, 부위별 세트수, 메모, 심박수 데이터, 위치, 시작/종료 시각
    4. Context의 `phase`를 `'completed'`로 설정한다.
    5. 운동 리마인더 알림을 종료 시점(`completedAt`) 기준 22시간 후로 예약한다.
    6. 운동 결과 화면(2번)으로 이동한다.
- 캘린더 등록은 운동 종료와 별개로, 사용자가 드로어의 **캘린더 연동 버튼**을 눌러 수동으로 실행한다.

### 캘린더 등록 퍼미션 플로우 (`expo-calendar` + `expo-linking`)

<aside>
⚙️

캘린더 권한은 앱 최초 실행 시 HealthKit, 알림, 위치와 함께 요청한다.

</aside>

- 캘린더 권한이 부여된 상태: 캘린더 연동 버튼 클릭 시 즉시 일정 등록 실행.
- 캘린더 권한이 거부된 상태: 캘린더 연동 버튼 클릭 시 커스텀 모달 표시.
    - "설정으로 이동" → `Linking.openSettings()`
    - "나중에" → 모달 닫기

## 1.6. 백그라운드 동작

- 앱이 백그라운드로 이동해도 HealthKit Workout Session은 유지된다.
    - 심박수/칼로리 데이터는 HealthKit 레벨에서 계속 기록된다.
- 운동 타이머는 경과 시간 기반으로 설계한다.
    - 운동 시작 시 `startedAt: Date.now()`를 Context + AsyncStorage에 저장한다.
    - 포그라운드 복귀 시 `elapsed = Date.now() - startedAt`으로 경과 시간을 역산하여 UI를 즉시 동기화한다.
    - 일시정지 구간은 별도로 누적하여 차감한다.

## 1.7. 앱 크래시 / 강제 종료 복원

<aside>
⚙️

- **설계 원칙:** 운동중 앱이 크래시되거나 강제 종료되어도, 재진입 시 운동중 화면으로 복원하여 사용자의 운동 데이터를 보존한다.
- **복원 기준:** Context의 `phase`가 `'recording'`인 상태가 AsyncStorage에 남아 있으면 복원 대상으로 판단한다.
</aside>

- 앱 재진입 시 시스템은 AsyncStorage에서 `phase` 상태를 확인한다.
- `phase === 'recording'`이면 운동중 화면으로 즉시 복원한다.
    - 저장된 `startedAt`과 일시정지 누적 시간을 기반으로 타이머를 재계산한다.
    - HealthKit Workout Session을 새로 시작한다. *(크래시로 인해 이전 세션은 HealthKit에서 자동 종료됨)*
    - 부위/세트수/메모는 AsyncStorage에서 복원한다.
- `phase === 'completed'`이거나 `phase`가 없으면 정상 메인화면으로 진입한다.

## 1.8. 퍼미션 플로우 요약

<aside>
⚙️

앱 최초 실행 시 HealthKit, 알림, 위치, 캘린더 권한을 순차적으로 요청한다.

</aside>

| 권한 | 요청 시점 | 거부 시 동작 |
|------|-----------|-------------|
| HealthKit | 앱 최초 실행 | 심박수/칼로리 데이터 없음 → 운동 시작 버튼 비활성화 |
| 알림 | 앱 최초 실행 | 운동 리마인더 알림 비활성화 |
| 위치 | 앱 최초 실행 | 운동 가능, 위치만 기록 안 됨 |
| 캘린더 | 앱 최초 실행 | 캘린더 연동 버튼 클릭 시 설정 앱 유도 모달 표시 |

## 1.9. 기술 구현

### 라이브러리

| 역할 | 라이브러리 |
|------|-----------|
| HealthKit 연동 | `react-native-health` |
| 위치 | `expo-location` |
| 캘린더 | `expo-calendar` |
| 설정 앱 유도 | `expo-linking` |
| 햅틱 | `expo-haptics` |
| SVG (프로그레스) | `react-native-svg` |

### 상태 관리

```typescript
// React Context — WorkoutContext
interface WorkoutState {
  phase: 'idle' | 'countdown' | 'recording' | 'paused' | 'completed';
  startedAt: string | null;        // 운동 시작 ISO timestamp
  completedAt: string | null;      // 운동 종료 ISO timestamp
  pausedDuration: number;          // 일시정지 누적 시간 (ms)
  bodyParts: Array<{               // 선택된 부위별 세트수
    part: string;
    setCount: number;              // 기본값 10
  }>;
  memo: string;                    // 메모
  location: { lat: number; lng: number } | null;  // 운동 위치
}
```

- 모든 상태는 React Context로 관리하며, 변경 시 AsyncStorage에 동기화한다.
- 앱 재진입 시 AsyncStorage에서 Context 초기값을 복원한다.
