# 메인 화면 기능서

> 현재 구현 기준으로 정리한 문서.  
> 범위: `메인 탭 진입 → 오늘 요약 확인 → 최근 세션 확인 → 운동 시작/차단 → 주간 세션 조회`

## 1. 문서 목적

이 문서는 YepBuddy의 메인 화면이 어떤 역할을 하는지, 사용자가 첫 진입 시 어떤 정보를 보게 되는지, 어떤 카드가 어디로 연결되는지를 비즈니스 관점에서 이해할 수 있도록 정리한 기능서다.

기획 아이디어나 희망사항이 아니라, 현재 코드에 연결되어 있는 실제 동작을 기준으로 작성한다.

## 2. 기능 한눈에 보기

메인 화면은 사용자가 앱에 들어왔을 때 가장 먼저 보는 요약 허브 화면이다.

핵심 역할은 5가지다.

1. 오늘 운동 요약을 한눈에 보여준다.
2. 오늘 운동 완료 여부에 따라 운동 시작 가능 상태를 제어한다.
3. 가장 최근 세션 1건으로 빠르게 이동하게 한다.
4. 이번 주 세션 목록을 요약 형태로 보여준다.
5. 운동 상세 화면과 운동 실행 화면으로 이어지는 진입점을 제공한다.

## 3. 사용자 흐름

```text
메인 탭 진입
  └─ 메인 화면 로드 시작
      ├─ 오늘 요약 조회
      │   ├─ 로컬 완료 세션 조회
      │   └─ 오늘 HealthKit workout 조회
      ├─ 최근 세션 조회
      ├─ 이번 주 세션 조회
      └─ 오늘 완료 여부 조회
          └─ 화면 렌더링
              ├─ 오늘 날짜 표시
              ├─ 오늘의 운동 카드 표시
              ├─ 오늘 운동시간 / 세트수 표시
              ├─ 최근 세션 카드 표시
              ├─ 운동 시작 카드 표시
              └─ 이번 주 세션 리스트 표시
                  ├─ 최근 세션 카드 탭 → 결과 화면 이동
                  ├─ 운동 시작 카드 탭 → 카운트다운 화면 이동
                  ├─ 오늘의 운동 카드 탭 → 캘린더 이동
                  └─ 주간 세션 화살표 탭 → 결과 화면 이동
```

## 4. 화면 범위

| 화면 | 경로 | 역할 |
| --- | --- | --- |
| 메인 화면 | `/(tabs)` | 오늘 운동 요약, 최근 세션, 운동 시작, 주간 세션 목록을 보여주는 허브 화면 |

현재 구성 기준:

- 화면 본문은 `SummaryScreen`이 담당한다.
- 오늘 요약, 최근 세션, 주간 세션, 오늘 완료 여부를 각각 별도 조회 훅으로 읽는다.
- 메인 화면은 “조회와 이동”이 중심이며, 메모 수정이나 세션 삭제는 여기서 하지 않는다.

## 5. 화면별 기능

### 5.1 메인 화면 진입

사용자는 하단 탭 또는 앱 기본 진입 지점에서 메인 화면으로 들어온다.

현재 동작 기준:

- 진입 시 오늘 날짜를 상단에 표시한다.
- 메인 화면은 여러 저장원에서 데이터를 동시에 읽는다.
- 일부 보조 데이터가 없어도 화면 전체는 열릴 수 있다.

조회 대상:

- 오늘 요약
- 최근 세션
- 이번 주 세션
- 오늘 운동 완료 여부

### 5.2 오늘 날짜 헤더

화면 상단에는 현재 날짜 문자열이 표시된다.

동작 규칙:

- 기기 현재 시각 기준 날짜를 사용한다.
- 날짜 형식은 `MM.DD 요일` 형태다.
- 요일 표시는 앱 번역 리소스를 사용한다.

현재 구현 기준의 의미:

- 사용자는 오늘 기준의 요약 화면이라는 점을 즉시 인지할 수 있다.
- 날짜는 운동 세션 시작 시각이 아니라 “지금 시점” 기준이다.

### 5.3 오늘의 운동 카드

오늘의 운동 카드는 오늘 운동 부위와 오늘 세트 수를 큰 카드 형태로 요약한다.

표시 항목:

- 오늘 운동 부위 문자열
- 오늘 총 세트 수
- 원형 게이지

계산 방식:

- 운동 부위는 오늘 저장된 로컬 세션의 `bodyParts`를 합쳐 문자열로 만든다.
- 운동 부위가 없으면 `미지정`으로 표시한다.
- 총 세트 수는 로컬 세션의 각 부위 `setCount` 합계다.
- 게이지 목표값은 현재 고정 목표처럼 동작하며, 최소 `24`를 기준으로 잡는다.
- 오늘 세트 수가 `24`보다 크면 그 값에 맞춰 게이지 목표도 함께 커진다.

탭 동작:

- 카드를 누르면 현재는 `/calendar`로 이동한다.

현재 제약:

- 오늘 여러 세션을 합산하지 않고, 오늘 날짜에 매핑된 대표 세션 1건 기준으로 표시된다.
- 목표 세트 수는 사용자 설정 기반이 아니라 화면 내부 규칙이다.

### 5.4 오늘 운동시간 / 세트수 카드

오늘의 핵심 지표 2개를 숫자 카드로 보여준다.

표시 항목:

- 운동시간
- 세트수

계산 방식:

- 운동시간은 오늘 날짜의 HealthKit workout 목록 `duration` 합계를 분 단위로 반올림해 계산한다.
- 세트수는 오늘 대표 로컬 세션의 부위별 `setCount` 합계다.

로딩 중 처리:

- 오늘 요약을 아직 읽는 중이면 `--`로 표시한다.

현재 구현 기준의 의미:

- 운동시간은 HealthKit 기반 지표다.
- 세트수는 로컬 저장 기반 지표다.
- 한 카드 안에서도 데이터 원천이 서로 다를 수 있다.

### 5.5 최근 세션 카드

최근 세션 카드는 가장 최근에 저장된 완료 세션 1건을 요약한다.

표시 항목:

- 운동 부위 요약
- 칼로리 영역
- 날짜 문자열

계산 방식:

- 운동 부위는 가장 최근 저장 세션의 `bodyParts`를 문자열로 합쳐 표시한다.
- 부위가 없으면 `미지정`으로 표시한다.
- 날짜는 최근 세션의 `startedAt` 기준으로 `MM.DD 요일` 형식으로 표시한다.

탭 동작:

- 최근 세션이 있으면 `/workout/[sessionId]` 결과 화면으로 이동한다.
- 최근 세션이 없으면 이동하지 않는다.

현재 제약:

- 칼로리 값은 아직 실제 데이터에 연결되어 있지 않아 `--`로 표시된다.
- 최근 세션이 없을 때도 카드 자체는 보이지만 실질 이동은 불가능하다.

### 5.6 운동 시작 카드

운동 시작 카드는 새 운동 세션을 시작하는 진입점이다.

표시 항목:

- 운동 라벨
- 근력 강화 운동 텍스트
- 시작 유도 문구

탭 동작:

- 오늘 운동을 아직 완료하지 않았으면 `/workout/countdown`으로 이동한다.
- 오늘 운동을 이미 완료한 상태면 탭이 비활성화된다.

비활성 규칙:

- 오늘 날짜 키에 완료 세션 ID가 존재하면 비활성화된다.
- 비활성 상태에서는 opacity가 낮아진다.

현재 구현 기준의 의미:

- “하루 1세션 기준” 규칙이 메인 화면 행동 제어에도 반영된다.

### 5.7 이번 주 세션 리스트

이번 주 세션 리스트는 현재 주간 범위 안의 저장 세션들을 요약해서 보여준다.

주간 범위 기준:

- 로컬 시간 기준 월요일 00:00부터 일요일 23:59:59까지

표시 항목:

- 운동 부위
- 운동 날짜
- 운동 시간(분)
- 세트 수
- 칼로리 영역
- 결과 화면 이동용 화살표

계산 방식:

- 세션 목록은 저장된 완료 세션을 날짜 범위로 조회해 최신순으로 읽는다.
- 운동 부위는 각 세션의 `bodyParts`를 문자열로 합쳐 만든다.
- 운동 시간은 `completedAt - startedAt` 차이를 분 단위로 반올림한 값이다.
- 세트 수는 각 세션의 `setCount` 합계다.

이동 동작:

- 헤더의 더보기/셰브론을 누르면 `/sessions`로 이동한다.
- 각 행의 화살표를 누르면 해당 세션의 결과 화면으로 이동한다.

빈 상태 처리:

- 이번 주 세션이 없으면 카드 안에 “데이터가 없습니다.” 문구를 표시한다.

현재 제약:

- 리스트의 칼로리 값은 아직 실제 데이터에 연결되어 있지 않아 `--`로 표시된다.
- 행 전체가 아니라 우측 화살표를 눌러야 결과 화면으로 이동한다.

## 6. 데이터 구성 방식

메인 화면은 여러 저장원을 조합해 만든다.

### 6.1 로컬 저장 데이터

로컬 저장 세션에서 사용하는 정보:

- 오늘 날짜 대표 세션 ID
- 최근 세션 1건
- 이번 주 저장 세션 목록
- 운동 부위 목록
- 부위별 세트 수
- 시작 시각 / 종료 시각

역할:

- 오늘 부위/세트수 계산의 기준이 된다.
- 최근 세션 카드와 주간 세션 리스트의 기본 데이터가 된다.
- 오늘 운동 완료 여부를 판단한다.

### 6.2 HealthKit 데이터

HealthKit에서 사용하는 정보:

- 오늘 날짜의 workout 목록
- 각 workout의 duration
- 각 workout의 kcal

역할:

- 오늘 운동시간 계산의 원천이 된다.
- 오늘 총 칼로리 같은 후속 지표 확장 기반이 된다.

현재 구현 기준 제약:

- 메인 화면에서 HealthKit kcal은 아직 카드 UI에 연결되지 않았다.
- 최근 세션 카드와 주간 세션 리스트 칼로리도 아직 실제 값으로 표시되지 않는다.

## 7. 상태와 예외 케이스

### 7.1 로딩 중 상태

오늘 요약이 아직 끝나지 않으면:

- 운동시간 카드에 `--`
- 세트수 카드에 `--`

현재 구현 기준:

- 별도의 전체 화면 로딩은 없다.
- 카드 단위로 숫자만 placeholder처럼 보인다.

### 7.2 데이터 없음 상태

가능한 빈 상태는 다음과 같다.

- 오늘 저장 세션이 없음
- 최근 세션이 없음
- 이번 주 세션이 없음
- HealthKit workout이 없음

현재 처리 방식:

- 오늘 부위 없음 → `미지정`
- 오늘 세트 수 없음 → `0`
- 최근 세션 없음 → 카드 표시 유지, 이동 없음
- 이번 주 세션 없음 → “데이터가 없습니다.”
- 오늘 HealthKit workout 없음 → 운동시간 `0분`

### 7.3 날짜 변경 반영

메인 화면의 요약 조회 훅들은 날짜 경계에 반응한다.

현재 동작 기준:

- 최초 진입 시 1회 조회
- 앱이 다시 active 되면 재조회
- 자정이 지나면 다시 조회

사용자 관점의 의미:

- 앱을 오래 켜 두고 있어도 날짜가 바뀌면 오늘 요약이 새 기준으로 다시 계산된다.

## 8. 현재 제약 및 비범위

현재 메인 화면에서 지원하지 않는 것:

- 최근 세션 카드의 실제 칼로리 표시
- 이번 주 세션 리스트의 실제 칼로리 표시
- 세션 삭제 / 편집 / 공유
- 목표 세트 수 사용자 설정
- 여러 세션 합산 기반의 오늘 대표 부위 표시

이번 문서 범위 밖:

- 운동 실행 상세 플로우
- 결과 화면 메모 수정
- 캘린더 월별 조회
- 히트맵 형태 대체 UI

## 9. 요약

메인 화면은 “오늘 운동 요약 + 가장 최근 세션 + 이번 주 세션 + 운동 시작”을 하나의 허브에서 제공하는 조회 중심 화면이다.

현재 구현 기준으로 보면:

- 오늘 세트 수와 운동 부위는 로컬 저장 세션 중심
- 오늘 운동시간은 HealthKit 중심
- 최근 세션/주간 세션은 저장 세션 기반 이동 허브
- 운동 시작 버튼은 오늘 완료 여부에 따라 제어

즉 메인 화면은 단순 랜딩 화면이 아니라, 오늘 운동 상태를 확인하고 다음 행동으로 바로 이어지게 하는 요약 대시보드 역할을 한다.
