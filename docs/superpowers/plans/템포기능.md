## 1. 타이머 엔진 (useTempoTimer 훅)

타이머는 `Date.now()` 타임스탬프 기반으로 설계한다.

- [ ] 타이머 상태 관리
  - `status`: idle | contraction | relaxation | rest
  - `startedAt`: 타이머 시작 타임스탬프
  - `currentSet`: 현재 세트 (1부터)
  - `currentRep`: 현재 횟수 (1부터)
  - `segmentStartedAt`: 현재 구간 시작 타임스탬프
  - `remainingRestTime`: 휴식 남은 초 (휴식 중일 때만, null이면 휴식 아님)
- [ ] 구간 진행 순서 계산
  - 수축 먼저 모드 (modeIndex === 0): 수축 → 이완 → 수축 → 이완 → ... (횟수만큼) → 휴식 → 다음 세트
  - 이완 먼저 모드 (modeIndex === 1): 이완 → 수축 → 이완 → 수축 → ... (횟수만큼) → 휴식 → 다음 세트
  - 마지막 세트 완료 후: idle로 복귀 (휴식 없음)
- [ ] 프로그레스 계산
  - 현재 구간의 경과 시간 / 구간 총 시간으로 0~1 progress 계산
  - TempoRingDisplay에 전달

## 2. 사운드 & 햅틱 피드백

사운드는 시스템 사운드로 구현하되, 재생 로직을 `tempoSound.ts`로 분리하여 추후 커스텀 에셋으로 교체 가능하게 한다.

### 사운드 재생 타이밍 (기존 웹 버전 로직 기반)

- [ ] **수축/이완 구간 — 매 1초마다 사운드 재생**
  - 수축: pip 계열 사운드 × 수축시간(초)
  - 이완: pik 계열 사운드 × 이완시간(초)
  - 모드에 따라 순서만 바뀜 (수축 먼저 / 이완 먼저)
- [ ] **rep 완료 시 — 카운트 사운드**
  - 각 rep(수축+이완 1세트) 완료 후 횟수 카운트 사운드 재생
  - 시스템 사운드로 대체 (웹에서는 음성 파일이었으나, 앱에서는 시스템 사운드 1종으로 통일)
- [ ] **휴식 진입 시 — 시작 사운드**
  - 세트 간 휴식 시작 시 사운드 재생
- [ ] **휴식 종료 10초 전 — 예고 사운드**
  - 휴식 남은 시간이 10초일 때 사운드 재생
- [ ] **모든 세트 완료 시 — 완료 사운드**

## 5. 최적화 (기존 웹 버전 대비)

기존 웹 버전은 `for` 루프 + `setTimeout` 체이닝으로 구현되어 있었다. RN에서는 아래와 같이 개선한다.

- **타임스탬프 기반 계산**: `setTimeout` 누적 오차 없이 `Date.now() - startedAt`으로 정확한 경과 시간 계산
- **사운드 프리로드**: 매 초마다 `new Audio()`로 생성하지 않고, 앱 진입 시 사운드 객체를 미리 로드하여 재사용 (`Audio.Sound.createAsync`로 프리로드 후 `replayAsync`로 재생)
- **단일 인터벌**: 1개의 `setInterval` (또는 `requestAnimationFrame`)로 매 프레임/틱마다 현재 시각을 계산하여 구간/세트/횟수를 결정. 루프 중첩 없음
- **순수함수 역산**: `tempoCalculator.ts`에서 `(elapsed, settings) → { set, rep, phase, phaseElapsed }` 형태의 순수함수로 현재 상태를 계산. 백그라운드 복귀 시에도 동일 함수로 즉시 동기화
