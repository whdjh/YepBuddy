# 운동 화면 기능

> 운동 카드 클릭 → 카운트다운(3,2,1) → 운동중 화면. 운동 세션 수명주기, 입력 상태, 저장, 복원, 부가 연동까지 이 문서를 기준으로 정리한다.

## 0. 개요

### 0.1 핵심 설계 원칙
- **즉시 시작**: 운동 카드 클릭 → 사전 입력 없이 바로 카운트다운.
- **운동 가능 조건 단순화**: 심박수 측정 가능 여부와 무관하게 운동 시간 측정 및 기록이 가능해야 한다.
- **HealthKit**: 운동중 화면 진입 시 Workout Session을 시작하고, 종료 버튼에서 즉시 종료한다.
- **심박수는 선택적 데이터**: 심박수 / 칼로리는 수신 가능하면 표시하고, 없어도 운동 세션과 저장 흐름은 정상 동작한다.
- **세션 제한**: 하루 1세션 (로컬 타임존 00:00~23:59).
- **상태 관리**: React Context + AsyncStorage. 별도 라이브러리 미사용.

### 0.2 진입 플로우
```text
메인 (운동 시작 버튼)
  └→ /workout/countdown  (3,2,1)
       │  • 위치 1회 기록
       │  • 예약된 리마인더 알림 취소
       └→ /workout/active
            │  • HealthKit Workout Session 시작
            │  • 타이머 시작
            │  • phase = 'recording'
            │
            ├→ 중지 버튼 → HK pause + timer pause
            ├→ 재개 버튼 → HK resume + timer resume
            ├→ 캘린더 연동 버튼 → expo-calendar 등록 (권한 분기)
            └→ 운동 종료 버튼
                 • HK Workout end
                 • AsyncStorage 최종 저장
                 • phase = 'completed'
                 • 리마인더 22h 후 재예약
                 └→ /workout/[sessionId]  (Phase 02 결과 화면)
```

## 1. 기능 요구사항

### 1.1 운동 시작 조건
`enabled = !hasTodayCompletedSession`
- 당일 완료 세션이 없으면 운동 시작 가능.
- 심박수 디바이스 연결 여부는 시작 조건에 포함하지 않는다.
- 당일 세션 체크는 메인화면 운동 카드 노출 시점부터 지속적으로 갱신한다.

### 1.2 카운트다운 화면 — `/workout/countdown`
- 전체화면, 큰 원형 프로그레스 중앙 숫자(3 → 2 → 1), 각 1초.
- 부위 아이콘 + "근력 강화 운동" 텍스트.
- 카운트다운 중 시스템 동작:
- 위치 1회 기록 (`expo-location`). 권한 거부 시 스킵.
- 예약된 리마인더 알림 취소 (`expo-notifications`).
- 카운트다운 종료 시 자동으로 `/workout/active`로 교체 (`router.replace`).

### 1.3 운동중 화면 — `/workout/active`
- 메인 영역 (스크롤):
- 실시간 심박수 + 하트 아이콘
- 활동 kcal / 총 kcal (2열)
- 부위 칩 다중 선택(가슴/등/하체/어깨/팔/코어)
- 선택된 부위별 세트수 (기본 10, 미선택 시 노출 안 함)
- 메모 입력 (placeholder: "운동 메모를 자유롭게 작성하세요...")
- 하단 드로어:
- 부위 아이콘 + 타이머 (`MM:SS.ms`)
- 중지/재개 버튼 (전체 너비)
- 운동 종료 버튼 (전체 너비)
- 캘린더 연동 버튼 (전체 너비)
- 자동 저장: 변경 시 1초 디바운싱 → Context + AsyncStorage.
- 심박수 데이터가 없으면 `StatsSection`은 빈 상태(`--` 등)로 표시한다.

### 1.4 중지 / 재개
- 중지: HK session pause, 타이머 정지, `phase = 'paused'`.
- 재개: HK session resume, 타이머 재개, `phase = 'recording'`.
- 심박수 / 칼로리 측정은 가능하면 재개하고, 불가해도 세션 자체는 유지한다.

### 1.5 운동 종료
1. `AppleHealthKit.saveWorkout(...)` 또는 Workout Session end
2. 타이머 정지
3. AsyncStorage 최종 저장
4. `phase = 'completed'`
5. 리마인더 알림 예약 (`completedAt + 22h`)
6. `/workout/${sessionId}`로 이동

### 1.6 앱 크래시 / 강제 종료 복원
- 앱 진입 시 AsyncStorage의 `phase` 확인.
- `phase === 'recording'` 또는 `phase === 'paused'` → `/workout/active`로 즉시 복원.
- 타이머는 `startedAt` + `pausedDuration` 기준으로 재계산.
- HK Workout Session은 크래시로 이미 종료됐을 수 있으므로 필요 시 새로 시작.

## 4. 상태 관리

### 4.1 타입

`src/features/do-workout/model/types.ts`

```typescript
import type { BodyPart } from "@/entities/workout-session/model/types"

export type WorkoutPhase = "idle" | "countdown" | "recording" | "paused" | "completed"

export interface WorkoutState {
  phase: WorkoutPhase
  sessionId: string | null
  startedAt: string | null
  completedAt: string | null
  pausedAt: string | null
  pausedDuration: number
  bodyParts: Array<{ part: BodyPart; setCount: number }>
  memo: string
  location: { lat: number; lng: number } | null
  heartRate: number | null
  activeKcal: number
  totalKcal: number
}
```

### 4.2 Context / Reducer
- `WorkoutContext`에서 운동 세션 전역 상태 관리
- `START_COUNTDOWN`, `START_RECORDING`, `PAUSE`, `RESUME`, `COMPLETE`, `RESET`, `HYDRATE` 액션 사용
- `startedAt` ISO 문자열을 `sessionId`로 재사용

### 4.3 영속화
- 현재 세션은 `yb:workout:current` 키로 저장
- 변경 시 1초 디바운싱 저장
- `idle`, `completed` 상태에서는 현재 세션 스토리지 제거

## 5. AsyncStorage 영속화 / 복원

### 5.1 현재 세션 저장
- 운동중 입력값, 상태값, 시간값을 현재 세션 스냅샷으로 저장
- 앱 크래시 / 강제 종료 후에도 복구 가능해야 함

### 5.2 완료 세션 저장
- 완료 시 `sessionId`, `bodyParts`, `memo`, `location`, `startedAt`, `completedAt` 저장
- Phase 02 결과 화면과 Phase 03 요약 / 캘린더 조회의 공통 소스로 사용

### 5.3 복원 규칙
- `recording` / `paused` 상태면 운동중 화면으로 이동
- `startedAt`, `pausedAt`, `pausedDuration` 기준으로 타이머 재계산
- HK 세션은 복원 시점에 다시 시작할 수 있도록 설계

## 6. 타이머

### 6.1 규칙
- `startedAt` 기반으로 실시간 경과 시간 계산
- 일시정지 중에는 `pausedAt` 시점으로 고정
- 재개 시 `pausedDuration`에 누적 반영
- 백그라운드 복귀 시 `Date.now()` 기준 재계산

### 6.2 표시 형식
- `WorkoutDrawer timerDisplay` → `MM:SS.ms`

## 7. HealthKit 연동

### 7.1 권한 요청
- 초기 진입 시 `initHealthKit()` 호출로 권한 확보

### 7.2 연동 원칙
- `react-native-health`는 공식적인 live workout session API가 제한적이므로 폴링 + `saveWorkout(...)` 조합 사용
- 운동중에는 심박수 / 활동 kcal / 총 kcal를 주기적으로 갱신
- 운동 종료 시 `saveWorkout(...)` 호출로 HKWorkout 저장
- 심박수나 칼로리 데이터 조회 실패는 운동 지속 조건이 아니라 선택적 데이터 실패로 처리

### 7.3 UI 계약
- `StatsSection heartRate`: `number | null`
- `StatsSection activeKcal`: `number`
- `StatsSection totalKcal`: `number`
- `heartRate === null`이면 `--` 표시

## 8. 카운트다운 화면

### 8.1 동작
- 진입 시 `START_COUNTDOWN`
- 위치 1회 기록
- 예약된 리마인더 알림 취소
- 3초 카운트다운 종료 후 `START_RECORDING`
- `/workout/active`로 전환

## 9. 운동중 화면

### 9.1 상태 연결
- `StatsSection` ← `heartRate`, `activeKcal`, `totalKcal`
- `BodyPartChips` ← 선택된 부위 배열
- `SetCountInputs` ← 선택된 부위별 세트수
- `MemoInput` ← `memo`
- `WorkoutDrawer` ← `timerDisplay`, `paused`, `onPauseToggle`, `onEnd`, `onCalendar`

### 9.2 자동 저장
- 부위 / 세트수 / 메모 변경 시 1초 디바운싱
- Context와 AsyncStorage를 같이 갱신

### 9.3 종료 플로우
- HK 저장
- 완료 세션 저장
- 22시간 후 리마인더 예약
- 결과 화면 이동

## 10. 캘린더 연동

### 10.1 권한 분기
- 캘린더 버튼 클릭 시 권한 확인
- 미허용이면 `requestCalendarPermissionsAsync()`
- 여전히 거부면 `Linking.openSettings()` 유도

### 10.2 등록 규칙
- `startedAt`, `completedAt`, `memo`를 기반으로 일정 생성
- 완료 시 Alert로 결과 피드백

## 11. 알림

### 11.1 리마인더 규칙
- 카운트다운 진입 시 기존 예약 취소
- 운동 종료 시 `completedAt + 22h`에 리마인더 예약

### 11.2 유틸 계약
- `scheduleReminder22h(completedAtIso)`
- `cancelScheduledReminders()`

## 12. 백그라운드 / 복원

- `AppState`가 `active`로 돌아오면 타이머는 자동 동기화
- `useRestoreWorkoutOnMount()`가 `_layout.tsx`에서 복원 실행
- HK Workout Session은 크래시 후 자동 종료될 수 있으므로 폴링 / 저장 재시작 기준으로 복구

## 13. 퍼미션 플로우 요약

| 권한 | 요청 시점 | 거부 시 동작 |
|------|-----------|-------------|
| HealthKit | 앱 최초 실행 (`initHealthKit()`) | 심박수 / 칼로리 표시만 실패, 운동은 가능 |
| 알림 | 앱 최초 실행 (`Notifications.requestPermissionsAsync()`) | 리마인더 예약만 실패, 운동은 가능 |
| 위치 (Foreground) | 앱 최초 실행 또는 카운트다운 진입 시 | 위치 기록만 스킵 |
| 캘린더 | 캘린더 버튼 클릭 시 | 커스텀 모달 → 설정 이동 |
