# 운동 조회 통합 실행 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 운동화면, 결과화면, 메인화면, 캘린더를 `React Context + AsyncStorage + HealthKit` 계약 위에서 순차적으로 완성하고, 기능별 브랜치 4개로 안전하게 분리한다.

**Architecture:** `feat/workout-screen`이 세션 생성과 저장의 원천이다. `feat/result-screen`, `feat/main-screen`, `feat/calendar`는 동일한 `sessionId`와 저장 포맷을 소비하는 구조로 구현한다. UI 스텁은 이미 존재하므로 이번 작업의 핵심은 공통 데이터 계약, 영속화, 조회 훅, 라우팅 연결이다.

**Tech Stack:** Expo Router, React Native, React Context, AsyncStorage, HealthKit, NativeWind, TypeScript

  part: BodyPart
  setCount: number
}

  lat: number
  lng: number
}

export interface StoredWorkoutSession {
  sessionId: string
  startedAt: string
  completedAt: string
  bodyParts: WorkoutBodyPartSet[]
  memo: string
  location: WorkoutLocation | null
}

## 사전 확인 사항

- `React Context`를 상태 관리 기준으로 사용한다.
- 백엔드는 사용하지 않는다. 운동 플로우는 `HealthKit + AsyncStorage + expo-*` 조합으로 처리한다.
- 실제 구현 전, 이 문서를 기준으로 공통 세션 계약이 충분히 명확한지 사용자 검토를 반드시 받는다.
