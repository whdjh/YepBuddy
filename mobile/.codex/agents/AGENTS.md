# 에이전트 작업 분배

공통 프로젝트 규칙은 [상위 AGENTS.md](../../AGENTS.md)를 따른다. 이 문서와 역할 파일은 메인 에이전트가 위임할 때 명시적으로 읽고 전달하는 작업 템플릿이다. Markdown 역할 파일 자체가 모델 설정이나 에이전트 등록을 수행하지는 않는다. 아래 프로젝트 경로는 `mobile/` 기준이며, Markdown 링크는 이 파일 위치 기준이다.

## 현재 모델에 맞는 운영 원칙

- 메인 에이전트가 작업 전체를 이해하고 요구사항 판단, 구현, 통합, 검증을 끝까지 맡는다. 상위 모델의 판단을 파일 수나 고정된 단계로 제한하지 않는다.
- 독립적인 하위 작업이 있고 병렬 수행이 시간이나 품질에 도움이 되면 서브에이전트를 사용한다. 필요한 결과를 받기 전에도 메인이 진행할 일이 있어야 한다.
- 파일명에 남아 있는 lead/senior/junior는 책임 범위를 고르는 이름이다. 능력이 다른 모델을 뜻하지 않는다. 기본적으로 현재 세션의 모델·추론 설정을 상속하며, 모델 이름이나 effort를 템플릿에 고정하지 않는다.
- 이미 근거와 권한이 있는 작업은 자율적으로 진행한다. 추가 정보가 반드시 필요한 부분만 메인 에이전트에 전달하고, 가능한 독립 작업은 계속한다.
- 검증은 변경의 영향과 위험에 맞춘다. 모든 작업에 계획 문서, 전체 테스트, 별도 리뷰어 두 명을 의무화하지 않는다.

## 역할 선택

| 파일 | 책임 | 위임하기 좋은 작업 |
| --- | --- | --- |
| [lead-dev.md](lead-dev.md) | 여러 경계를 다루는 구현 | 독립적으로 분리 가능한 기능, 상태·저장소·네이티브 경계 변경 |
| [senior-dev.md](senior-dev.md) | 범위가 정해진 구현·원인 분석 | 기능 일부, 버그 수정, 훅·컴포넌트 개선 |
| [junior-dev.md](junior-dev.md) | 명확한 반복 변경 | 타입·번역·정해진 패턴의 일괄 수정 |
| [spec-reviewer.md](spec-reviewer.md) | 요구사항·동작 검증 | 누락, 범위 초과, 호환성, 사용자 흐름 확인 |
| [quality-reviewer.md](quality-reviewer.md) | 결함·유지보수성 검토 | 실제 버그, 경계 위반, 회귀 위험, 불필요한 복잡성 확인 |

같은 역할을 여러 독립 범위에 사용할 수 있다. 구현 직후 스펙·품질 리뷰를 병렬로 실행할 수 있으며, 작은 작업은 메인이 두 관점을 직접 확인한다.

## 위임할 정보

역할 템플릿에 아래 정보를 채운다. 관련 없는 선택 항목은 생략하고 미치환 placeholder를 전달하지 않는다. 긴 소스 전체를 복제하기보다 파일 경로와 필요한 배경을 제공한다.

```text
목표: {{TASK_DESCRIPTION}}
완료 조건: {{ACCEPTANCE_CRITERIA}}
수정 허용 파일/영역: {{WRITE_SCOPE}}
참조 문서와 진입점: {{CONTEXT}}
검증할 동작/명령: {{VALIDATION}}
다른 작업과의 경계/선행 조건: {{DEPENDENCIES}}
```

리뷰에는 목표와 완료 조건 외에 `{{REVIEW_TARGET}}`을 전달한다. 커밋 범위, 기준 브랜치 대비 diff, 미커밋 변경 파일 중 실제 대상을 명시한다. 커밋이 있어야만 리뷰할 수 있는 것은 아니다.

## 병렬 작업과 통합

- 구현 담당자의 수정 파일은 겹치지 않게 배정한다. 여러 작업이 필요로 하는 공용 파일은 한 담당자가 맡는다.
- 담당 범위를 넓혀야 하면 먼저 메인에 이유와 파일을 알린다. 다른 에이전트나 사용자의 변경을 덮어쓰거나 되돌리지 않는다.
- 리뷰어는 기본적으로 읽기 전용이다. 수정까지 맡길 때는 구현 담당자와 겹치지 않는 파일 범위를 새로 배정한다.
- 메인은 서브에이전트 보고를 결론으로 그대로 복사하지 않는다. 근거 코드와 통합 diff를 확인하고, 통합 후 필요한 검증을 실행한다.

## 결과 보고

구현·분석 담당자는 다음 중 하나와 함께 결과를 짧게 보고한다.

- `DONE`: 담당 범위와 검증 완료.
- `DONE_WITH_CONCERNS`: 변경은 완료했으나 미실행 검증이나 남은 우려가 있음.
- `NEEDS_CONTEXT`: 결과를 결정하는 정보가 필요함. 필요한 정보와 진행한 독립 작업을 명시.
- `BLOCKED`: 도구·권한·외부 상태 때문에 더 진행할 수 없음. 시도한 방법과 필요한 조치를 명시.

보고에는 변경 파일, 해결한 동작, 실행한 검증과 결과, 남은 이슈만 담는다. 메인은 미해결 완료 조건이 있으면 작업을 이어가며, 검증하지 않은 상태를 성공으로 보고하지 않는다.

## 문서 유지

공통 규칙은 [상위 AGENTS.md](../../AGENTS.md), 역할별 관점은 각 템플릿에 둔다. 새 규칙을 추가하기 전에 기존 문서와 중복·충돌하는지 확인한다. 작업 중 알게 된 프로젝트 계약은 해당 레이어 README나 화면 기능서에 반영한다.

운영 원칙은 OpenAI 공식 [GPT-6 Astra 동작 안내](https://developers.openai.com/api/docs/guides/latest-model#gpt-6-astra-behavior)의 자율 실행, 지침 충돌 점검, 명확한 병렬 위임, 적정 검증 범위에 맞췄다. 지침 파일의 탐색 범위는 [AGENTS.md 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)를 참고한다.
