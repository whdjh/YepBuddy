# yepbuddy 디자인 원칙

레이아웃의 기본값은 `src/tokens/semantic.json`의 `layout`과 `tailwind.config.js`를 따른다. 아래 수치는 React Native의 논리 단위이며, 화면 기능서와 기존 컴포넌트의 구체적인 요구를 함께 확인한다. 토큰 적용 방식은 `.codex/design-tokens.md`를 참조한다.

## 1. 여백(Spacing) 시스템

여백은 시각적인 안정감을 주고 정보의 위계를 명확하게 하는 데 중요한 역할을 합니다.

| 용도 | 크기 | 설명 |
|------|------|------|
| 좌우 여백 | 20 (`px-yb-5`) | 화면 콘텐츠의 기본 좌우 패딩. |
| 섹션 간 여백 | 24 (`gap-yb-6`) | 독립적인 콘텐츠 그룹을 구분하는 기본 간격. |
| 카드 내부 여백 | 24 (`p-yb-6`) | 기본 카드 패딩. 해당 variant의 실제 구현도 확인. |
| 제목-콘텐츠 여백 | 16 (`gap-yb-4`) | 제목과 관련 내용을 하나의 그룹으로 보여주는 간격. |
| 버튼/탭/카드 간 여백 | 12 (`gap-yb-3`) | 반복 요소를 구분하는 기본 간격. |

## 2. 터치 영역(Touch Area)

모바일 환경에서는 손가락으로 조작하기 때문에 충분한 터치 영역 확보가 필수적입니다.

- **최소 터치 영역**: 44×44 논리 단위 — 버튼, 링크, 입력 필드 등 새 상호작용 요소의 기준. 작은 시각 요소는 padding이나 hitSlop 등으로 실제 터치 영역을 확보하고 인접 요소와 겹치지 않게 한다.
- **아이콘과 터치 영역 분리**: 눈에 보이는 아이콘이 24x24로 작더라도 실제 터치 영역(Touch Target)은 44x44로 설정하여 오터치 방지.

## 3. 네이티브 컴포넌트 및 그리드 시스템

OS의 기본 환경과 디바이스 특성을 존중하여 디자인합니다. (iOS 기준)

- **참고 프레임**: 375×812. 고정 화면 크기로 구현하지 않고 작은 화면, 큰 글자, Android에서도 내용과 조작 요소가 잘리지 않는지 확인한다.
- **OS 네이티브 영역 확보**:
  - **상태 바(Status Bar)**: 콘텐츠와 조작 요소에 safe area를 적용한다. `Main`은 상단 inset을 적용하므로 같은 여백을 중복 추가하지 않는다.
  - **홈 인디케이터(Home Indicator)**: 화면별 하단 inset과 네비게이션 높이를 고려한다. `Main`이 하단 여백까지 처리한다고 가정하지 않는다.
- **그리드 기본값**: 거터 16, 좌우 마진 20. 4컬럼은 디자인 참고이며, 모든 화면에 강제하지 않고 실제 콘텐츠와 기존 화면 구조에 맞춘다.
- **공식 리소스 활용**: Apple Design Resources 등 OS 공식 UI 키트 적극 활용.

## 4. 테마와 접근성

- light/dark 색상과 운동 화면의 추가 테마는 semantic 토큰으로 표현한다. 색상만으로 상태를 구분하지 않고 라벨이나 아이콘도 함께 제공한다.
- 글래스 UI는 공용 컴포넌트의 fallback을 유지해 지원되지 않는 기기와 투명도 감소 설정에서도 내용을 읽을 수 있게 한다.
- 아이콘 버튼에 접근성 라벨을 제공하고, 글자 크기 확대 시 줄바꿈과 터치 영역을 확인한다.
