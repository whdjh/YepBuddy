개요

캘린더 화면은 저장된 완료 운동 세션을 날짜 단위로 훑고, 운동이 있는 날짜에서 해당 결과 화면으로 이동하는 조회 중심 화면이다. 이 문서는 03_calendar.md의 내용을 현재 코드 기준으로 보강한 HTML 기능서다.

범위: /calendar → CalendarScreen → MonthGrid → DayCell → /workout/[sessionId]

월 목록 렌더링

useInfiniteMonths(anchorDate, count = 6)는 이름과 달리 실제 무한 스크롤이 아니라 현재 월부터 과거 방향으로 고정 개수의 월 목록을 만든다.

항목 구현 기준 사용자 의미
월 순서 anchorDate.getFullYear(), getMonth() + 1 현재 월이 맨 위에 오고 한 달씩 과거로 내려간다.
기본 개수 count = 6 현재 월 포함 최근 6개월만 표시한다.
월 경계 month === 0 → 12, year -= 1 1월 이전은 전년도 12월로 자연스럽게 넘어간다.
월 제목 t("sessions.monthHeader", { year, month }) 번역 리소스 기준의 월 라벨을 오른쪽 정렬로 표시한다.

운동 날짜 맵

각 MonthGrid는 자기 월의 시작일과 마지막 일을 YYYY-MM-DD 키로 만들고, getStoredWorkoutSessionsInRange로 완료 세션을 조회한다. 결과는 날짜 키를 기준으로 sessionId, 상위 운동 부위, 유산소 여부를 담는 맵으로 변환된다.

맵 생성 규칙
  • ●월 범위는 로컬 날짜 키 기준으로 YYYY-MM-01부터 월 마지막 날까지다.
  • ●세션의 startedAt을 로컬 날짜 키로 변환해 날짜 셀에 배치한다.
  • ●getUniqueWorkoutBodyParts(session.bodyParts)로 상위 운동 부위만 중복 제거한다.
  • ●cardioStartedAt이 있으면 hasCardio=true로 표시 후보에 포함한다.
  • ●같은 날짜의 세션이 이미 맵에 있으면 뒤 세션은 건너뛴다. 조회 결과가 최신순이므로 최신 대표 세션 하나가 남는다.
  • ●조회 실패 시 해당 월의 workoutDates는 빈 객체로 대체된다.
DayWorkout 예시
{
  "2026-04-03": {
    "sessionId": "2026-04-03T10:00:00.000Z",
    "bodyParts": ["chest", "back"],
    "hasCardio": true
  }
}

캘린더 화면은 HealthKit 월별 workout을 직접 읽지 않는다. 현재 표시는 앱에 저장된 완료 세션 인덱스와 세션 본문에 의존한다.

날짜 셀 상태

날짜 셀은 DayCell이 담당한다. 현재 구현은 원형 링이 아니라 날짜 숫자와 운동 부위 아이콘 배지 중심의 간결한 그리드다.

기본 셀

각 셀은 너비 14.285%, 최소 높이 68로 7열 그리드를 만든다. 월 1일 앞에는 getFirstDayOfWeek 결과만큼 빈 칸을 둔다.

오늘

오늘이면 날짜 숫자를 bg-yb-accent 원형 배경 안에 넣고, 텍스트는 text-yb-on-accent로 표시한다.

운동 있음

운동 날짜는 첫 번째 운동 부위 배지만 바로 보인다. 추가 부위나 유산소가 있으면 +N 숫자를 표시한다.

롱프레스 툴팁

표시할 배지가 2개 이상이면 롱프레스에서 모달 툴팁을 띄워 전체 운동 부위와 유산소 아이콘을 보여준다.

미래 또는 기록 없음

disabled = isFuture || !dayWorkout다. 미래 날짜와 운동 없는 날짜는 버튼 역할은 유지하지만 눌러도 이동하지 않는다.

접근성

접근성 라벨은 영어 문자열 Day N과 운동 가능 여부를 포함한다. 비활성 상태는 accessibilityState에 반영된다.

탭 동작

운동이 있는 날짜만 결과 화면으로 이동한다. CalendarScreen의 handleDayPress는 router.push(`/workout/${encodeURIComponent(sessionId)}`)를 호출한다.

탭 분기
graph TD A[날짜 셀 탭] --> B{disabled?} B -- "true" --> C[동작 없음] B -- "false" --> D{dayWorkout 있음?} D -- "no" --> C D -- "yes" --> E[dayWorkout.sessionId 전달] E --> F[encodeURIComponent] F --> G[/workout/sessionId push]
제약
  • ●하루 여러 세션을 선택하는 목록 UI는 없다.
  • ●동일 날짜에 여러 세션이 있으면 최신 대표 세션 하나로 이동한다.
  • ●결과 화면에서의 삭제, 메모 수정, 상세 표시 정책은 이 문서 범위 밖이다.

날짜 갱신 동작

useCalendarRefreshSignal은 화면의 현재 날짜 기준과 월별 데이터 재조회 트리거를 함께 관리한다. 앱 복귀와 자정 경계에서 anchorDate를 새로 만들고 refreshKey를 1 증가시킨다.

초기 진입

useState(() => new Date())로 현재 월, 오늘 강조, 미래 날짜 판정 기준을 만든다.

앱 복귀

AppState가 active가 되면 즉시 갱신한다.

자정

다음 자정까지 setTimeout을 예약하고 실행 후 다시 다음 자정을 예약한다.

효과: 앱을 오래 열어 두거나 백그라운드에서 돌아온 경우에도 오늘 강조, 미래 날짜 비활성, 월별 저장 데이터 조회가 새 기준으로 다시 계산된다.

OS 캘린더 등록 메모

OS 캘린더 일정 등록은 이 화면의 탭 동작이 아니라 운동 완료 흐름에서 수행된다. 운동을 완료하면 결과 화면으로 가기 전에 캘린더 등록 여부를 묻고, 사용자가 추가를 선택하면 registerWorkoutToCalendar를 호출한다.

권한과 캘린더 선택
  • ●캘린더 권한이 없으면 요청하고, 거부 시 설정 앱으로 이동하는 알림을 띄운다.
  • ●수정 가능한 YepBuddy 전용 캘린더를 먼저 찾는다.
  • ●없으면 YepBuddy 제목, yepbuddy 이름, 앱 강조색으로 새 캘린더 생성을 시도한다.
  • ●Android에서 생성이 실패하면 수정 가능한 기존 캘린더를 fallback으로 사용한다.
이벤트 내용
  • ●제목은 운동 부위 라벨과 세트 수를 조합하고, 유산소 시간이 있으면 함께 붙인다.
  • ●시작과 종료는 완료 세션의 startedAt, completedAt을 사용한다.
  • ●메모는 notes, 위치가 있으면 변환된 위치 라벨은 location에 저장한다.
  • ●캘린더 ID 확보나 이벤트 생성 실패 시 실패 알림을 표시하고 false를 반환한다.

스펙 ↔ 코드 갭

[md 표현 보정] 운동 날짜의 “링”과 “작은 점” 표시는 현재 코드와 다르다

03_calendar.md는 날짜 셀을 원형 링과 작은 점으로 설명하지만, 현재 DayCell.tsx는 운동 부위 아이콘 배지와 +N 카운트로 표시한다. 오늘 날짜만 원형 배경으로 강조된다.

[확인된 제약] “무한” 월 목록은 고정 6개월 렌더링이다

훅 이름은 useInfiniteMonths지만 기본 count=6으로 현재 월 포함 6개월만 반환한다. 스크롤 끝에서 과거 월을 추가 로드하는 트리거는 없다.

[확인된 제약] 같은 날짜의 여러 운동은 최신 대표 세션 하나만 노출된다

저장 계층은 날짜별 대표 세션 ID를 관리하고, 월 날짜 맵 생성도 같은 날짜가 이미 있으면 다음 세션을 건너뛴다. 캘린더 UI에는 하루 여러 세션 목록이나 선택 모달이 없다.

[범위 분리] OS 캘린더 등록은 캘린더 조회 화면의 책임이 아니다

등록 코드는 존재하지만 /calendar에서 호출되지 않는다. 실제 호출 지점은 운동 완료 흐름의 ActiveWorkoutContent.tsx이며, 이 화면은 저장된 완료 세션 조회와 결과 화면 이동만 담당한다.

[접근성 뉘앙스] 날짜 셀 accessibilityLabel은 번역 리소스를 쓰지 않는다

화면 제목과 요일은 번역 리소스를 사용하지만 날짜 셀 라벨은 Day ${day} 형식의 하드코딩 영어 문자열이다. 제품 언어 일관성 관점에서는 추후 개선 후보다.
