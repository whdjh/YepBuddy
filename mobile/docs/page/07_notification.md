# 알림 기능서

> 현재 구현 기준으로 정리한 문서.  
> 범위: `앱 실행 시 알림 초기화 → 운동 리마인더 동기화 → 운동 시작/종료 시 리마인더 갱신 → 프로틴 세일 알림 토글 ON/OFF → 프로틴 알림 탭 라우팅`

## 1. 문서 목적

이 문서는 YepBuddy의 알림 기능이 어떤 종류로 나뉘는지, 언제 예약/취소되는지, 어떤 사용자 액션과 연결되는지를 비즈니스 관점에서 이해할 수 있도록 정리한 기능서다.

기획 아이디어나 희망사항이 아니라, 현재 코드에 연결되어 있는 실제 동작을 기준으로 작성한다.

## 2. 기능 한눈에 보기

현재 앱 알림은 2가지 축으로 동작한다.

1. 운동 리마인더 알림
2. 프로틴 세일 알림

핵심 역할은 6가지다.

1. 앱 시작 시 알림 권한 요청 흐름을 시작한다.
2. 앱 시작 시 프로틴 세일 알림(활성화된 경우)과 운동 리마인더를 동기화한다.
3. 운동 시작 직전 기존 운동 리마인더를 취소한다.
4. 운동 종료 시점에 다음 운동 리마인더를 규칙(22:00)에 맞게 재예약한다.
5. 프로틴 화면 토글로 세일 알림 ON/OFF를 제어한다.
6. 프로틴 세일 알림을 탭하면 프로틴 탭으로 이동시킨다.

## 3. 사용자 흐름

```text
앱 실행
  └─ 루트 레이아웃 초기화
      ├─ OS 알림 권한 요청 시작
      ├─ 프로틴 세일 알림 핸들러 등록
      ├─ 저장된 프로틴 세일 알림 활성 상태 확인
      │   └─ 활성 상태면 향후 세일 알림 재예약
      └─ 운동 리마인더 동기화
          ├─ 권한 확인/요청
          ├─ 기존 운동 리마인더 취소
          ├─ 오늘 운동 여부 확인
          ├─ 이번 주 루틴 남은 횟수 기반 본문 계산
          └─ 다음 22:00(오늘 또는 내일)로 1건 예약

운동 시작 카드 탭
  └─ 카운트다운 화면 진입
      └─ 기존 운동 리마인더 취소

운동 종료
  └─ 로컬 세션/헬스킷/캘린더 저장 시도
      └─ 운동 리마인더 동기화 재실행
          └─ 다음 22:00 기준으로 1건 재예약

프로틴 탭 진입
  └─ 세일 알림 토글 확인
      ├─ 토글 ON
      │   ├─ iOS 권한 확인/요청
      │   ├─ 기존 프로틴 알림 전부 취소
      │   ├─ 주요 세일 일정들 예약
      │   └─ 활성 상태 저장
      └─ 토글 OFF
          ├─ 활성 상태 false 저장
          └─ 기존 프로틴 알림 전부 취소

프로틴 세일 알림 탭
  └─ 알림 payload kind 확인
      └─ kind가 프로틴 세일이면 /protein으로 이동
```

## 4. 화면 범위

| 화면 | 경로 | 역할 |
| --- | --- | --- |
| 앱 루트 레이아웃 | `src/app/_layout.tsx` | 알림 권한 요청 시작, 프로틴 핸들러 등록, 초기 동기화 실행 |
| 카운트다운 화면 | `/workout/countdown` | 운동 시작 직전 기존 운동 리마인더 취소 |
| 운동 중 화면 | `/workout/active` | 운동 종료 시 운동 리마인더 동기화 재실행 |
| 프로틴 목록 화면 | `/protein` | 세일 알림 토글 ON/OFF 제어 |

## 5. 기능 상세

### 5.1 앱 시작 시 초기화

루트 레이아웃 `useEffect`에서 알림 관련 초기 작업을 한 번 수행한다.

현재 동작:

- `Notifications.requestPermissionsAsync()`를 호출해 OS 권한 요청 플로우를 시작한다.
- 프로틴 세일 알림 응답 핸들러를 등록한다.
- 저장된 프로틴 세일 알림 활성 상태가 true면 일정 재동기화를 수행한다.
- 운동 리마인더 동기화를 즉시 한 번 수행한다.

의미:

- 앱을 다시 켤 때도 “알림 상태와 예약 상태”를 현재 정책 기준으로 복구한다.

### 5.2 운동 리마인더 정책

운동 리마인더는 `entities/workout-session/lib/reminder.ts`에서 관리한다.

현재 정책:

- 기준 시각은 매일 `22:00`이다.
- 동기화 시 기존 운동 리마인더 1건을 취소하고 새로 1건만 예약한다.
- 오늘 운동을 이미 완료했거나 현재 시각이 22:00 이후면 `내일 22:00`에 예약한다.
- 오늘 운동 미완료이고 현재 시각이 22:00 이전이면 `오늘 22:00`에 예약한다.

### 5.3 운동 리마인더 본문 생성

운동 리마인더 본문은 주간 루틴 상태를 기준으로 동적으로 결정한다.

동작 규칙:

- 루틴 기능이 ON이고 설정이 있으면:
  - 이번 주 세션 진행률을 계산한다.
  - `remainingSessions`를 사용해 본문을 만든다.
  - 예시 형태: `이번 주 세션에 남은 운동: 3회.`
- 루틴 기능이 OFF이거나 설정이 없거나 계산 중 오류가 나면:
  - 기본 문구 `workout.reminder.body`를 사용한다.

### 5.4 운동 시작/종료와 리마인더 연계

#### 5.4.1 카운트다운 진입 시 취소

- 카운트다운 화면 진입 시 `cancelScheduledWorkoutReminder()`를 호출한다.
- 의미: 사용자가 지금 운동을 시작했으므로 기존 “운동하러 가자” 알림은 불필요하다고 보고 즉시 정리한다.

#### 5.4.2 운동 종료 시 재동기화

- 운동 중 화면에서 종료 저장 흐름이 끝난 뒤 `syncWorkoutReminderAtNight()`를 호출한다.
- 의미: 최신 운동 완료 상태를 반영해 다음 리마인더 시각을 다시 확정한다.

### 5.5 프로틴 세일 알림

프로틴 세일 알림은 `shared/lib/protein-sale-notification` 모듈에서 관리한다.

현재 특성:

- 플랫폼: iOS 중심으로 동작한다. (`scheduleProteinSaleNotifications`는 Android에서 false 반환)
- 토글 ON 시:
  - 권한 확인/요청
  - 기존 프로틴 세일 알림 전체 취소
  - 고정 세일 일정 + 블랙프라이데이 기반 일정 예약
  - 예약 ID 목록 저장
  - 활성 상태 저장
- 토글 OFF 시:
  - 활성 상태 false 저장
  - 예약 전체 취소

알림 시각 규칙:

- 고정 세일: 세일 시작일 전날 19:00
- 블랙프라이데이: 해당 연도 11월 마지막 금요일 전날 19:00
- 현재 연도 + 다음 연도 일정 중 “지금 이후” 일정만 예약

### 5.6 프로틴 알림 탭 라우팅

프로틴 세일 알림 응답 핸들러는 payload의 `kind`를 확인해서 라우팅한다.

동작 규칙:

- `kind === myproteinSale`이면 `/protein`으로 이동한다.
- 동일 notification identifier는 중복 처리하지 않도록 캐시한다.
- 처리 후 `clearLastNotificationResponseAsync()`로 마지막 응답을 정리한다.

## 6. 저장소 키

### 6.1 운동 리마인더

- `yb:workout:reminder`
  - 값: 현재 예약된 운동 리마인더 notification identifier 1건

### 6.2 프로틴 세일 알림

- `yb:protein-sale-notification:enabled`
  - 값: `"true"` / `"false"`
- `yb:protein-sale-notification:ids`
  - 값: 예약된 프로틴 세일 notification identifier 배열(JSON)

## 7. 현재 제약과 참고사항

1. 운동 리마인더는 “22:00 고정 시각 정책”으로 동작한다.
2. 프로틴 세일 알림 예약은 Android에서 no-op이다.
3. 운동 리마인더와 프로틴 세일 알림은 서로 다른 저장 키/취소 경로를 사용하므로 서로를 직접 취소하지 않는다.
