# 메인 화면 기능서

> 현재 구현 기준으로 정리한 문서.  
> 범위: `메인 탭 진입 → 오늘 요약 확인 → 카드 구성 편집 → 최근 세션 확인 → 운동 시작/차단 → 주간 루틴 사용 여부 선택 → 운동 중 루틴 선택 → 주간 루틴 예정 확인 → 주간 세션 조회`

## 1. 문서 목적

이 문서는 YepBuddy의 메인 화면이 어떤 역할을 하는지, 사용자가 첫 진입 시 어떤 정보를 보게 되는지, 어떤 카드가 어디로 연결되는지를 비즈니스 관점에서 이해할 수 있도록 정리한 기능서다.

기획 아이디어나 희망사항이 아니라, 현재 코드에 연결되어 있는 실제 동작을 기준으로 작성한다.

## 2. 기능 한눈에 보기

메인 화면은 사용자가 앱에 들어왔을 때 가장 먼저 보는 요약 허브 화면이다.

핵심 역할은 8가지다.

1. 오늘 운동 요약을 한눈에 보여준다.
2. 오늘 운동 완료 여부에 따라 운동 시작 가능 상태를 제어한다.
3. 가장 최근 세션 1건으로 빠르게 이동하게 한다.
4. 이번 주 실제 세션과, 루틴 ON 상태일 때의 예정 루틴을 한 목록에서 보여준다.
5. 주간 루틴 사용 여부를 처음 선택하거나 다시 켜고 끄게 한다.
6. 루틴 ON 상태에서는 운동 중 화면에서 오늘 할 루틴 세션을 선택하고 부위를 빠르게 채운다.
7. 운동 상세 화면과 운동 실행 화면으로 이어지는 진입점을 제공한다.
8. 사용자가 메인 요약 카드의 표시 여부와 순서를 조정하게 한다.

## 3. 사용자 흐름

```text
메인 탭 진입
  └─ 메인 화면 로드 시작
      ├─ 오늘 요약 조회
      │   ├─ 로컬 완료 세션 조회
      │   └─ 오늘 HealthKit workout 조회
      ├─ 최근 세션 조회
      ├─ 이번 주 세션 조회
      ├─ 오늘 완료 여부 조회
      ├─ 주간 루틴 설정 조회
      │   └─ 저장된 루틴이 있으면 저장값 정규화
      ├─ 주간 루틴 사용 여부 상태 조회
      │   ├─ 저장된 상태가 있으면 해당 상태 사용
      │   ├─ 저장된 상태가 없고 루틴 설정이 있으면 ON으로 간주
      │   └─ 저장된 상태와 루틴 설정이 모두 없으면 미선택 상태로 시작
      ├─ 주간 루틴 안내 상태 조회
      └─ 저장된 요약 카드 구성 조회
          └─ 화면 렌더링
              ├─ 오늘 날짜 표시
              ├─ 저장된 카드 순서대로 요약 카드 표시
              │   ├─ 오늘의 운동 카드 표시
              │   ├─ 오늘 운동시간 / 세트수 표시
              │   ├─ 최근 세션 카드 표시
              │   ├─ 운동 시작 카드 표시
              │   └─ 이번 주 세션 리스트 표시
              │       ├─ 루틴 OFF/미선택 상태 → 실제 운동 행만 표시
              │       ├─ completed 매칭 루틴 슬롯 → 실제 운동 행 표시
              │       ├─ 미완료 루틴 슬롯 → 예정 행 표시
              │       └─ 완료 슬롯에 사용되지 않은 실제 세션 → 실제 운동 행 추가 표시
              ├─ 최초 루틴 사용 여부 안내 필요 여부 판단
              │   ├─ 알림 권한 최초 요청 완료 + 루틴 미선택 → 루틴 설정 안내 모달 표시
              │   ├─ 예 → 주간 루틴 설정 시트 열림
              │   └─ 아니오 → 루틴 OFF 저장
              ├─ 주간 루틴 안내 필요 여부 판단
              │   └─ 루틴 ON + 루틴 사이클 종료 → 새 사이클 시작 모달 표시
              ├─ 카드 편집 버튼 표시
              ├─ 루틴 ON/OFF 버튼 표시
              ├─ 최근 세션 카드 탭 → 결과 화면 이동
              ├─ 운동 시작 카드 탭 → 카운트다운 화면 이동
              │   └─ 카운트다운 종료 → 운동 중 화면 이동
              │       ├─ 루틴 ON이면 루틴 세션 칩 표시 (이번 주 진행률 기준)
              │       │   ├─ 완료 슬롯 → 비활성 칩
              │       │   ├─ 미완료 슬롯 → 선택 가능 칩 (다음 슬롯 자동 선택)
              │       │   └─ 칩 선택 → 해당 부위 자동 선택 + 첫 번째 부위 세부 항목 펼침
              │       └─ 부위 및 세부 항목 수동 선택 가능
              ├─ 오늘의 운동 카드 탭 → 캘린더 이동
              ├─ 주간 세션 화살표 탭 → 결과 화면 이동
              ├─ 루틴 OFF 버튼 탭 → 루틴 설정 안내 모달 표시
              ├─ 루틴 ON 버튼 탭 → 루틴 OFF 저장 및 예정 행 제거
              ├─ 주간 루틴 설정 시트 저장 → 루틴 ON 저장 및 이번 주 예정 행 재계산
              ├─ 예정 루틴에 맞는 운동 완료 → 예정 행이 실제 운동 행으로 대체
              └─ 카드 롱프레스 → 카드 편집 모드 진입
```

## 4. 화면 범위

| 화면 | 경로 | 역할 |
| --- | --- | --- |
| 메인 화면 | `/(tabs)` | 오늘 운동 요약, 최근 세션, 운동 시작, 주간 세션 목록을 보여주는 허브 화면 |

현재 구성 기준:

- 화면 본문은 `SummaryScreen`이 담당한다.
- 오늘 요약, 최근 세션, 주간 세션, 오늘 완료 여부를 각각 별도 조회 훅으로 읽는다.
- 주간 루틴 설정, 루틴 사용 여부, 루틴 사이클, 안내 모달 상태는 `useWeeklyRoutinePlan`으로 읽는다.
- 요약 카드 구성은 `useSummaryCardLayout`으로 읽고, 로컬 저장소에 저장한다.
- 메인 화면은 “조회와 이동”이 중심이며, 세션 메모 수정이나 세션 삭제는 여기서 하지 않는다.
- 다만 메인 화면에 표시할 요약 카드의 추가, 제거, 순서 변경은 지원한다.

## 5. 화면별 기능

### 5.1 메인 화면 진입

사용자는 하단 탭 또는 앱 기본 진입 지점에서 메인 화면으로 들어온다.

현재 동작 기준:

- 진입 시 오늘 날짜를 상단에 표시한다.
- 메인 화면은 여러 저장원에서 데이터를 동시에 읽는다.
- 일부 보조 데이터가 없어도 화면 전체는 열릴 수 있다.

조회 대상:

- 오늘 요약
- 최근 세션
- 이번 주 세션
- 오늘 운동 완료 여부
- 주간 루틴 설정
- 주간 루틴 사용 여부 상태
- 주간 루틴 안내 모달 상태
- 저장된 요약 카드 구성

카드 구성 기본값:

- 오늘의 운동
- 운동시간
- 세트수
- 최근 세션
- 운동 시작
- 이번 주 세션

### 5.2 오늘 날짜 헤더

화면 상단에는 현재 날짜 문자열이 표시된다.

동작 규칙:

- 기기 현재 시각 기준 날짜를 사용한다.
- 날짜 형식은 `MM.DD 요일` 형태다.
- 요일 표시는 앱 번역 리소스를 사용한다.

현재 구현 기준의 의미:

- 사용자는 오늘 기준의 요약 화면이라는 점을 즉시 인지할 수 있다.
- 날짜는 운동 세션 시작 시각이 아니라 “지금 시점” 기준이다.

추가 조작:

- 상단의 루틴 버튼은 현재 상태에 따라 `루틴 ON` 또는 `루틴 OFF`로 표시된다.
- `루틴 OFF` 버튼을 누르면 루틴 설정 안내 모달이 열린다.
- `루틴 ON` 버튼을 누르면 저장된 루틴 설정은 유지한 채 루틴 기능만 꺼진다.
- 상단의 `요약 편집` 버튼을 누르면 숨긴 요약 카드를 다시 추가할 수 있는 모달이 열린다.
- 카드 편집 모드에 들어간 상태에서는 `완료` 버튼이 함께 표시된다.

### 5.3 오늘의 운동 카드

오늘의 운동 카드는 오늘 운동 부위와 오늘 세트 수를 큰 카드 형태로 요약한다.

표시 항목:

- 오늘 운동 부위 문자열
- 오늘 총 세트 수
- 대표 운동 부위 아이콘
- 캘린더 이동용 화살표

계산 방식:

- 운동 부위는 오늘 저장된 로컬 세션의 `bodyParts`를 합쳐 문자열로 만든다.
- 세부 부위가 있는 항목은 `가슴 상부`처럼 상위 부위와 세부 부위를 함께 표시한다.
- 운동 부위가 없으면 `미지정`으로 표시한다.
- 대표 운동 부위 아이콘은 오늘 저장된 로컬 세션의 첫 번째 `bodyParts` 항목 기준으로 표시한다.
- 총 세트 수는 로컬 세션의 `bodyParts`별 `setCount` 합계다.

탭 동작:

- 카드를 누르면 현재는 `/calendar`로 이동한다.

현재 제약:

- 오늘 여러 세션을 합산하지 않고, 오늘 날짜에 매핑된 대표 세션 1건 기준으로 표시된다.
- 목표 세트 수나 원형 게이지는 현재 카드 UI에 표시되지 않는다.

### 5.4 오늘 운동시간 / 세트수 카드

오늘의 핵심 지표 2개를 숫자 카드로 보여준다.

표시 항목:

- 운동시간
- 세트수

계산 방식:

- 운동시간은 오늘 날짜의 HealthKit workout 목록 `duration` 합계를 분 단위로 반올림해 계산한다.
- 세트수는 오늘 대표 로컬 세션의 `bodyParts`별 `setCount` 합계다.

로딩 중 처리:

- 오늘 요약을 아직 읽는 중이면 `--`로 표시한다.

현재 구현 기준의 의미:

- 운동시간은 HealthKit 기반 지표다.
- 세트수는 로컬 저장 기반 지표다.
- 한 카드 안에서도 데이터 원천이 서로 다를 수 있다.

### 5.5 최근 세션 카드

최근 세션 카드는 가장 최근에 저장된 완료 세션 1건을 요약한다.

표시 항목:

- 운동 부위 요약
- 칼로리 영역
- 날짜 문자열

계산 방식:

- 운동 부위는 가장 최근 저장 세션의 `bodyParts`를 문자열로 합쳐 표시한다.
- 세부 부위가 있는 항목은 `가슴 상부`처럼 표시한다.
- 부위가 없으면 `미지정`으로 표시한다.
- 날짜는 최근 세션의 `startedAt` 기준으로 `MM.DD 요일` 형식으로 표시한다.

탭 동작:

- 최근 세션이 있으면 `/workout/[sessionId]` 결과 화면으로 이동한다.
- 최근 세션이 없으면 이동하지 않는다.

현재 제약:

- 칼로리 값은 아직 실제 데이터에 연결되어 있지 않아 `--`로 표시된다.
- 최근 세션이 없을 때도 카드 자체는 보이지만 실질 이동은 불가능하다.

### 5.6 운동 시작 카드

운동 시작 카드는 새 운동 세션을 시작하는 진입점이다.

표시 항목:

- 운동 라벨
- 근력 강화 운동 텍스트
- 시작 유도 문구

탭 동작:

- 오늘 운동을 아직 완료하지 않았으면 `/workout/countdown`으로 이동한다.
- 오늘 운동을 이미 완료한 상태면 탭이 비활성화된다.

비활성 규칙:

- 오늘 날짜 키에 완료 세션 ID가 존재하면 비활성화된다.
- 비활성 상태에서는 opacity가 낮아진다.

현재 구현 기준의 의미:

- “하루 1세션 기준” 규칙이 메인 화면 행동 제어에도 반영된다.

### 5.6.1 운동 중 화면 — 루틴 세션 칩

운동 중 화면(`/workout/active`) 상단에는 이번 주 루틴 세션을 선택하는 칩 행이 표시된다.

표시 조건:

- 루틴 데이터 로딩이 끝난 이후 표시된다.
- 루틴 사용 상태가 ON일 때만 표시된다.
- 루틴 OFF 또는 미선택 상태에서는 루틴 세션 칩 영역 자체를 표시하지 않는다.
- 루틴 ON 상태에서 저장된 루틴이 없으면 기본 루틴(가슴/등/어깨팔/하체) 칩을 표시한다.

칩 상태:

| 슬롯 상태 | 칩 표시 |
|---|---|
| `completed` | 비활성 (opacity 낮음, 탭 불가) |
| `partial` | 선택 가능 |
| `pending` | 선택 가능 |

칩 라벨:

- 칩에는 루틴 슬롯의 상위 운동 부위만 `/`로 연결해 표시한다.
- 세부 부위 선택값은 칩 라벨에는 표시하지 않지만, 칩 선택 시 운동 부위 상태에는 함께 반영된다.

자동 선택:

- 화면 진입 시 이번 주에서 아직 완료하지 않은 첫 번째 슬롯이 자동 선택된다.
- 자동 선택 시 해당 슬롯의 부위가 운동 부위 상태에 즉시 반영된다.
- 자동 선택은 첫 진입에만 1회 적용된다.

칩 선택 시 동작:

- 해당 슬롯의 운동 부위가 아래 부위 선택 행에 자동 반영된다.
- 슬롯의 첫 번째 부위에 세부 항목이 있으면 세부 항목 행이 자동으로 펼쳐진다.
- 사용자는 이후 부위와 세부 항목을 자유롭게 수정할 수 있다.

이번 주 루틴을 모두 완료한 경우:

- 모든 칩이 비활성 상태로 표시된다.
- “이번 주 루틴을 모두 완료했어요” 문구가 표시된다.

### 5.7 이번 주 세션 리스트

이번 주 세션 리스트는 현재 주간 범위 안의 실제 저장 세션과, 루틴 ON 상태일 때의 주간 루틴 예정 세션을 함께 보여준다.

사용자 관점의 핵심 흐름:

- 루틴 OFF 또는 미선택 상태에서는 실제 저장 세션만 표시한다.
- 루틴 ON 상태에서 아직 운동하지 않은 루틴 슬롯은 `예정` 행으로 표시된다.
- 사용자가 해당 루틴과 완전히 일치하는 운동을 완료하면, 그 슬롯은 실제 운동 행으로 대체된다.
- 루틴과 일부만 겹치는 운동은 루틴 완료로 보지 않고, 예정 행은 유지한 채 실제 운동 행을 별도로 표시한다.
- 루틴과 매칭되지 않은 실제 운동 세션은 목록 뒤에 실제 운동 행으로 추가된다.

주간 범위 기준:

- 로컬 시간 기준 월요일 00:00부터 일요일 23:59:59까지

표시 항목:

- 운동 부위
- 행 상태
  - 실제 운동 행: 운동 날짜, 운동 시간(분), 세트 수, 칼로리 영역, 결과 화면 이동용 화살표
  - 예정 행: `예정` 라벨과 루틴 부위 조합

계산 방식:

- 이번 주 저장 세션은 날짜 범위로 조회한다.
- 주간 루틴 진행률은 루틴 ON 상태에서만 계산한다.
- 루틴 ON 상태에서 저장된 루틴 설정이 있으면 그 설정을 사용하고, 없으면 기본 루틴을 사용한다.
- 루틴 OFF 또는 미선택 상태에서는 루틴 슬롯을 비워 예정 행을 만들지 않는다.
- 루틴 슬롯의 모든 부위와 세부 부위가 실제 세션에 포함되면 `completed` 슬롯으로 판단한다.
- 루틴 슬롯의 일부 상위 부위만 실제 세션과 겹치면 `partial` 슬롯으로 판단한다.
- `completed` 슬롯에 매칭 세션이 있으면 실제 운동 행으로 만든다.
- `partial` 또는 `pending` 슬롯은 예정 행으로 만든다.
- 이미 루틴 슬롯에 표시된 실제 세션은 중복 표시하지 않는다.
- 완료 슬롯에 사용되지 않은 실제 세션은 목록 뒤에 추가한다.
- 실제 운동 행의 운동 부위는 각 세션의 `bodyParts`를 문자열로 합쳐 만든다.
- 세부 부위가 있는 항목은 `가슴 상부`처럼 표시한다.
- 실제 운동 행의 운동 시간은 `completedAt - startedAt` 차이를 분 단위로 반올림한 값이다.
- 실제 운동 행의 세트 수는 각 세션의 `setCount` 합계다.
- 예정 행의 운동 부위는 루틴에 저장된 부위 조합을 문자열로 만든다.

이동 동작:

- 헤더의 더보기/셰브론을 누르면 `/sessions`로 이동한다.
- 실제 운동 행의 화살표를 누르면 해당 세션의 결과 화면으로 이동한다.
- 예정 행은 아직 결과 화면이 없으므로 이동 화살표를 표시하지 않는다.

빈 상태 처리:

- 표시할 실제 세션과 예정 루틴 행이 모두 없으면 카드 안에 “데이터가 없습니다.” 문구를 표시한다.
- 루틴 ON 상태에서는 저장된 루틴이 없더라도 기본 루틴 예정 행이 표시된다.
- 루틴 OFF 또는 미선택 상태이고 이번 주 실제 세션도 없으면 빈 상태 문구가 표시된다.

현재 제약:

- 리스트의 칼로리 값은 아직 실제 데이터에 연결되어 있지 않아 `--`로 표시된다.
- 실제 운동 행은 행 전체가 아니라 우측 화살표를 눌러야 결과 화면으로 이동한다.
- 예정 행은 특정 요일이나 시간에 배정되지 않고, 이번 주에 해야 할 루틴 슬롯으로만 표시된다.
- `partial` 슬롯은 리스트에서 예정 행으로 남고, 일부 겹친 실제 운동은 별도 실제 운동 행으로 추가된다.
- 주간 루틴 완료 개수는 `completed` 슬롯만 기준으로 계산한다.

### 5.8 주간 루틴 ON/OFF, 설정 및 사이클 안내 모달

주간 루틴 기능은 사용자가 명시적으로 켜거나 끌 수 있다. 루틴 설정은 루틴 ON 상태에서 이번 주 세션 리스트에 표시되는 예정 행의 기준이 된다.

진입 방식:

- 루틴 사용 여부가 아직 미선택이고, 알림 권한 최초 요청 흐름이 끝난 사용자는 메인 진입 시 루틴 설정 안내 모달을 본다.
- 사용자가 상단의 `루틴 OFF` 버튼을 누르면 루틴 설정 안내 모달이 열린다.
- 사용자가 상단의 `루틴 ON` 버튼을 누르면 루틴 설정 데이터는 유지한 채 루틴 기능만 꺼진다.
- 루틴 ON 상태인 사용자의 루틴 사이클이 끝나면 새 사이클 시작 안내 모달을 본다.

루틴 ON/OFF 버튼 동작:

- 메인 화면 헤더의 `요약 편집` 버튼 옆에 표시된다.
- 루틴 ON 상태에서는 `루틴 ON`으로 표시된다.
- 루틴 OFF 또는 미선택 상태에서는 `루틴 OFF`로 표시된다.
- 루틴 ON 상태에서 누르면 `disabled` 상태를 저장하고, 이번 주 예정 루틴 행과 운동 중 루틴 추천을 즉시 숨긴다.
- 루틴 OFF 상태에서 누르면 안내 모달을 띄운다.
- 루틴 데이터 로딩 중에는 버튼이 비활성화되고 opacity가 낮아진다.

루틴 설정 안내 모달 동작:

- `예`를 누르면 안내 모달을 닫고 주간 루틴 설정 시트를 연다.
- `아니오`를 누르면 루틴 OFF 상태를 저장한다.
- 설정 시트를 열었더라도 저장 전까지는 루틴 ON으로 전환하지 않는다.
- 설정 시트에서 저장을 완료하면 루틴 설정 저장 후 루틴 ON 상태를 저장한다.
- 안내는 React Native 기본 `Alert`로 표시되며, native `Modal` 기반 설정 시트와 동시에 열리지 않는다.

사이클 종료 모달 동작:

- 설정된 훈련 주차와 디로드 주차를 모두 지나면 표시된다.
- 새 사이클 시작 버튼을 누르면 현재 주차를 새 사이클 시작 주차로 저장한다.
- 나중에 버튼 또는 배경을 누르면 해당 주차에는 다시 표시하지 않는다.
- 루틴 OFF 또는 미선택 상태에서는 표시하지 않는다.
- 루틴 설정이 없는 사용자에게도 표시하지 않는다.

주간 루틴 설정 시트 동작:

- 훈련 주차 수를 설정한다.
- 디로드 주차 수를 설정한다.
- 루틴 분할 수를 1~7 사이에서 설정한다.
- 루틴 분할 수가 바뀌면 루틴 세션 개수도 같은 수로 늘거나 줄어든다.
- 각 루틴 세션마다 운동 부위와 세부 부위를 선택할 수 있다.
- 저장하면 루틴 설정을 AsyncStorage에 저장하고, 루틴 사용 상태를 ON으로 저장한 뒤 이번 주 세션 리스트의 예정 행을 다시 계산한다.
- 시트는 native `Modal`로 렌더링하고, Modal 내부 터치가 동작하도록 `GestureHandlerRootView`와 gesture-handler `Pressable`을 사용한다.
- 제목, 주차 설정, 루틴 세션 카드는 스크롤 영역에 있고, 저장 버튼은 스크롤 영역 밖 하단 footer에 고정된다.

저장 데이터:

- 루틴 설정 저장 키는 `yb:workout:weekly-routine`이다.
- 루틴 사용 여부 저장 키는 `yb:workout:weekly-routine-feature-status`다.
- 안내 모달 상태 저장 키는 `yb:workout:weekly-routine-prompt`다.

상태 값:

- `unasked`: 아직 루틴 사용 여부를 선택하지 않음
- `enabled`: 루틴 ON
- `disabled`: 루틴 OFF

기존 사용자 마이그레이션:

- 루틴 사용 여부 저장값이 있으면 그 값을 우선 사용한다.
- 루틴 사용 여부 저장값이 없고 기존 루틴 설정이 있으면 `enabled`로 간주한다.
- 루틴 사용 여부 저장값과 루틴 설정이 모두 없으면 `unasked`로 시작한다.

현재 제약:

- 예정 루틴은 “이번 주에 해야 할 슬롯”으로만 표시되며 요일 배정은 없다.
- 디로드 주차는 루틴 사이클 상태 계산에 사용되지만, 세션 강도나 세트 수를 자동으로 바꾸지는 않는다.

### 5.9 요약 카드 구성 편집

사용자는 메인 화면에 표시되는 요약 카드의 표시 여부와 순서를 조정할 수 있다.

진입 방식:

- 각 요약 카드를 길게 누르면 편집 모드로 들어간다.
- 상단의 `요약 편집` 버튼을 누르면 현재 숨겨진 카드를 추가하는 모달이 열린다.

편집 모드 동작:

- 편집 모드에서는 카드 우측 상단에 삭제 버튼이 표시된다.
- 삭제 버튼을 누르면 해당 카드가 메인 화면에서 숨김 처리된다.
- 카드를 위아래로 드래그하면 현재 카드 목록 안에서 한 칸씩 순서가 바뀐다.
- 드래그 이동은 세로 이동량이 일정 기준을 넘을 때 적용된다.
- 상단의 `완료` 버튼을 누르면 편집 모드를 종료한다.

카드 추가 모달 동작:

- 현재 숨겨진 카드만 추가 후보로 표시된다.
- 후보 카드를 누르면 해당 카드가 현재 카드 목록의 끝에 추가되고 모달은 닫힌다.
- 추가 가능한 카드가 없으면 “추가할 수 있는 카드가 없습니다.” 문구를 표시한다.
- 모달 배경 또는 닫기 버튼을 누르면 모달을 닫는다.

레이아웃 규칙:

- `오늘의 운동`, `이번 주 세션` 카드는 전체 너비 카드다.
- `운동시간`, `세트수`, `최근 세션`, `운동 시작` 카드는 반 너비 카드다.
- 반 너비 카드는 두 개씩 한 행에 배치된다.
- 반 너비 카드가 홀수로 남으면 빈 반쪽 영역을 함께 배치해 카드 폭을 유지한다.

저장 규칙:

- 카드 순서와 숨김 상태는 카드 ID 배열 형태로 AsyncStorage에 저장된다.
- 저장 키는 `yb:summary:cards`다.
- 앱을 다시 열면 저장된 카드 구성을 불러와 동일한 순서로 렌더링한다.
- 저장된 값이 없으면 기본 카드 구성을 사용한다.
- 저장된 값에 유효하지 않은 카드 ID나 중복 카드 ID가 있으면 정리해서 사용한다.
- 저장된 카드 ID 배열이 비어 있으면 모든 카드를 숨긴 상태로 유지한다.
- 저장값이 배열이지만 유효한 카드 ID가 하나도 없으면 모든 카드를 숨긴 상태로 렌더링한다.

현재 제약:

- 모든 카드를 숨길 수 있다.
- 모든 카드가 숨겨진 경우 본문에는 “표시 중인 카드가 없습니다.” 문구가 표시된다.
- 카드 편집은 메인 화면 구성만 바꾸며, 운동 세션 데이터 자체를 삭제하거나 수정하지 않는다.

## 6. 데이터 구성 방식

메인 화면은 여러 저장원을 조합해 만든다.

### 6.1 로컬 저장 데이터

로컬 저장 세션에서 사용하는 정보:

- 오늘 날짜 대표 세션 ID
- 최근 세션 1건
- 이번 주 저장 세션 목록
- 운동 부위/세부 부위 목록
- `bodyParts`별 세트 수
- 시작 시각 / 종료 시각
- 요약 카드 ID 목록

역할:

- 오늘 부위/세트수 계산의 기준이 된다.
- 최근 세션 카드와 주간 세션 리스트의 기본 데이터가 된다.
- 오늘 운동 완료 여부를 판단한다.
- 메인 화면 카드의 표시 여부와 순서를 복원한다.

### 6.2 HealthKit 데이터

HealthKit에서 사용하는 정보:

- 오늘 날짜의 workout 목록
- 각 workout의 duration
- 각 workout의 kcal

역할:

- 오늘 운동시간 계산의 원천이 된다.
- 오늘 총 칼로리 같은 후속 지표 확장 기반이 된다.

현재 구현 기준 제약:

- 메인 화면에서 HealthKit kcal은 아직 카드 UI에 연결되지 않았다.
- 최근 세션 카드와 주간 세션 리스트 칼로리도 아직 실제 값으로 표시되지 않는다.

### 6.3 주간 루틴 데이터

주간 루틴 데이터는 루틴 ON/OFF 상태, 이번 주 세션 리스트의 예정 행, 운동 중 루틴 추천, 사이클 종료 안내 모달을 만드는 기준이다.

루틴 사용 여부 상태:

- `unasked`: 아직 루틴 사용 여부를 선택하지 않음
- `enabled`: 루틴 ON
- `disabled`: 루틴 OFF

루틴 설정 정보:

- 루틴 세션 목록
- 사이클 시작 주차 날짜 키
- 훈련 주차 수
- 디로드 주차 수
- 루틴 분할 수(1~7)

안내 모달 상태:

- 사이클 종료 안내를 dismiss한 주차 날짜 키

구성 방식:

- 저장된 루틴 사용 여부 상태가 있으면 그 값을 우선 사용한다.
- 저장된 루틴 사용 여부 상태가 없고 루틴 설정이 있으면 기존 사용자를 위해 ON으로 간주한다.
- 저장된 루틴 사용 여부 상태와 루틴 설정이 모두 없으면 미선택 상태로 시작한다.
- 루틴 ON 상태에서 저장된 루틴 설정이 있으면 누락 필드를 기본값으로 보강해 사용한다.
- 루틴 ON 상태에서 저장된 루틴 설정이 없으면 기본 루틴을 사용해 이번 주 예정 행을 만든다.
- 루틴 OFF 또는 미선택 상태에서는 루틴 슬롯을 비워 예정 행과 운동 중 루틴 추천을 만들지 않는다.
- 기본 루틴은 가슴, 등, 어깨/팔, 하체 순서다.
- 루틴 분할 수를 늘리면 루틴 세션 수도 함께 늘어난다.
- 루틴 분할 수는 1~7 범위로 정규화된다.
- 추가되는 루틴 세션은 미리 정의된 부위 프리셋을 사용한다.
- 기존 저장값에 `regularWeeks`만 있으면 훈련 주차 수와 분할 수의 초기값으로 함께 사용한다.
- 사이클 상태는 사이클 시작 주차와 현재 주차의 차이로 계산한다.
- 현재 주차가 설정된 훈련 주차 이후이고 디로드 기간 안이면 디로드 주차로 판단한다.
- 설정된 훈련 주차와 디로드 주차를 모두 지나면 사이클 완료 상태로 판단한다.

### 6.4 요약 카드 레이아웃 데이터

요약 카드 레이아웃은 운동 세션 데이터와 별도로 저장된다.

카드 정의:

- `todayWorkout`: 오늘의 운동, 전체 너비
- `workoutTime`: 운동시간, 반 너비
- `sets`: 세트수, 반 너비
- `latestSession`: 최근 세션, 반 너비
- `startWorkout`: 운동 시작, 반 너비
- `weeklySessions`: 이번 주 세션, 전체 너비

구성 방식:

- 화면은 저장된 카드 ID 배열을 기준으로 렌더링 순서를 정한다.
- 전체 너비 카드는 단독 행으로 배치한다.
- 반 너비 카드는 연속된 카드 2개를 한 행으로 묶는다.
- 카드 추가는 배열 끝에 ID를 추가하는 방식이다.
- 카드 삭제는 배열에서 해당 ID를 제거하는 방식이다.
- 카드 이동은 배열 안에서 해당 ID를 앞 또는 뒤로 한 칸 이동하는 방식이다.

## 7. 상태와 예외 케이스

### 7.1 로딩 중 상태

오늘 요약이 아직 끝나지 않으면:

- 운동시간 카드에 `--`
- 세트수 카드에 `--`

현재 구현 기준:

- 별도의 전체 화면 로딩은 없다.
- 카드 단위로 숫자만 placeholder처럼 보인다.

### 7.2 데이터 없음 상태

가능한 빈 상태는 다음과 같다.

- 오늘 저장 세션이 없음
- 최근 세션이 없음
- 이번 주 실제 세션이 없음
- HealthKit workout이 없음
- 표시 중인 요약 카드가 없음
- 추가 가능한 숨김 카드가 없음
- 주간 루틴 설정이 없음
- 주간 루틴 사용 여부가 OFF 또는 미선택

현재 처리 방식:

- 오늘 부위 없음 → `미지정`
- 오늘 세트 수 없음 → `0`
- 최근 세션 없음 → 카드 표시 유지, 이동 없음
- 이번 주 실제 세션 없음 + 루틴 ON → 기본 루틴 또는 저장 루틴 기반 예정 행 표시
- 이번 주 실제 세션 없음 + 루틴 OFF/미선택 → “데이터가 없습니다.” 표시
- 오늘 HealthKit workout 없음 → 운동시간 `0분`
- 표시 중인 요약 카드 없음 → “표시 중인 카드가 없습니다.”
- 추가 가능한 숨김 카드 없음 → “추가할 수 있는 카드가 없습니다.”
- 주간 루틴 설정 없음 + 루틴 ON → 기본 루틴으로 예정 행 계산
- 주간 루틴 설정 없음 + 루틴 미선택 → 알림 권한 최초 요청 완료 후 루틴 설정 안내 모달 표시 대상
- 주간 루틴 OFF → 저장된 루틴 설정이 있어도 예정 행과 운동 중 추천 미표시

### 7.3 카드 구성 저장 예외

요약 카드 구성은 로컬 저장소 값을 신뢰하되, 화면 렌더링 전에 정리한다.

현재 처리 방식:

- 저장된 값이 없으면 기본 카드 배열을 사용한다.
- 저장된 값이 JSON 파싱에 실패하면 기본 카드 배열을 사용한다.
- 저장된 값이 배열이 아니면 기본 카드 배열을 사용한다.
- 배열 안의 알 수 없는 카드 ID는 제거한다.
- 중복된 카드 ID는 첫 번째 값만 남긴다.
- 정리 후 남은 카드가 없으면 빈 카드 목록으로 렌더링한다.
- 따라서 빈 배열 또는 유효한 ID가 없는 배열이 저장되어 있으면 “표시 중인 카드가 없습니다.” 상태가 된다.

### 7.4 날짜 변경 반영

메인 화면의 요약 조회 훅들은 날짜 경계에 반응한다.

현재 동작 기준:

- 최초 진입 시 1회 조회
- 앱이 다시 active 되면 재조회
- 자정이 지나면 다시 조회

사용자 관점의 의미:

- 앱을 오래 켜 두고 있어도 날짜가 바뀌면 오늘 요약이 새 기준으로 다시 계산된다.
- 루틴 ON 상태라면 주간 루틴 진행률도 새 주차 기준으로 다시 계산된다.
- 루틴 ON 상태에서 새 주차가 루틴 사이클 종료 조건에 해당하면 사이클 갱신 안내 모달 대상이 된다.

## 8. 현재 제약 및 비범위

현재 메인 화면에서 지원하지 않는 것:

- 최근 세션 카드의 실제 칼로리 표시
- 이번 주 세션 리스트의 실제 칼로리 표시
- 세션 데이터 삭제 / 편집 / 공유
- 목표 세트 수 사용자 설정 및 오늘 카드 게이지 표시
- 여러 세션 합산 기반의 오늘 대표 부위 표시
- 예정 루틴의 요일/시간 배정
- 예정 루틴 행에서 바로 운동 시작
- 디로드 주차에 따른 세트 수나 강도 자동 조정
- 카드 구성 초기화 버튼
- 카드별 크기 사용자 설정

이번 문서 범위 밖:

- 운동 실행 상세 플로우
- 결과 화면 메모 수정
- 캘린더 월별 조회
- 히트맵 형태 대체 UI

## 9. 요약

메인 화면은 “오늘 운동 요약 + 가장 최근 세션 + 이번 주 실제/예정 세션 + 운동 시작 + 주간 루틴 ON/OFF 및 설정 + 요약 카드 구성 편집”을 하나의 허브에서 제공하는 화면이다.

현재 구현 기준으로 보면:

- 오늘 세트 수와 운동 부위는 로컬 저장 세션 중심
- 오늘 운동시간은 HealthKit 중심
- 최근 세션은 저장 세션 기반 이동 허브
- 이번 주 세션은 실제 저장 세션과, 루틴 ON 상태의 주간 루틴 예정 슬롯을 합쳐 표시
- 루틴 OFF 또는 미선택 상태에서는 예정 루틴과 운동 중 루틴 추천을 표시하지 않음
- 예정 루틴과 완전 매칭되는 운동이 완료되면 해당 슬롯이 실제 운동 행으로 표시
- 부분 매칭 운동은 루틴 슬롯을 완료하지 않고 별도 실제 운동 행으로 표시
- 루틴 완료 개수는 완전 매칭 슬롯만 기준으로 계산
- 운동 시작 버튼은 오늘 완료 여부에 따라 제어
- 주간 루틴 사용 여부, 루틴 설정, 안내 모달 상태는 AsyncStorage에 저장
- 요약 카드의 표시 여부와 순서는 AsyncStorage에 저장

즉 메인 화면은 단순 랜딩 화면이 아니라, 오늘 운동 상태를 확인하고 다음 행동으로 바로 이어지게 하는 요약 대시보드 역할을 한다.
