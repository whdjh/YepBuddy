# 결과 화면 기능서

> 현재 구현 기준으로 정리한 문서.  
> 범위: `운동 기록 상세 조회 → 메모/세트 수 수정 → HealthKit/위치 정보 확인 → 운동 기록 및 연결 일정 삭제`

## 1. 문서 목적

이 문서는 YepBuddy의 운동 결과 화면이 어떤 역할을 하는지, 사용자가 어떤 정보를 확인할 수 있는지, 메모와 세트 수를 어떤 범위에서 수정할 수 있는지를 비즈니스 관점에서 이해할 수 있도록 정리한 기능서다.

기획 아이디어나 희망사항이 아니라, 현재 결과 화면에 연결되어 있는 실제 동작을 기준으로 작성한다.

## 2. 기능 한눈에 보기

결과 화면은 이미 저장된 운동 세션 1건을 다시 열어 보는 상세 조회 화면이다.

핵심 역할은 6가지다.

1. 완료된 운동의 기본 정보를 다시 보여준다.
2. 로컬 저장 데이터와 HealthKit 데이터를 한 화면에서 함께 보여준다.
3. 운동 후 메모를 결과 화면에서 수정할 수 있게 한다.
4. 저장된 운동 부위 구성은 유지하면서 각 항목의 세트 수만 명시적으로 수정할 수 있게 한다.
5. 심박수 차트와 위치 정보를 조건부로 노출한다.
6. 잘못 저장된 운동 기록과 연결된 OS 캘린더 일정을 함께 삭제할 수 있게 한다.

## 3. 사용자 흐름

```text
운동 기록 진입
  └─ /workout/[id]
      └─ 결과 화면 로드 시작
          ├─ 로컬 저장 세션 조회
          ├─ HealthKit 상세 조회 시도
          └─ 로딩 완료
              ├─ 헤더 정보 표시
              ├─ 메모 조회 및 수정
              ├─ 운동 세부사항 표시
              │   └─ 세트 수 수정 바텀시트에서 취소 또는 저장
              ├─ 심박수 차트 조건부 표시
              ├─ 위치 지도 조건부 표시
              ├─ 헤더 우측 삭제 아이콘 표시
              └─ 삭제 확인 후 연결된 OS 일정과 로컬 기록 삭제
                  └─ 메인 탭 화면으로 이동
```

참고:

- 현재 운동 종료 직후에는 이 화면으로 자동 이동한다.
- 결과 화면은 세션 ID가 있을 때만 열리는 상세 조회 라우트다.
- 라우트 파라미터 `id`는 URL 디코딩 후 `sessionId`로 사용된다.

## 4. 화면 범위

| 화면 | 경로 | 역할 |
| --- | --- | --- |
| 결과 화면 | `/workout/[id]` | 완료된 운동 세션 1건의 상세 조회, 메모/세트 수 수정 및 삭제 |

현재 구성 기준:

- 화면 본문은 `ResultScreen`이 담당한다.
- 데이터는 `sessionId` 하나로 로컬 세션과 HealthKit 상세를 함께 읽는다.
- 메모 수정, 세트 수 수정, 연결된 캘린더 일정 동기화와 운동 기록 삭제가 연결되어 있다.
- 공유, 수정 이력, 재운동 시작 같은 후속 액션은 현재 연결되어 있지 않다.

## 5. 화면별 기능

### 5.1 결과 화면 진입

사용자는 세션 ID가 포함된 결과 라우트로 진입한다.

현재 동작 기준:

- 캘린더 화면에서 운동한 날짜 링을 누르면 해당 세션 결과 화면으로 이동한다.
- 운동 중 화면에서 운동 종료 버튼을 누르면 저장 완료 후 해당 세션 결과 화면으로 이동한다.
- 세션 목록 화면에서 세션 카드를 누르면 해당 세션 결과 화면으로 이동한다.
- 메인 화면의 분할 루틴 리스트에서 해당 세션 화살표를 누르면 결과 화면으로 이동한다.
- `/workout/[id]`에서 URL 파라미터를 읽는다.
- `id`가 문자열이면 `decodeURIComponent` 후 결과 화면에 전달한다.
- 세션 ID가 비어 있으면 유효한 데이터를 불러오지 못한 상태로 처리된다.

즉 현재 구현 기준으로 결과 화면에 올 수 있는 대표 진입 경로는 다음 4가지다.

1. 캘린더 화면에서 해당 월/일의 운동 날짜 선택
2. 운동 중 화면에서 운동 종료 버튼 선택
3. 세션 목록 화면에서 세션 카드 선택
4. 메인 화면의 분할 루틴 리스트에서 해당 세션 선택

### 5.2 초기 로딩

결과 화면은 진입 직후 상세 데이터를 읽는다.

데이터 조회 방식:

- 로컬 저장소에서 완료 세션을 조회한다.
- 저장 세션의 workout UUID가 있을 때만 해당 HealthKit 상세 데이터를 조회한다.
- HealthKit 조회가 끝나거나 실패하면 로컬 세션과 조회 가능한 보조 정보로 화면을 그린다.

로딩 중 사용자에게 보이는 기능:

- 중앙 로딩 인디케이터 표시

로딩 후 분기:

- 로컬 세션이 없으면 “데이터가 없습니다.” 문구를 보여준다.
- 로컬 세션이 있으면 상세 콘텐츠를 보여준다.

현재 구현 기준의 의미:

- 결과 화면의 기준 데이터는 로컬 저장 세션이다.
- HealthKit 데이터는 보조 정보이며, 없어도 화면 자체는 열릴 수 있다.

### 5.3 상단 헤더

헤더는 결과 화면의 핵심 요약 영역이다.

표시 항목:

- 운동 날짜
- 우측 상단 연필 및 휴지통 아이콘
- 운동 종류 라벨
- 디로드 상태 배지
- 운동 부위 요약
- 시작 시각
- 종료 시각
- 위치 라벨 여부

동작 규칙:

- 화면 상단 제목에는 시작 시각 기준 날짜를 표시한다.
- 운동 종류는 현재 항상 “근력 강화 운동”으로 표시된다.
- 로컬 세션의 `isDeload`가 `true`이면 운동 종류 라벨 옆에 작은 `디로드` 배지를 표시한다.
- 운동 부위가 1개 이상 있으면 부위명을 쉼표로 이어서 표시한다.
- 세부 부위가 있는 항목은 `가슴 상부`처럼 상위 부위와 세부 부위를 함께 표시한다.
- 운동 부위가 없으면 “미지정”으로 표시한다.
- 위치 데이터가 있는 경우 헤더 시간 문자열 끝에 역지오코딩으로 얻은 주소 라벨을 붙인다.
- 한국 주소 라벨은 국가 코드가 `KR`이면 `시/도 + 시/군/구 + 상세 위치명` 순으로 표시해 읍·면·동 이름을 중복해 붙이지 않는다. 그 외 국가는 기존 역지오코딩 필드 순서를 유지한다.
- 역지오코딩에 실패하거나 위치 데이터가 없으면 위치 라벨은 생략한다.
- 우측 상단 연필 아이콘을 누르면 현재 메모 저장을 시작하고 세트 수 수정 바텀시트를 연다.
- 우측 상단 휴지통 아이콘을 누르면 운동 기록 삭제 확인 흐름을 시작한다.
- 수정과 삭제 액션은 아이콘으로만 표시하고 접근성 라벨로 의미를 제공한다.

현재 제약:

- 운동 타입은 세션 데이터와 무관하게 단일 라벨로 고정되어 있다.

### 5.4 메모 입력 및 수정

결과 화면에서는 완료된 운동의 메모를 바로 수정할 수 있다.

동작 규칙:

- 로컬 세션에 저장된 메모를 기본값으로 보여준다.
- 사용자는 텍스트를 자유롭게 수정할 수 있다.
- 저장 버튼은 없다.
- 입력이 바뀐 뒤 300ms 디바운스로 로컬 저장소에 다시 저장한다.

저장 범위:

- 수정 대상은 메모 필드만 해당한다.
- 완료 세션 전체를 다시 저장하지만, 바뀌는 값은 메모다.
- HealthKit 데이터는 수정하지 않는다.

현재 구현 기준의 의미:

- 운동 후 회고를 나중에 덧붙이는 용도로 사용할 수 있다.
- 앱을 나갔다 다시 들어와도 마지막으로 저장된 메모가 유지된다.

### 5.5 운동 세부사항 카드

결과 화면에는 2x2 형태의 요약 카드 영역이 있다.

표시 항목:

- 운동 시간
- 활동 칼로리
- 세트수
- 평균 심박수

계산 방식:

- 운동 시간은 HealthKit `duration`을 우선 사용하고, 없으면 로컬 세션의 저장된 duration으로 폴백한다.
- 활동 칼로리는 HealthKit `activeKcal`을 우선 사용하고, 없으면 로컬 세션의 저장된 `activeKcal`로 폴백한다.
- 세트수는 로컬 세션의 각 운동 항목 `setCount` 합계로 계산한다.
- 평균 심박수는 선택된 workout의 유효 심박 샘플 평균을 반올림해 계산한다. 샘플이 없으면 저장 세션의 `averageHeartRate`, HealthKit `averageHeartRate` 순서로 유효한 양수값을 사용한다.

빈 상태 처리:

- 운동 시간이 없으면 `-`로 표시한다.
- 활동 칼로리가 없으면 `-`로 표시한다.
- 평균 심박수가 없으면 `-`로 표시한다.
- 세트수는 로컬 세션이 있으면 항상 숫자로 표시되며, 선택 부위가 없으면 `0`이 된다.

현재 제약:

- 총 칼로리 값은 HealthKit 상세에서 읽더라도 결과 화면 카드에는 노출하지 않는다.
- 칼로리 값은 정수 기준으로 보인다.

### 5.6 세트 수 수정

사용자가 상단 휴지통 아이콘 옆의 연필 아이콘을 누르면 현재 메모 저장을 시작하고 세트 수 수정 바텀시트가 열린다. 결과 화면의 기본 조회 UI는 그대로 유지되며, 편집 컨트롤은 리퀴드 글래스 바텀시트 안에서만 표시된다.

초기값과 표시 규칙:

- 바텀시트를 열 때 현재 완료 세션에 저장된 운동 항목을 그대로 불러온다.
- 각 항목의 상위 운동 부위와 세부 부위는 읽기 전용 라벨로 표시한다.
- 각 항목의 현재 `setCount`를 Stepper 기본값으로 표시한다.
- Stepper는 운동 중 화면에서 사용하는 기존 공용 컴포넌트의 glass variant를 재사용한다.
- 세트 수는 정수이며 최소값은 `1`이다.

편집 범위:

- 변경할 수 있는 값은 기존 항목별 `setCount`뿐이다.
- 운동 부위 또는 세부 부위를 추가, 삭제, 변경하거나 순서를 바꿀 수 없다.
- 세트 편집은 HealthKit 데이터, 운동 시작/종료 시각, 위치, 디로드 상태를 변경하지 않는다. 메모는 세트 값과 별도로 연필 아이콘을 누른 시점의 입력값을 저장한다.

저장 흐름:

1. 연필 아이콘을 누르면 현재 메모 저장을 시작하고 리퀴드 글래스 바텀시트를 연다.
2. Stepper 조작은 바텀시트의 임시 값만 바꾼다.
3. 사용자가 `취소`하거나 저장하지 않고 바텀시트를 닫으면 세트 수는 변경하지 않는다.
4. 사용자가 `저장`을 누르면 메모 저장 완료를 기다린 뒤 기존 운동 항목 구성을 유지한 채 각 항목의 세트 수만 완료 세션에 저장한다.
5. 저장 후 결과 화면의 총 세트 수를 새 값으로 갱신한다.
6. 세션에 연결된 캘린더 이벤트가 있으면 같은 이벤트의 제목과 메모를 현재 세션 값으로 갱신한다.

캘린더 동기화 규칙:

- 완료 세션의 `calendarEventId`가 있으면 해당 ID의 동일 OS 이벤트를 수정한다.
- 과거 세션처럼 `calendarEventId`가 `null`이면 YepBuddy 캘린더에서 기존 제목, 시작 시각, 종료 시각이 모두 일치하는 후보를 찾는다.
- 후보가 정확히 1건일 때만 그 ID를 세션에 연결하고 제목과 메모를 수정한다.
- 후보가 없거나 2건 이상이면 임의의 일정을 수정하거나 연결하지 않는다.
- 캘린더 자동 저장 선호값은 신규 일정 생성만 제어한다. 이미 연결된 이벤트는 현재 선호값과 무관하게 수정 대상이다.
- 캘린더 이벤트의 시간과 위치는 세트 수 수정으로 덮어쓰지 않는다.

### 5.7 심박수 차트

심박수 차트는 현재 세션에 대응하는 HealthKit workout의 유효 샘플이 2개 이상일 때만 보이는 선택 영역이다. 아래 규칙을 코드에 반영했으며, 자동·실기기 검증 상태는 문서 하단에 별도로 기록한다.

표시 조건:

- iOS에서 선택된 workout에 연관되고 시작~종료 구간에 포함된 유효 심박 샘플이 2개 이상일 때만 제목과 차트를 노출한다.
- 샘플 0~1개, 권한 없음, 조회 실패, workout 선택 불가 상태에서도 로컬 결과·수정·삭제는 정상 동작한다.
- Android에서는 HealthKit 조회와 심박수 그래프를 실행하지 않는다.

표시 요소:

- 최고 심박수
- 평균 심박수
- 최저 심박수
- 실제 측정 간격을 보존하는 선·영역 차트
- 시작 시각
- 종료 시각
- 선택한 측정 시각과 BPM, 선택 원과 세로선

동작 규칙:

- 저장된 HealthKit workout UUID가 있으면 해당 workout만 선택하며, 찾지 못해도 다른 workout으로 대체하지 않는다.
- UUID가 없는 기록은 HealthKit 초기화·조회 없이 상세를 비운다. 로컬 시작·종료 시각으로 다른 운동을 찾아 연결하지 않는다.
- 네이티브에서 선택된 workout에 연관되고 운동 구간 안에 포함된 샘플을 시작 시각순으로 조회한다. 시각은 밀리초 포함 ISO 문자열로 반환한다.
- entity API는 양수 유한 BPM인 샘플만 남기고 소수 BPM과 네이티브가 반환한 UUID·시각을 유지한다. 같은 시각의 서로 다른 샘플도 유지한다.
- X값은 `(샘플 시작 시각 - workout 시작 시각) / (workout 종료 시각 - workout 시작 시각)`이며, X축은 항상 0~1이다. 측정 공백과 긴 운동도 실제 시간 비율로 표시한다.
- 차트 통계와 결과 평균 심박수는 같은 유효 심박 샘플을 우선 사용한다. 샘플이 없을 때만 저장 평균·HealthKit 평균을 보조 정보로 사용한다.
- 최고·평균·최저 라벨은 항상 표시한다. 평균 가이드는 최저·최고와 충분히 떨어진 경우에만 표시해 겹침을 피한다.
- 차트 영역을 누르면 화면상 가장 가까운 측정점을 선택하고 차트 위 고정 영역에 `HH:mm:ss` 시각과 BPM을 표시한다. 같은 시각의 다른 BPM도 구분하며 손을 떼어도 선택값을 유지한다. 선택 전 안내 문구는 표시하지 않는다.
- VoiceOver·TalkBack의 이전·다음 조절 동작으로 측정점을 탐색할 수 있다.
- 양 끝 라벨은 샘플의 첫·마지막 시각이 아니라 선택된 workout의 시작·종료 시각이며 ko/en 문구, BPM 단위와 접근성 요약을 제공한다.
- 프로틴 가격과 심박수는 `shared/ui/MetricChart`의 동일한 accent 토큰 색상, 높이 160, 채움·가이드·통계 스타일을 사용한다. 공용 컴포넌트가 유효 point 처리, 계산·렌더링, 점 선택·접근성 탐색을 소유한다.
- 공용 계약은 `{ x, y }[]`, X/Y formatter, 양 끝 라벨, 선택적 X domain과 접근성 제목이다. 도메인 adapter는 데이터·날짜·단위의 변환과 표시 문구만 전달한다.

현재 구현 기준의 의미:

- 단일 BPM과 같은 시각의 샘플도 안전하게 처리한다. 원본 샘플은 별도 저장하지 않는다.
- 프로틴 가격은 순서 기반 X축과 날짜 라벨을 유지하며, 차트의 스타일·통계·점 선택 동작은 심박수와 같다. 두 차트 모두 유효 point가 0~1개이면 숨긴다.

### 5.8 위치 지도

위치 지도는 운동 시작 위치가 저장된 경우에만 보이는 선택 영역이다.

표시 조건:

- 로컬 세션에 `location` 값이 있을 때만 노출된다.

표시 요소:

- 고정 지도
- 마커 1개
- 하단 위치 라벨

동작 규칙:

- 저장된 위도와 경도를 중심으로 지도를 연다.
- 지도는 스크롤, 줌, 회전, 기울이기 조작이 비활성화되어 있다.
- 마커는 저장된 좌표 1개만 표시한다.
- 이 좌표는 자동 학습되는 운동 장소와 도착 알림의 기준 위치로 사용한다.
- 장소 알림 동기화 시 기존 완료 기록도 같은 좌표 기준으로 자동 반영한다.

현재 제약:

- 지도 하단의 위치명은 헤더와 같은 역지오코딩 주소 포맷을 사용하고, 실패 시 좌표 문자열로 폴백한다.
- 위치 이동 경로나 다중 위치 기록은 지원하지 않는다.

### 5.9 운동 기록 삭제

결과 화면 상단 헤더 오른쪽에는 저장된 운동 기록을 삭제하는 휴지통 아이콘이 있다. 화면 하단에는 별도의 삭제 버튼을 두지 않는다.

표시 조건:

- 로컬 세션이 정상적으로 조회된 경우에만 표시된다.
- 로딩 중이거나 로컬 세션이 없으면 표시하지 않는다.

사용자 흐름:

1. 사용자가 상단 헤더 오른쪽의 휴지통 아이콘을 누른다.
2. React Native 기본 `Alert` 확인 팝업을 표시한다.
3. Alert는 “이 운동 기록을 삭제하시겠습니까?” 문구와 안내 메시지를 보여준다.
4. 사용자가 취소하거나 Alert를 닫으면 삭제하지 않는다.
5. 사용자가 삭제를 확인하면 연결된 OS 캘린더 일정 삭제를 먼저 시도한다.
6. OS 일정 삭제가 완료됐거나 이미 존재하지 않으면 앱 운동 기록 삭제를 계속한다.
7. OS 일정에 연결할 수 없거나 권한/기타 오류로 삭제하지 못하면, 사용자가 `앱 기록만 삭제`를 명시적으로 선택한 경우에만 앱 운동 기록을 삭제한다.

삭제 시 처리:

- `calendarEventId`가 있는 경우 해당 ID의 OS 캘린더 일정을 먼저 삭제한다.
- `calendarEventId`가 `null`인 과거 세션은 기존 제목, 시작 시각, 종료 시각이 모두 일치하는 후보가 YepBuddy 캘린더에 정확히 1건 있을 때만 연결한 뒤 삭제한다.
- OS 일정이 이미 삭제되어 조회되지 않는 상태는 캘린더 삭제가 끝난 것으로 간주한다.
- 완료 세션 본문을 삭제한다.
- 해당 세션의 날짜 인덱스를 삭제한다.
- 저장된 날짜 목록 인덱스에서도 해당 날짜를 제거한다.
- 남은 완료 세션의 결과 위치로 운동 장소 목록을 다시 계산하고 장소 geofence를 재동기화한다.
- 삭제 성공 후 메인 탭 화면으로 이동한다.

삭제하지 않는 정보:

- HealthKit에 저장된 운동 샘플

현재 구현 기준의 의미:

- 실수로 저장된 운동 기록을 앱 내부 기록에서 제거할 수 있다.
- 날짜 인덱스도 함께 제거되므로, 같은 날짜에 다시 운동을 시작할 수 있다.
- 연결된 캘린더 일정은 앱 기록보다 먼저 삭제해 기본 삭제 경로에서 두 기록을 함께 제거한다.
- 자동 저장 선호값을 나중에 꺼도 이미 연결된 이벤트는 삭제 대상이다.

## 6. 데이터 구성 방식

결과 화면은 로컬 저장 세션과 HealthKit 데이터를 조합해 표시하고, OS 캘린더 이벤트 ID를 로컬 세션에 연결해 수정·삭제를 동기화한다.

### 6.1 로컬 저장 데이터

로컬 저장 세션에서 사용하는 정보:

- 세션 ID
- 시작 시각
- 종료 시각
- 운동 부위/세부 부위 목록
- 운동 항목별 세트 수
- 메모
- 운동 시작 위치
- 운동 종료 후 보강 저장된 평균 심박수
- HealthKit workout UUID
- 연결된 OS 캘린더 이벤트 ID 또는 `null`

역할:

- 결과 화면의 기본 뼈대 역할을 한다.
- 메모와 세트 수 수정의 저장 대상이 된다.
- 부위, 세트수, 위치 노출 여부를 결정한다.
- HealthKit 종료 결과에서 평균 심박수나 workout UUID가 반환되면 완료 세션에 병합 저장된다.
- UUID는 주변 공백을 제거하고 소문자로 통일한다. 실패한 종료 응답의 UUID는 저장하지 않으며, 비어 있는 후속 응답으로 기존 UUID를 지우지 않는다. 형식이 손상됐어도 비어 있지 않은 저장 ID는 다른 운동을 선택하는 fallback을 허용하지 않는다.

### 6.2 OS 캘린더 연결 데이터

완료 세션은 캘린더 자동 등록 성공 시 `createEventAsync`가 반환한 이벤트 ID를 `calendarEventId`로 저장한다.

역할:

- 세트 수 수정 후 동일 이벤트의 제목을 갱신한다.
- 운동 기록 삭제 전 동일 이벤트를 먼저 삭제한다.
- 신규 일정 생성 이후 자동 저장 선호값이 바뀌어도 이미 연결된 이벤트의 수정/삭제 관계를 유지한다.

하위 호환 규칙:

- 기존 저장 세션처럼 필드가 없거나 값이 잘못된 경우 `calendarEventId`는 `null`로 정규화한다.
- `null`인 세션은 YepBuddy 캘린더에서 기존 제목, 시작 시각, 종료 시각이 모두 일치하는 이벤트가 정확히 1건일 때만 해당 ID를 저장한다.
- 일치 후보가 없거나 여러 건이면 연결하지 않는다.

### 6.3 HealthKit 데이터

HealthKit 상세에서 사용하는 정보:

- 운동 시간
- 활동 칼로리
- 총 칼로리
- 평균 심박수
- 심박 샘플 목록
- 선택된 workout UUID와 시작·종료 시각

역할:

- 통계 카드와 심박 차트의 데이터 원천이다.
- 결과 화면에서 로컬 데이터만으로 채울 수 없는 생체 정보 영역을 보강한다.
- 평균 심박수는 유효 심박 샘플 평균, 저장 세션에 보강된 값, HealthKit 상세 값 순서로 사용된다.

현재 제약:

- HealthKit 조회는 iOS 환경과 연동 가능 상태를 전제로 한다.
- 저장 UUID가 있으면 해당 workout만 읽는다. UUID가 없는 기록은 HealthKit 상세를 조회하지 않는다.
- 네이티브 상세는 선택된 workout UUID로만 조회하며, 해당 workout 연관 조건과 시작~종료 조건을 함께 적용해 심박 샘플을 읽는다. 같은 시간대라는 이유만으로 다른 workout의 샘플을 합치지 않는다.
- 일치하는 workout이 없거나 권한·네이티브 모듈·조회에 문제가 있으면 HealthKit 상세를 비운다. 로컬 결과는 유지한다.
- 원본 심박 샘플은 화면 조회 시에만 사용하며 로컬·서버로 별도 복제하지 않는다.

## 7. 권한 및 예외 케이스

### 7.1 세션 ID가 없거나 잘못된 경우

- 결과 화면은 유효한 상세 데이터를 만들지 못한다.
- 최종적으로 로컬 세션이 없으면 빈 상태 문구를 보여준다.

### 7.2 로컬 세션이 없는 경우

- 화면의 기준 데이터가 없으므로 상세 콘텐츠를 보여주지 않는다.
- “데이터가 없습니다.” 상태만 보여준다.

### 7.3 HealthKit 사용 불가 또는 조회 실패

- 로컬 세션이 있으면 결과 화면은 계속 열린다.
- 운동 시간, 칼로리, 평균 심박수는 `-`로 표시될 수 있다.
- 유효 심박 샘플이 2개 미만이면 심박수 제목과 차트는 보이지 않는다.

### 7.4 위치 정보가 없는 경우

- 헤더의 위치 라벨이 보이지 않는다.
- 지도 섹션도 노출되지 않는다.

### 7.5 메모 저장 중 세션이 사라진 경우

- 메모 업데이트 함수는 `null`을 반환하고 종료한다.
- 현재 화면에서 별도 에러 메시지를 띄우지는 않는다.

### 7.6 세트 수 저장 중 세션이 사라진 경우

- 세트 수를 저장하지 않는다.
- 사라진 세션을 새 데이터로 다시 만들지 않는다.

### 7.7 캘린더 일정 수정 실패

- 후보가 없거나 여러 건인 과거 일정은 임의로 수정하지 않는다.
- 권한이 없거나 OS 일정 수정이 실패하면 다른 캘린더 이벤트를 대신 수정하지 않는다.

### 7.8 운동 기록 삭제 실패

- 삭제 중 오류가 발생하면 결과 화면에 남아 있다.
- “삭제 실패” 안내 팝업을 표시한다.
- 삭제 아이콘은 다시 누를 수 있는 상태로 돌아간다.

### 7.9 캘린더 일정 삭제 예외

- OS 일정이 이미 삭제되어 존재하지 않으면 앱 기록 삭제를 계속한다.
- `calendarEventId`가 없고 과거 일정의 유일 후보도 찾지 못한 경우 연결되지 않은 상태로 처리한다.
- 연결되지 않았거나 권한/기타 오류로 OS 일정을 삭제할 수 없으면 앱 기록을 자동으로 삭제하지 않는다.
- 이 경우 사용자가 `앱 기록만 삭제`를 명시적으로 선택하면 OS 일정 상태와 무관하게 앱 기록 삭제를 계속한다.

## 8. 저장 데이터

결과 화면이 조회하거나 수정하는 데이터는 아래 기준으로 관리된다.

| 구분 | 저장 내용 | 목적 |
| --- | --- | --- |
| 완료 세션 | 시작/종료 시각, 부위/세부 부위, 세트 수, 디로드 여부, 메모, 위치, `calendarEventId` | 결과 화면 기본 조회와 캘린더 일정 연결 |
| HealthKit 보강 필드 | 평균 심박수, HealthKit workout UUID | 운동 종료 후 확정 지표 보관 |
| 완료 세션 인덱스 | 저장된 전체 세션 ID 목록 | 세션 목록 조회와 인덱스 복구 |
| 날짜 인덱스 | 특정 날짜의 대표 세션 ID | 날짜 기반 진입 연결 |
| HealthKit 운동 상세 | 운동 시간, 칼로리, 평균 심박수, 심박 샘플 | 결과 화면 통계/차트 보강 |

메모 수정 시:

- 완료 세션 본문이 다시 저장된다.
- 날짜 인덱스는 기존 sessionId를 그대로 유지한다.

세트 수 수정 시:

- 기존 운동 부위/세부 부위 구조를 유지하고 항목별 `setCount`만 바꿔 완료 세션 본문을 다시 저장한다.
- HealthKit, 시작/종료 시각, 메모, 위치는 변경하지 않는다.
- 연결된 OS 캘린더 이벤트가 있으면 동일 이벤트의 제목과 메모를 갱신한다.

운동 기록 삭제 시:

- 연결된 OS 캘린더 이벤트를 먼저 삭제한다.
- 완료 세션 본문이 삭제된다.
- 날짜 인덱스가 삭제된다.
- 저장된 날짜 목록 인덱스에서 해당 날짜가 제거된다.
- HealthKit 운동 상세는 삭제 대상이 아니다.

## 9. 현재 기능 기준에서 꼭 알아야 할 제약

이 문서는 기대 동작이 아니라 현재 붙어 있는 기능 기준이므로, 아래 제약을 함께 이해해야 한다.

### 9.1 운동 종료 직후 자동 이동은 연결되어 있음

- 결과 라우트는 존재한다.
- 현재 운동 종료 직후에는 해당 세션의 결과 화면으로 바로 이동한다.
- 따라서 결과 화면은 사후 조회 화면이면서 운동 종료 직후의 랜딩 화면 역할도 함께 가진다.

### 9.2 수정 가능한 항목은 메모와 세트 수만 해당

- 메모는 기존 입력 영역에서 수정하며 연필 아이콘을 누를 때 현재 값의 저장을 시작한다. 세트 수는 이어서 열린 바텀시트에서 명시적으로 저장한다.
- 운동 부위/세부 부위, 시작/종료 시각, 위치, HealthKit 데이터는 결과 화면에서 수정할 수 없다.
- 세트 수 수정 중에도 운동 부위/세부 부위 구성은 읽기 전용이며 추가, 삭제, 변경할 수 없다.
- 재분류 기능은 현재 없다.
- 운동 기록 삭제는 가능하지만, 이는 메모처럼 특정 필드를 수정하는 기능이 아니라 세션 전체를 제거하는 기능이다.

### 9.3 총 칼로리 데이터는 조회되지만 화면에는 직접 보이지 않음

- HealthKit 상세 객체에는 `totalKcal` 필드가 있다.
- 하지만 현재 UI 카드에는 활동 칼로리만 표시한다.

### 9.4 위치명은 역지오코딩 결과

- 지도는 좌표 기반으로 표시된다.
- 하단 위치 텍스트는 저장 좌표의 역지오코딩 결과를 사용하고, 실패하면 좌표 문자열을 표시한다.
- 같은 저장 좌표가 자동 학습 운동 장소와 도착 알림의 기준이 된다.

### 9.5 심박 차트는 실제 측정 간격을 유지한다

- 차트 포인트는 선택된 workout 시작~종료 구간 내 실제 시각 비율을 X축으로 사용한다.
- 측정 공백은 그만큼 넓은 간격으로 표시한다. 선은 인접 측정값을 연결한 것이며 공백 중 추가 측정값을 생성하지 않는다.

### 9.6 삭제는 연결 일정과 로컬 기록을 함께 처리한다

- 연결된 OS 캘린더 일정 삭제를 먼저 처리한 뒤 앱 내부 로컬 저장소와 날짜 인덱스를 삭제한다.
- HealthKit 기록은 삭제하지 않는다.
- OS 일정이 이미 없으면 앱 기록 삭제를 계속한다.
- 캘린더 일정이 연결되지 않았거나 권한/기타 오류로 삭제할 수 없으면 사용자가 `앱 기록만 삭제`를 명시적으로 선택해야 로컬 삭제를 계속한다.

## 10. 이 페이지가 제공하는 비즈니스 가치

이 결과 화면은 단순한 기록 확인 페이지가 아니라, 사용자가 완료된 운동을 다시 해석하고 되돌아볼 수 있게 하는 회고 화면이다.

가치는 다음과 같다.

1. 운동 직후 남긴 기록을 나중에도 다시 확인할 수 있다.
2. 운동 메모와 잘못 입력한 세트 수를 사후에 보완하면서 기록 완성도를 높일 수 있다.
3. 운동 시간, 칼로리, 심박수 같은 생체 정보와 사용자가 직접 입력한 정보를 한 번에 볼 수 있다.
4. 위치 정보까지 함께 남겨 운동 맥락을 회상하기 쉽게 만든다.
5. 실수로 저장된 운동과 연결된 캘린더 일정을 함께 삭제해 잘못된 기록을 정리할 수 있다.

## 11. 요약

현재 YepBuddy의 결과 화면은 “저장된 운동 세션을 다시 열어 보고, 메모와 세트 수를 제한된 범위에서 보완하고, HealthKit과 위치 정보를 함께 확인하며, 잘못 저장된 운동 기록과 연결된 캘린더 일정을 삭제할 수 있는” 조회 중심 구조다.

사용자는 날짜, 부위, 시간, 세트 수, 메모, 심박수 흐름, 위치를 한 화면에서 확인할 수 있다. 필드 단위 수정은 메모와 기존 항목의 세트 수만 가능하며 운동 부위 구성은 바꿀 수 없다. HealthKit 데이터가 없으면 관련 통계는 유연하게 비워 두고, 캘린더 이벤트 ID가 있거나 과거 일정이 유일하게 일치할 때만 동일 OS 일정을 수정·삭제하는 것이 이 화면의 핵심 원칙이다.
