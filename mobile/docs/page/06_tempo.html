개요

템포 페이지는 운동 중 수축/이완 리듬을 일정하게 유지하도록 돕는 단일 화면 타이머다. 사용자는 진행 순서와 시간, 횟수, 세트, 휴식 시간을 설정한 뒤 30초 준비 카운트다운을 거쳐 자동 진행되는 템포 안내를 받는다.

범위: /tempo 진입 → 설정 → 30초 준비 → 수축/이완/count 반복 → 세트 간 휴식 → 완료 후 대기

라우트 · 진입

TempoPage는 TempoScreen을 감싸는 엔트리다. 일반 탭 진입과 운동 중 복귀 진입을 fromWorkout 파라미터로 구분한다.

일반 템포 탭
  • 하단 탭의 템포 화면으로 진입한다.
  • 상단에는 템포 제목만 표시된다.
  • 우하단 설정 FAB가 표시된다.
!isFromWorkout && <SettingsFab />
운동 중 템포 진입
  • fromWorkout=1이면 뒤로가기 버튼을 표시한다.
  • 뒤로가기는 router.replace("/workout/active")로 운동 화면을 복구한다.
  • 설정 FAB는 숨겨 운동 복귀 동선을 우선한다.
showBackButton={isFromWorkout}

기본 설정

화면 진입 시 useReducer는 initialTempoState를 사용한다. 이 값은 로컬 저장소에서 복원되지 않으며, 화면을 새로 열면 항상 같은 기본값으로 시작한다.

모드 · 설정 컨트롤

모드 선택과 스테퍼 설정은 시작 전에는 조작 가능하고, 타이머가 실행 중이면 pointerEvents="none"와 opacity-40으로 잠긴다. 시작 버튼도 실행 중에는 렌더링되지 않는다.

진행 모드
  • ●수축 먼저: 수축 → 이완 → count
  • ●이완 먼저: 이완 → 수축 → count
  • ●선택 버튼은 accent/glass variant로 상태를 표시한다.
스테퍼 규칙
  • ●수축/이완/횟수/세트는 -1, +1 단위.
  • ●휴식은 -10, -1, +1, +10 조작을 지원한다.
  • ●직접 텍스트 입력은 없다.
값 최소값 최대값 보정 위치
수축1초없음Math.max(1, payload)
이완1초없음Math.max(1, payload)
횟수1회없음Math.max(1, payload)
세트1세트없음Math.max(1, payload)
휴식0초없음Math.max(0, payload)

준비 카운트다운

시작 버튼을 누르면 곧바로 본 템포가 시작되지 않고 고정 30초 준비 단계로 들어간다. 이 단계는 사용자 설정으로 변경할 수 없다.

화면 표시
  • ●상태 라벨은 tempo.preparing으로 표시된다.
  • ●중앙 링은 rawElapsed / 30_000 진행률을 사용한다.
  • ●중앙 숫자는 Math.ceil((30_000 - rawElapsed) / 1000)로 계산한 남은 초다.
  • ●현재 세트/횟수는 0으로 유지되어 하단 요약에는 대시가 보인다.
10초 경고

남은 시간이 10초가 되는 프레임에서 playRestWarning()을 호출한다. 같은 초 안에서 반복 호출되지 않도록 prevPositionRef.lastTickSecond로 초 단위 게이트를 둔다.

경고 피드백: rest-warning.mp3 + Haptics.ImpactFeedbackStyle.Heavy

템포 phase 머신

카운트다운 이후 위치 계산은 누적 tick이 아니라 Date.now() - startedAt에서 카운트다운 30초를 뺀 경과 시간으로 매 프레임 다시 계산한다. 핵심 계산은 calculateTempoPosition에 모여 있다.

State / phase flow
graph TD I[idle] -->|start| CD[countdown
30 sec fixed] CD -->|rawElapsed >= 30s| P{modeIndex} P -->|0 contraction first| C[contraction] P -->|1 relaxation first| R[relaxation] C --> R2[relaxation] R2 --> CNT[count
1 sec] R --> C2[contraction] C2 --> CNT CNT --> REP{rep complete?} REP -->|more reps| P REP -->|set complete| SET{last set?} SET -->|no| REST[rest] REST --> P SET -->|yes| DONE[finish] DONE --> I
Rep duration
contraction + relaxation + 1000ms

count phase는 매 반복 끝에 고정 1초다.

Set duration
repMs * reps

마지막 세트를 제외하면 여기에 휴식 시간이 붙는다.

Progress
phaseElapsed / phaseDuration

링은 현재 phase 기준 진행률만 표시한다.

휴식 · 완료

세트 간 휴식

  • ●마지막 세트가 아니고 현재 세트의 모든 rep가 끝나면 rest phase로 들어간다.
  • ●휴식 시작 phase 변경 시 playRestStart()가 실행된다.
  • ●remainingRest === 10이면 10초 경고음/햅틱이 실행된다.
  • ●rest=0이면 계산상 휴식 구간 길이가 0이므로 다음 세트로 즉시 넘어간다.

전체 완료

  • ●elapsedMs >= totalMs이면 isFinished로 판정한다.
  • ●stop()으로 상태, 진행률, 카운트다운, RAF 참조를 초기화한다.
  • ●초기화 후 playComplete()로 성공 햅틱을 1회 시도한다.
  • ●완료 기록 저장, 결과 화면 이동, 통계 반영은 없다.
UI nuance: useTempoTimer는 remainingRest를 반환하지만 TempoScreen과 TempoRingDisplay는 이 값을 전달하거나 표시하지 않는다. 사용자는 휴식 phase 여부는 보지만 남은 휴식 초 숫자는 별도로 보지 못한다.

사운드 · 햅틱 · 백그라운드 타이밍

오디오와 햅틱은 템포 계산과 분리되어 있으며, phase와 초 단위 게이트를 기준으로 호출된다. 오디오 초기화 실패는 콘솔 경고만 남기고 타이머 진행을 막지 않는다.

Audio mode

expo-audio에서 백그라운드 재생과 무음 모드 재생을 허용하고, 다른 오디오와는 mix 방식으로 동작하도록 설정한다.

AppState active

앱이 다시 active가 되면 기존 RAF를 취소하고 다음 프레임에서 시작 시각 기준 위치를 재계산한다.

Unmount

화면 언마운트 시 RAF와 오디오 플레이어를 정리한다. 세션 복원용 상태 저장은 없다.

제약

세션 제어

시작 후 일시정지, 재개, 수동 종료 버튼이 없다. 완료되거나 화면을 벗어나야 세션이 끝난다.

저장 · 복원

진행 중 스냅샷, 완료 기록, 마지막 설정값을 저장하지 않는다. 화면 재진입 시 기본 상태로 돌아온다.

입력 범위

최소값만 있고 최대값 제한이 없다. 매우 큰 값은 긴 세션으로 그대로 계산된다.

오디오 범위

숫자 음성은 1부터 20까지다. 21회 이상부터는 count phase가 진행되어도 숫자 음성이 재생되지 않는다.

준비 시간

준비 카운트다운은 30초 고정이다. 사용자가 변경할 수 있는 UI나 상태 필드가 없다.

권한

템포 화면 진입에는 별도 OS 권한이 필요하지 않는다. 오디오/햅틱 실패는 사용자 메시지 없이 진행된다.

스펙 ↔ 코드 갭

[확인] md의 핵심 흐름은 현재 코드와 일치

기본값, 30초 준비 카운트다운, 수축/이완/count 순서, 세트 간 휴식, 완료 후 idle 초기화, 실행 중 입력 잠금은 코드와 맞다.

[확인] 휴식 잔여 초는 계산되지만 UI에는 미노출

useTempoTimer는 remainingRest를 반환하지만 TempoScreen은 이 값을 TempoRingDisplay에 전달하지 않는다. 따라서 휴식 라벨과 링 진행률만 보인다.

[확인] count 음성은 20회까지만 있지만 진행 계산은 제한 없음

COUNT_SOURCES는 1~20 파일만 포함하고 playCount는 범위 밖이면 return한다. reducer에는 reps 최대값이 없으므로 21회 이상도 화면/타이머는 계속 진행된다.

[확인] 완료 시 "화면 상태 초기화 후 성공 햅틱" 순서

useTempoTimer는 position.isFinished일 때 stop()을 먼저 호출하고, 그 다음 playComplete()를 호출한다.
