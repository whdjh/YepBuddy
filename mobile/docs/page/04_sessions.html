개요

세션 목록 화면은 저장된 완료 운동 세션을 월별로 탐색하고, 부위 필터로 좁힌 뒤, 선택한 세션의 결과 화면으로 이동하는 읽기 전용 히스토리 허브다. 현재 구현은 로컬 저장 세션을 기준 데이터로 삼고 HealthKit workout 요약은 kcal 보강에만 사용한다.

범위: /sessions → 월별 세션 로드 → 필터 적용 → SessionCard → /workout/[sessionId]

라우트 · 진입

src/app/sessions.tsx는 WorkoutNavigationGuard와 SessionListScreen만 렌더링한다. 실제 화면 헤더, 필터, 스크롤 목록, 카드 이동은 모두 기능 슬라이스인 features/view-sessions 안에 있다.

SessionListScreen.tsx · t("sessions.title")

필터 탭

필터는 화면 상단의 가로 스크롤 pill 목록이다. 기본값은 all이고, 선택값은 SessionListScreen의 로컬 state로만 관리된다. 필터 변경 시 저장소나 HealthKit을 다시 읽지 않고, 이미 로드된 sessions 배열에 클라이언트 사이드 필터를 적용한다.

표시 라벨 값 필터 규칙
모두all전체 세션 반환
가슴 · 등 · 하체 · 어깨 · 팔 · 코어BodyPartsession.bodyParts.includes(activeFilter)
세부 부위는 목록 필터에서 직접 쓰지 않는다. 저장 세션의 WorkoutBodyPartSet[]는 getUniqueWorkoutBodyParts를 거쳐 상위 부위 배열로 정규화된다.

월별 세션 로드

useInfiniteSessions는 현재 월부터 과거 방향으로 월 단위 데이터를 누적한다. 최초 진입 또는 refreshKey 변경 시 현재 월 포함 3개월을 순차 로드하고, 스크롤 하단에서 240px 이내로 접근하면 마지막 로드 월의 이전 달 1개를 추가로 읽는다.

초기 범위
현재 월 + 과거 2개월
INITIAL_MONTH_COUNT = 3
추가 로드 조건
하단까지 240px 미만
distanceFromBottom < 240
중복 제거
sessionId 기준 Map 병합
mergeSessions()
코드상 포그라운드 복귀(AppState active)와 자정 경계에서도 refreshKey를 올려 초기 3개월 로드를 다시 수행한다. 비동기 응답 충돌은 requestIdRef로 오래된 응답을 무시한다.

카드 렌더링

필터링된 목록은 groupByMonth로 묶이고, 각 그룹은 formatMonthYear로 YYYY년 M월 헤더를 표시한다. 각 세션은 SessionCard로 렌더링되며 카드 전체가 눌리는 대상이다.

카드 요소 구현 기준
대표 아이콘상위 부위 배열의 첫 번째 값, 없으면 null
부위 문자열상위 부위 라벨을 + 로 연결, 없으면 미지정
칼로리HealthKit 매칭 kcal, 없으면 -- KCAL
날짜startedAt 기반 MM.DD 요일
탭 동작/workout/${encodeURIComponent(sessionId)}로 이동

HealthKit 병합

월별 로드는 로컬 완료 세션과 HealthKit workout 요약을 Promise.all로 동시에 조회한다. 이후 HealthKit 결과를 startDate 기준 Map으로 만들고, 저장 세션의 sessionId와 같은 workout이 있을 때만 kcal을 채운다.

로컬 저장 세션
  • sessionId, startedAt, completedAt
  • bodyParts에서 상위 부위와 총 세트 수 계산
  • 결과 화면 이동의 유일한 기준
HealthKit workout
  • iOS + 이전 접근 상태 enabled일 때 비프롬프트 초기화
  • 월 시작/끝 로컬 날짜 범위로 workout 조회
  • calories를 반올림해 kcal로 사용
HealthKit workout만 존재하는 운동은 목록 카드로 추가되지 않는다. 저장 세션을 순회하며 보강하기 때문에 HealthKit은 단독 데이터 소스가 아니라 보조 지표다.

빈 상태 · 로딩 상태

초기 로딩

isLoadingInitial이고 월 그룹이 비어 있으면 중앙 ActivityIndicator를 표시한다.

추가 로딩

isLoadingMore이면 목록 하단에 ActivityIndicator를 표시한다.

데이터 없음

초기 로딩이 끝났고 그룹이 없으면 데이터가 없습니다.를 표시한다.

저장 세션 없음, 초기 3개월 범위에 세션 없음, 필터 결과 없음, 월별 조회 실패 후 빈 목록은 현재 동일한 빈 상태 문구로 합쳐진다.

스펙 ↔ 코드 갭

[확인된 제약] "무한 스크롤"은 전체 기간 완전 로드를 보장하지 않음

스크롤 하단 접근 때 이전 월을 1개씩 추가하는 방식이다. 끝 조건, 마지막 세션 월 감지, 전체 기간 완료 플래그는 없다.

[코드 보강] 앱 복귀와 자정 refresh가 md보다 명확함

useInfiniteSessions는 AppState가 active가 되거나 자정 타이머가 실행되면 refreshKey를 올려 현재 월 기준 초기 3개월을 다시 계산한다.

[표시 차이] totalSets는 계산하지만 현재 카드에는 표시하지 않음

loadSessionsByMonth는 totalSets를 계산해 SessionListItem에 담지만, SessionCard는 현재 부위, kcal, 날짜만 렌더링한다.

[빈 상태] 원인별 안내 문구 없음

전체 데이터 없음, 필터 결과 없음, 초기 로드 범위 내 데이터 없음은 모두 workout.result.noData 번역값인 데이터가 없습니다.로 표시된다.

[HealthKit 계약] workout 단독 노출 없음

HealthKit 월 요약은 저장 세션의 sessionId와 workout startDate가 일치할 때 kcal만 보강한다. HealthKit에만 있는 workout은 세션 목록 카드로 나오지 않는다.
