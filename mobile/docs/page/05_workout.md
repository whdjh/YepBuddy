# 운동 화면 기능서

> 현재 구현 기준으로 정리한 문서.  
> 범위: `운동 시작 → 카운트다운 → 운동 중 기록 → 운동 종료 → 캘린더 자동 연동`

## 1. 문서 목적

이 문서는 YepBuddy의 운동 실행 화면이 어떤 역할을 하는지, 사용자가 어떤 흐름으로 이용하는지, 어떤 예외 상황을 처리하는지를 비즈니스 관점에서 이해할 수 있도록 정리한 기능서다.

기획 아이디어나 희망사항이 아니라, 현재 페이지에 연결되어 있는 실제 동작을 기준으로 작성한다.

## 2. 기능 한눈에 보기

운동 화면은 사용자가 운동을 시작한 순간부터 종료할 때까지의 한 세션을 기록하는 영역이다.

핵심 역할은 4가지다.

1. 운동을 빠르게 시작하게 한다.
2. 운동 중 입력과 시간을 지속적으로 기록한다.
3. 앱이 꺼지거나 중간에 이탈해도 진행 중인 운동을 복원한다.
4. 운동이 끝나면 기기 기능과 연동해 기록을 남긴다.

## 3. 사용자 흐름

```text
메인 요약 화면
  └─ 운동 카드 탭
      └─ 카운트다운 화면
          ├─ 3초 카운트다운 진행
          ├─ 캘린더 자동 저장 선호값이 unknown이면 1회성 동의 Alert 표시
          ├─ 위치 1회 기록 시도
          └─ 기존 운동 리마인더 취소
              └─ 운동 중 화면 진입
                  ├─ 실시간 타이머 시작
                  ├─ HealthKit live metric 동기화 시도
                  ├─ 운동 부위 선택
                  ├─ 세부 부위 선택
                  ├─ 세트 수 조절
                  ├─ 메모 작성
                  ├─ 일시정지 / 재개
                  ├─ 저장하지 않고 종료하기
                  │   ├─ 취소 확인 팝업 표시
                  │   ├─ 진행 중 스냅샷 제거
                  │   └─ 메인 탭 화면으로 복귀
                  └─ 운동 종료
                      ├─ 운동 세션 저장
                      ├─ 위치가 있으면 반복 운동 장소 히스토리 반영
                      ├─ HealthKit 저장 시도
                      ├─ 캘린더 일정 등록 시도
                      ├─ 운동 리마인더 프롬프트 없는 재동기화
                      ├─ 장소 도착 알림 프롬프트 없는 재동기화
                      └─ 결과 화면으로 이동
```

## 4. 화면 범위

| 화면 | 경로 | 역할 |
| --- | --- | --- |
| 카운트다운 화면 | `/workout/countdown` | 운동 시작 직전 진입 연출과 사전 준비 처리 |
| 운동 중 화면 | `/workout/active` | 운동 시간, 입력값, 실시간 상태를 기록하는 메인 화면 |

참고:

- 운동 결과 화면 `/workout/[id]` 라우트는 존재한다.
- 현재 운동 종료 직후에는 저장된 세션의 결과 화면으로 이동한다.
- 따라서 본 문서는 “운동 실행 플로우”에 집중한다.

## 5. 화면별 기능

### 5.1 운동 시작 진입

사용자는 메인 요약 화면의 운동 카드를 눌러 운동을 시작한다.

현재 동작 기준:

- 사전 입력 단계 없이 바로 시작한다.
- 운동 종류는 “근력 운동” 단일 흐름으로 취급한다.
- 누르면 바로 카운트다운 화면으로 이동한다.

### 5.2 카운트다운 화면

카운트다운 화면은 운동 전환 화면이자 백그라운드 준비 처리 구간이다.

사용자에게 보이는 기능:

- 3초 카운트다운 숫자 표시
- 원형 진행 링 애니메이션
- 운동 아이콘과 라벨 표시

사용자에게 보이지 않는 시스템 동작:

- 새 운동 세션을 `countdown` 상태로 전환
- 캘린더 자동 저장 선호값이 `unknown`이면 기존 자동 저장 동의 Alert를 한 번 표시
- 사용자가 자동 저장에 동의한 경우에만 캘린더 권한 요청
- 기존에 예약된 운동 리마인더 알림이 있으면 취소
- 현재 위치를 1회 조회해 운동 세션에 저장 시도
- 카운트다운 종료 후 자동으로 운동 중 화면으로 이동

이 화면의 의미:

- 사용자는 “운동이 곧 시작된다”는 심리적 준비를 한다.
- 시스템은 실제 기록 시작 전에 필요한 초기 작업을 처리한다.
- 캘린더 자동 저장 Alert와 권한 선택은 카운트다운과 기록 시작을 막지 않는다.

### 5.3 운동 중 화면

운동 중 화면은 실제 기록의 중심 화면이다. 사용자는 이 화면에서 운동 시간을 확인하고, 운동 내용을 입력하고, 세션을 종료한다.

#### 5.3.1 상단 실시간 지표

표시 항목:

- 심박수
- 활동 칼로리
- 총 칼로리

동작 방식:

- 운동이 기록 중일 때 iPhone HealthKit live workout session 연동을 초기화한다.
- AirPods Pro 3 등 iPhone HealthKit live metric으로 심박수나 칼로리를 제공할 수 있는 환경을 지원 대상으로 본다.
- 심박수, 활동 칼로리, 총 칼로리가 모두 비어 있거나 `0`이면 생체 지표 영역 전체를 숨긴다.
- `수신중`, `센서 대기 중`, `권한 없음` 같은 HealthKit 상태 문구는 운동 중 화면에 기본 표시하지 않는다.
- 심박수 또는 칼로리 중 하나라도 실제 값이 들어오면 생체 지표 영역을 표시한다.
- 생체 지표 영역이 표시된 상태에서 심박수만 없으면 심박수 값은 `--`로 표시하고 칼로리 값은 그대로 표시한다.
- Apple Watch 기반 실시간 심박수/칼로리는 이 화면의 지원 범위가 아니다. Apple Watch 앱, Watch companion, workout mirroring은 만들지 않는다.
- Galaxy/Android 웨어러블 기반 실시간 심박수/칼로리도 지원 범위가 아니다.

#### 5.3.2 운동 부위 선택

사용자가 선택할 수 있는 부위:

- 가슴
- 등
- 하체
- 어깨
- 팔
- 코어

동작 규칙:

- 여러 부위를 동시에 선택할 수 있다.
- 이미 선택한 부위를 다시 누르면 선택 해제된다.
- 부위를 새로 선택하면 기본 세트 수 `10`이 자동으로 들어간다.
- 운동 부위 칩을 길게 누르면 해당 부위의 세부 부위 선택 줄이 열린다.
- 운동 부위 칩 자체에는 세부 부위가 선택되어도 상위 부위명만 표시된다.
- 세부 부위를 선택하면 `가슴 상부`처럼 별도 운동 항목이 추가된다.
- 같은 세부 부위를 다시 누르면 해당 세부 운동 항목만 해제된다.
- 상위 부위를 다시 눌러 해제하면 해당 상위 부위와 연결된 세부 운동 항목도 함께 사라진다.

#### 5.3.3 세트 수 조절

세트 수는 선택한 운동 항목에 대해서만 노출된다.

동작 규칙:

- 상위 부위를 선택하면 `가슴` 같은 항목의 세트 수 조절 영역이 나타난다.
- 세부 부위를 선택하면 `가슴 상부` 같은 항목의 세트 수 조절 영역이 별도로 나타난다.
- 스테퍼 UI로 증가/감소한다.
- 최소값은 `1`세트다.
- 각 운동 항목은 독립적인 `setCount`를 가진다.
- 운동 항목을 해제하면 해당 항목의 세트 수 기록도 함께 사라진다.

#### 5.3.4 메모 입력

사용자는 자유롭게 운동 메모를 입력할 수 있다.

예시:

- 오늘의 무게 기록
- 컨디션 메모
- 다음 운동 때 참고할 포인트

동작 규칙:

- 텍스트를 자유롭게 입력할 수 있다.
- 별도 저장 버튼 없이 디바운스로 자동 저장 대상에 포함된다.

#### 5.3.5 하단 드로어

운동 중 화면 하단에는 드래그 가능한 드로어가 있다.

표시 요소:

- 운동 아이콘
- 경과 시간 타이머
- 진행 링
- 일시정지/재개 버튼
- 좌측 원형 "유산소 시작" 버튼
- 드로어 펼침 상태 최상단 "템포" 이동 버튼
- 운동 종료 버튼
- 저장하지 않고 종료하기 버튼

동작 방식:

- 드래그로 열고 닫을 수 있다.
- 닫힌 상태에서도 일시정지/재개 원형 버튼과 좌측 "유산소 시작" 원형 버튼은 유지된다.
- 일시정지 원형 버튼을 누르면 타이머가 멈추고 드로어가 열린 상태로 전환된다.
- 일시정지 상태에서 원형 버튼은 재개 버튼으로 바뀐다.
- 일시정지/재개 원형 버튼은 위험 액션 색상이 아니라 neutral 배경과 accent 아이콘을 사용한다.
- 드로어 펼침 상태 최상단의 "템포" 버튼을 누르면 템포 화면으로 이동한다.
- 운동 종료 버튼은 드로어 안에서 항상 사용할 수 있다.
- 타이머는 `MM:SS.CC`(센티초) 형식으로 표시된다.
- “저장하지 않고 종료하기”는 빨간색 위험 액션 버튼으로 표시된다.

### 5.4 일시정지 / 재개

사용자는 하단 드로어 또는 iOS 잠금화면 Live Activity에서 운동을 일시정지하거나 다시 시작할 수 있다.

일시정지 시:

- 운동 상태가 `paused`로 변경된다.
- 일시정지 시점이 기록된다.
- 타이머는 멈춘 것처럼 보인다.

재개 시:

- 운동 상태가 `recording`으로 돌아간다.
- 멈춰 있던 시간은 누적 휴지 시간으로 계산된다.
- 실제 운동 시간 계산에서 일시정지 구간은 제외된다.

현재 구현 기준의 기술적 특성:

- 앱 내부 상태와 타이머는 정확히 pause/resume 된다.
- HealthKit 라이브 세션도 `pauseWorkoutSession` / `resumeWorkoutSession` API로 함께 제어된다.
- 하단 드로어와 Live Activity action은 같은 `pause` / `resume` 운동 command 의미를 사용한다.
- Live Activity action은 앱 화면을 foreground로 열지 않고 상태 전환과 HealthKit pause/resume만 시도한다.
- HealthKit 호출 실패는 로컬 운동 상태 전환을 되돌리지 않는다.

### 5.4.1 iOS 잠금화면 Live Activity 제어

iOS에서는 운동이 `recording` 또는 `paused` 상태일 때 ActivityKit Live Activity를 표시한다.

잠금화면 Live Activity 표시 정보:

- 앱 이름 `옙버디`
- 현재 상태 문구: `운동 기록 중`, `운동 일시정지`, `유산소 기록 중`, `유산소 일시정지`
- 운동 중 화면과 같은 기준의 경과 시간 타이머
- 유산소 시작 버튼: `figure.run`
- 일시정지/재개 버튼: `pause.fill` 또는 `play.fill`
- 운동 종료 버튼: `stop.fill`

잠금화면 Live Activity action:

- `pause`: 기록 중인 운동을 일시정지한다.
- `resume`: 일시정지된 운동을 재개한다.
- `startCardio`: 기록 중이고 아직 유산소가 시작되지 않은 경우 `cardioStartedAt`을 기록하고 상태 문구를 `유산소 기록 중`으로 바꾼다.
- `finish`: 운동을 완료 저장하고 Live Activity를 즉시 종료한다.

의도적으로 넣지 않는 action:

- 템포 화면 이동
- 저장하지 않고 종료하기

잠금화면 종료의 UX:

- 사용자가 `stop.fill` 버튼을 누르면 Live Activity는 즉시 사라진다.
- 앱이 command를 소비하면 완료 세션 저장, HealthKit 종료, 운동 리마인더 재동기화, 캘린더 자동 저장 정책을 처리한다.
- 이 경로에서는 Alert, 화면 이동, 캘린더 권한 요청을 실행하지 않는다.
- 사용자가 이후 앱을 열면 `/workout/active`에 머물지 않고 메인 화면으로 돌아간다.

현재 Dynamic Island 표시:

- Expanded leading에는 `옙버디`를 표시한다.
- Expanded trailing에는 근력 운동 아이콘을 표시한다.
- Expanded bottom에는 상태 문구와 경과 시간을 표시한다.
- Compact leading/minimal에는 근력 운동 아이콘을 표시한다.
- Compact trailing에는 `운동` 텍스트를 표시한다.
- Dynamic Island에서 잠금화면과 같은 제어 버튼을 제공하는 작업은 다음 브랜치 범위다.

### 5.5 저장하지 않고 종료하기

사용자는 실수로 운동을 시작했거나 현재 세션을 기록으로 남기고 싶지 않을 때 하단 드로어에서 “저장하지 않고 종료하기”를 선택할 수 있다.

동작 흐름:

1. “저장하지 않고 종료하기” 버튼을 누른다.
2. “운동을 취소할까요?” 확인 팝업을 표시한다.
3. 사용자가 취소하면 운동 중 화면에 그대로 머문다.
4. 사용자가 확인하면 HealthKit 라이브 세션을 폐기(`discardWorkoutSession`)한다.
5. 운동 상태를 초기화한다.
6. 진행 중 스냅샷을 제거한다.
7. 메인 탭 화면으로 이동한다.

저장하지 않는 정보:

- 완료 세션
- 날짜 인덱스
- HealthKit 운동 기록
- 캘린더 일정
- 운동 리마인더 재예약

이 기능의 의미:

- 실수로 운동 시작을 눌렀을 때 기록을 남기지 않고 되돌릴 수 있다.
- 완료 저장 전 단계에서 종료하므로, 결과 화면 삭제보다 더 가벼운 복구 흐름이다.

### 5.6 일시정지 / 운동 종료

운동 종료는 세션 저장과 외부 연동이 동시에 일어나는 단계다. 기본 흐름은 먼저 “일시정지”를 눌러 시간을 멈추고, 드로어가 열린 뒤 “운동 종료” 버튼으로 완료 저장을 진행하는 방식이다. 단, 드로어 안의 “운동 종료” 버튼은 기록 중/일시정지 상태와 관계없이 항상 활성화된다.

종료 시 처리 순서:

1. “일시정지” 버튼을 누른다.
2. 운동 상태가 `paused`로 변경되고 타이머가 멈춘 것처럼 보인다.
3. 드로어가 열린 상태로 전환된다.
4. 원형 버튼은 재개 버튼으로 바뀐다.
5. “운동 종료” 버튼을 누른다.
6. 일시정지 시각을 종료 시각으로 사용해 현재 운동 세션을 완료 상태로 전환한다.
7. 세션 데이터를 로컬 저장소에 저장한다.
8. 위치가 있는 세션이면 반복 운동 장소 히스토리에 반영한다.
9. 장소 도착 알림을 권한 프롬프트 없이 재동기화한다.
10. 진행 중 스냅샷을 제거한다.
11. HealthKit 라이브 세션을 종료하고 운동 저장을 시도한다.
12. 운동 리마인더를 권한 프롬프트 없이 재동기화한다.
13. 캘린더 자동 저장 선호 상태를 확인한다.
14. 선호 상태가 `unknown`이면 기기 캘린더에 완료 운동을 자동 저장할지 한 번만 Alert로 묻는다. 일반적으로 이 선호값은 카운트다운 진입 시 이미 확정되어 있으므로, 이 단계는 아직 선호값이 남아 있는 경우의 fallback이다.
15. 선호 상태가 `enabled`이고 캘린더 권한이 이미 허용되어 있으면 조용히 운동 일정을 등록한다.
16. 선호 상태가 `disabled`이거나 권한이 없으면 캘린더 등록만 조용히 건너뛴다.
17. 저장된 세션 ID를 기준으로 결과 화면으로 이동한다.

종료 후 남는 정보:

- 시작 시각
- 종료 시각
- 선택한 운동 부위/세부 부위
- 운동 항목별 세트 수
- 메모
- 운동 시작 위치

반복 운동 장소 히스토리:

- 완료 세션에 위치가 있는 경우만 장소 후보로 사용한다.
- 새 운동 위치가 기존 장소 중심점 기준 120m 이내면 같은 장소로 묶는다.
- 같은 장소에서 완료 운동이 2회 이상 쌓이면 장소 도착 알림의 geofence 후보가 된다.
- 사용자가 운동 기록을 삭제하면 남은 완료 세션 기준으로 장소 히스토리를 다시 계산한다.
- 장소 히스토리 재계산과 geofence 동기화는 권한 상태만 확인하고 OS 권한 프롬프트를 띄우지 않는다.

캘린더 등록 방식:

- 초기 선호 상태는 `unknown`이다.
- `unknown` 상태에서 운동 시작 카운트다운에 진입하면 "앞으로 캘린더에 자동 저장할까요?" Alert를 한 번만 표시한다.
- 사용자가 "자동 저장"을 선택하면 캘린더 권한을 요청하고, 권한이 허용된 경우 `enabled`를 저장한다. 카운트다운 단계에서는 완료 세션이 아직 없으므로 캘린더 이벤트를 등록하지 않는다.
- `unknown` 상태가 앱 안 운동 종료 시점까지 남아 있으면 같은 Alert를 fallback으로 표시하고, 사용자가 동의하면 `enabled` 저장 후 현재 운동을 캘린더에 등록한다.
- 사용자가 "저장 안 함"을 선택하거나 권한이 거부되면 `disabled`를 저장하고 이후 운동 종료에서는 Alert를 다시 띄우지 않는다.
- `enabled` 상태에서는 완료 시 권한 상태만 확인한다. 권한이 이미 허용되어 있으면 자동 등록하고, 권한이 없으면 조용히 건너뛴다.
- `disabled` 상태에서는 완료 시 캘린더 등록을 조용히 건너뛴다. 다시 켜는 동작은 설정 화면의 `캘린더 자동 저장` 토글이 담당한다.
- 잠금화면 Live Activity 종료 경로에서는 선호 상태가 `enabled`이고 캘린더 권한이 이미 허용되어 있을 때만 조용히 등록을 시도한다.
- 캘린더 이벤트 제목은 운동 부위와 세트 수, 유산소 시간을 조합한다. 디로드 세션이면 제목 앞에 `(디로드)`를 붙인다.
  - 예: `(디로드) 가슴(12), 등(8) + 유산소 20분`
- `YepBuddy` 전용 캘린더가 있으면 해당 캘린더에 일정을 추가한다.
- `YepBuddy` 전용 캘린더가 없으면 앱 메인 색상 `#9B7E56`을 사용해 새 캘린더를 만든 뒤 일정을 추가한다.
- 캘린더 앱에서 일정 색상은 개별 이벤트가 아니라 `YepBuddy` 캘린더 색상을 따른다.

## 6. 자동 저장과 복원

이 기능의 중요한 가치는 “운동 중 입력 유실을 막는 것”이다.

### 6.1 자동 저장

자동 저장 대상:

- 현재 운동 단계
- 시작 시각
- 일시정지 상태
- 선택 부위/세부 부위
- 세트 수
- 메모
- 위치
- 실시간 수치

저장 방식:

- 상태가 바뀌면 1초 디바운스 후 AsyncStorage에 저장한다.
- 입력 도중 매번 즉시 저장하지 않고 마지막 변경 상태를 저장한다.

### 6.2 앱 재진입 시 복원

복원 조건:

- 이전에 저장된 세션이 `recording` 또는 `paused` 상태일 때

복원 동작:

- 앱이 다시 열리면 저장된 세션을 읽는다.
- 진행 중 세션이면 자동으로 `/workout/active` 화면으로 이동시킨다.
- 시작 시간과 누적 일시정지 시간을 기반으로 타이머를 다시 계산한다.

사용자 관점의 의미:

- 앱이 꺼지거나 다른 화면으로 나갔다 와도 진행 중 운동을 이어서 기록할 수 있다.

## 7. 권한 및 예외 케이스

이 화면은 위치, HealthKit, 알림, 캘린더 같은 기기 권한과 연결되어 있다. 다만 권한이 없다고 해서 운동 자체를 막지는 않는다.

### 7.1 위치 권한 거부

- 카운트다운에서 위치를 1회 요청한다.
- 거부되면 위치는 저장하지 않는다.
- 운동 플로우는 그대로 진행된다.

### 7.2 HealthKit 사용 불가 또는 생체 지표 조회 실패

- HealthKit 초기화나 생체 지표 조회가 실패해도 운동은 계속 진행된다.
- 실제 심박수나 칼로리 값이 들어오기 전에는 생체 지표 영역을 숨긴다.
- 권한 거부, 센서 대기, 조회 실패 상태를 설명하는 문구는 운동 중 화면에 표시하지 않는다.
- 운동 종료 시 HealthKit 저장이 실패하더라도 로컬 세션 저장은 유지된다.

### 7.3 캘린더 권한 거부

- 앱 안에서 운동 종료 후 1회성 자동 저장 동의 Alert에서 사용자가 동의한 경우에만 캘린더 권한을 요청할 수 있다.
- 설정 화면에서 `캘린더 자동 저장`을 켜는 명시적 액션에서도 캘린더 권한을 요청할 수 있다.
- 앱 시작, Live Activity action, 잠금화면 운동 종료 같은 자동/백그라운드 경로에서는 캘린더 권한을 요청하지 않는다.
- 캘린더 권한이 없거나 등록에 실패해도 운동 종료 자체는 완료된다.

### 7.4 알림 권한 거부

- 운동 리마인더 재예약은 건너뛴다.
- 운동 종료와 저장은 정상 완료된다.

### 7.5 진행 중 이탈

- 운동 중 화면을 벗어나더라도 진행 스냅샷이 남아 있으면 다시 운동 화면으로 복귀시킨다.
- 사용자가 중간에 앱을 나가도 세션 지속성을 보장하려는 목적이다.

## 8. 저장 데이터

운동 세션은 로컬 저장소에 아래 기준으로 남는다.

| 구분 | 저장 내용 | 목적 |
| --- | --- | --- |
| 진행 중 스냅샷 | 현재 운동 상태 전체 | 앱 재실행 시 운동 복원 |
| 완료 세션 | 시작/종료 시각, 부위/세부 부위, 세트 수, 디로드 여부, 메모, 위치 | 운동 기록 보관 |
| 완료 세션 인덱스 | 저장된 전체 세션 ID 목록 | 전체 히스토리와 장소 히스토리 재계산 |
| 날짜 인덱스 | 특정 날짜의 대표 세션 ID | 날짜 기준 조회 준비 |
| 리마인더 ID | 예약된 알림 식별자 | 기존 알림 취소 및 재예약 |
| 캘린더 자동 저장 선호값 | `unknown` / `enabled` / `disabled` | 반복 캘린더 권한/등록 prompt 방지 |
| 반복 운동 장소 | 2회 이상 반복된 운동 장소 후보 | 장소 도착 알림 geofence 등록 기준 |

## 9. 현재 기능 기준에서 꼭 알아야 할 제약

이 문서는 기대 동작이 아니라 현재 붙어 있는 기능 기준이므로, 아래 제약을 함께 이해해야 한다.

### 9.1 결과 화면 자동 이동은 연결되어 있음

- 완료 후 해당 세션의 결과 화면으로 이동한다.
- 결과 화면에서 메모, 통계, 심박수, 위치 정보를 이어서 확인할 수 있다.

### 9.2 캘린더는 선호값 기반 자동 연동

- 최초에는 앱 안 종료 흐름에서 한 번만 자동 저장 여부를 묻는다.
- 이후에는 저장된 선호값과 현재 권한 상태에 따라 자동 등록하거나 조용히 건너뛴다.
- 등록 대상은 `YepBuddy` 전용 캘린더다.
- `YepBuddy` 전용 캘린더의 색상은 앱 메인 색상인 `#9B7E56`이다.
- 잠금화면 Live Activity 종료 경로에서는 Alert나 권한 요청을 실행하지 않는다.

### 9.3 하루 1세션 제한은 현재 화면 레벨에서 강제되지 않음

- 과거 계획서에는 하루 1세션 제한이 있었지만, 현재 구현 코드에는 실제 차단 로직이 붙어 있지 않다.
- 따라서 문서상 정책으로 단정하지 않는다.

### 9.4 실시간 생체 지표 지원 범위는 iPhone HealthKit 기준

- 운동 중 생체 지표는 센서 이름이나 기기 종류를 직접 추론하지 않고, 실제 HealthKit live metric 값 수신 여부로만 표시한다.
- Apple Watch 앱, Watch companion, workout mirroring, Galaxy/Android 웨어러블 연동은 현재 범위에 포함하지 않는다.
- 결과 화면의 심박수 그래프는 저장된 HealthKit 심박 샘플이 있을 때만 표시한다.

## 10. 이 페이지가 제공하는 비즈니스 가치

이 운동 화면은 단순 기록 화면이 아니라, 사용자의 실제 운동 행동을 끊기지 않게 연결하는 실행 플로우다.

가치는 다음과 같다.

1. 운동 시작 진입 장벽이 낮다.
2. 운동 중 기록이 자연스럽고 부담이 적다.
3. 앱 이탈 상황에서도 기록 손실 가능성을 줄인다.
4. 실수로 시작한 운동은 저장하지 않고 종료할 수 있어 잘못된 기록 생성을 줄인다.
5. 운동 종료 후 결과 화면, 캘린더, 리마인더까지 이어져 습관 형성에 도움을 준다.

## 11. 요약

현재 YepBuddy의 운동 화면은 “빠르게 시작하고, 운동 중 필요한 최소 기록을 남기고, 실수 시작은 저장 없이 취소하며, 끝나면 자동으로 외부 시스템과 연결하는” 실행 중심 구조다.

사용자는 복잡한 설정 없이 운동에 진입할 수 있고, 앱은 그 과정에서 시간, 부위/세부 부위, 세트 수, 메모, 위치를 저장한다. 권한이 없는 기능은 유연하게 건너뛰되, 운동 자체는 멈추지 않는 것이 이 플로우의 핵심 원칙이다.
