개요

결과 화면은 저장된 운동 세션 1건을 다시 열어 보는 상세 조회 화면이다. 로컬 완료 세션을 기준 데이터로 삼고, 가능한 경우 HealthKit 운동 상세와 심박 샘플을 결합해 운동 시간, 칼로리, 평균 심박수, 심박 차트를 보강한다.

범위: /workout/[id] → ResultScreen → 메모 수정 · 통계/심박/위치 조회 · 로컬 운동 기록 삭제

라우트·진입 경로

라우트 래퍼는 URL 파라미터 id를 읽고 문자열일 때 decodeURIComponent로 복원해 sessionId로 넘긴다. fromWorkout=1이면 결과 화면의 뒤로가기 버튼은 router.replace("/")로 메인 탭에 복귀한다.

운동 종료 직후

ActiveWorkoutContent가 완료 세션을 저장하고 HealthKit 종료·리마인더 동기화를 시도한 뒤 /workout/[id]로 replace한다. 파라미터에 fromWorkout: "1"을 포함한다.

사후 조회 경로

세션 목록, 캘린더 날짜, 메인 요약 카드, 주간 루틴 세션 리스트에서 세션 ID를 encodeURIComponent한 URL로 이동한다.

로딩·데이터 흐름

useSessionDetail(sessionId)는 세션 ID가 바뀔 때마다 로딩 상태를 켜고 getStoredWorkoutSession과 getWorkoutDetail을 Promise.all로 동시에 호출한다. 화면 언마운트나 ID 변경 뒤 늦게 도착한 응답은 active 플래그로 무시한다.

로딩 중

중앙 ActivityIndicator만 표시한다.

로컬 세션 없음

workout.result.noData 문구만 표시하고 상세 콘텐츠·삭제 버튼은 숨긴다.

HealthKit 없음

로컬 세션이 있으면 화면은 열린다. 통계는 로컬 저장값 또는 fallback으로 채운다.

헤더·상세 카드

상단 네비게이션과 세션 헤더

  • ●화면 제목은 stored.startedAt을 formatDateWithDay로 표시한다.
  • ●세션 헤더의 운동 타입 라벨은 현재 workout.result.strengthTraining으로 고정된다.
  • ●운동 부위는 getWorkoutBodyPartSetLabel로 상위 부위와 세부 부위를 합쳐 쉼표로 표시한다.
  • ●대표 부위가 있으면 BodyPartIconHost, 없으면 덤벨 아이콘을 표시한다.
  • ●시간 줄은 시작 – 종료이며 위치 라벨이 있으면 뒤에 · 위치를 붙인다.

운동 세부사항 카드

카드 현재 계산 기준
운동 시간 HealthKit duration 우선, 없으면 로컬 시작/종료 시각 차이
활동 칼로리 HealthKit activeKcal 우선, 없으면 로컬 activeKcal
세트수 로컬 bodyParts[].setCount 합계
평균 심박수 HealthKit 심박 샘플의 bpm 평균을 반올림

메모 수정

결과 화면에서 사용자가 수정할 수 있는 필드는 메모뿐이다. GlassTextarea는 로컬 세션의 memo를 초기값으로 받고, 별도 저장 버튼 없이 입력 변경 후 300ms 디바운스로 updateStoredWorkoutMemo(sessionId, memo)를 호출한다.

동기화 기준

sessionId 또는 저장된 stored.memo가 바뀌면 화면 상태의 메모를 다시 맞춘다.

저장 방식

기존 완료 세션을 읽고 { ...session, memo }로 바꾼 뒤 saveCompletedWorkoutSession으로 다시 저장한다.

저장 범위

HealthKit 데이터, 운동 부위, 세트 수, 시작/종료 시각, 위치는 수정하지 않는다.

삭제 전 처리

삭제 실행 전에 대기 중인 메모 저장 타이머를 지워 늦은 저장 호출을 막는다.

HealthKit·심박수

HealthKit 상세 조회

  • ●ensureHealthKitReady()가 실패하면 상세는 null이며 로컬 세션 화면은 유지된다.
  • ●sessionId를 날짜로 해석하지 못하면 HealthKit 상세 조회를 중단한다.
  • ●sessionId부터 24시간 뒤까지 workout 샘플을 가져온 뒤 시작 시각이 가장 가까운 샘플 1개를 고른다.
  • ●선택된 workout의 시작·종료 구간으로 심박 샘플을 다시 조회한다.
  • ●HealthKit workout.calories는 현재 activeKcal와 totalKcal에 동일하게 반올림 저장된다.

심박 차트

  • ●심박 샘플이 0개이면 차트 섹션 전체를 렌더링하지 않는다.
  • ●차트 X축은 실제 시간 간격이 아니라 샘플 배열 인덱스다.
  • ●최고·최저 기준선을 표시하고, 평균선은 최고/최저와 15% 이상 떨어진 경우에만 표시한다.
  • ●하단 시간은 첫 심박 샘플의 시작 시각과 마지막 샘플의 종료 시각을 사용한다.
  • ●렌더링은 victory-native와 @shopify/react-native-skia 기반이다.

위치 지도

위치 섹션은 로컬 완료 세션에 location이 있을 때만 표시된다. 위치는 저장 시점의 위도·경도 1개이며, 지도는 기록 확인용으로 고정되어 스크롤, 줌, 회전, 기울이기 조작이 모두 꺼져 있다.

라벨 생성

먼저 lat,lng 좌표 문자열을 표시하고, expo-location 역지오코딩이 성공하면 지역·도시·도로명 등을 합친 라벨로 교체한다.

지도 표시

initialRegion은 저장 좌표 중심, latitudeDelta/longitudeDelta는 0.005다.

하단 문구

workout.result.location 라벨 뒤에 현재 위치명 또는 좌표 fallback을 붙인다.

삭제 동작

삭제 버튼은 로컬 세션이 정상 조회된 상세 콘텐츠 안에서만 표시된다. 사용자가 버튼을 누르면 React Native Alert로 확인을 받고, 예를 선택한 경우에만 삭제한다.

삭제 세부 흐름
sequenceDiagram participant U as 사용자 participant R as ResultScreen participant S as sessionStorage participant P as Place Reminder participant N as Router U->>R: 운동 기록 삭제 탭 R->>R: Alert 표시 U->>R: 예 선택 R->>R: 메모 저장 타이머 취소, isDeleting=true R->>S: deleteStoredWorkoutSession(sessionId) S-->>R: 세션 본문·인덱스 정리 R->>P: 장소 알림 장소 목록 재빌드·동기화 R->>N: replace("/")

  • 완료 세션 본문: yb:workout:session:{sessionId}
  • 완료 세션 ID 인덱스
  • 날짜 대표 세션 키 또는 같은 날짜의 다음 대표 세션으로 재지정
  • 운동 날짜 목록 인덱스

  • HealthKit에 저장된 workout/심박 샘플

삭제 성공 후에는 장소 도착 알림의 장소 후보를 남은 완료 세션 목록으로 다시 만들고 syncWorkoutPlaceArrivalReminder({ allowPrompt: false })를 호출한다. 이 보조 작업은 실패해도 삭제 완료 흐름을 막지 않는다.

스펙 ↔ 코드 갭

[md 보정] 운동 시간·칼로리는 HealthKit 전용이 아니라 로컬 fallback이 있다

원본 md는 운동 시간과 활동 칼로리가 HealthKit 값이 있을 때만 표시된다고 설명하지만, 현재 ResultScreen은 hk.duration이 없으면 로컬 시작/종료 시각 차이를 사용하고 hk.activeKcal이 없으면 stored.activeKcal을 사용한다.

[md 보정] 위치명은 고정 “미지정”이 아니라 좌표·역지오코딩 라벨이다

원본 md는 지도 하단 위치명이 “미지정”이라고 적지만, 현재 코드는 먼저 좌표 문자열을 표시하고 Location.reverseGeocodeAsync가 성공하면 지역·도시·도로명 등을 합친 문자열로 갱신한다.

[확인된 제약] 삭제는 로컬 기록 중심이며 캘린더·HealthKit은 건드리지 않는다

삭제 확인 문구도 캘린더 일정이 삭제되지 않을 수 있음을 안내한다. 구현상 deleteStoredWorkoutSession은 AsyncStorage 세션 본문과 인덱스만 정리하고, HealthKit workout이나 캘린더 이벤트 ID를 찾아 삭제하는 경로는 없다.

[확인된 제약] HealthKit workout 매칭은 sessionId 시작 시각 근처 1건 기준이다

getWorkoutDetail은 sessionId부터 24시간 범위의 workout을 읽고, 시작 시각이 sessionId와 가장 가까운 샘플을 선택한다. 같은 시간대에 여러 운동 샘플이 있으면 HealthKit 상세가 로컬 세션과 다르게 붙을 수 있는 구조다.
