# 세션 목록 화면 기능서

> 현재 구현 기준으로 정리한 문서.  
> 범위: `세션 목록 진입 → 월별 세션 로드 → 부위 필터 적용 → 결과 화면 이동`

## 1. 문서 목적

이 문서는 YepBuddy의 세션 목록 화면이 어떤 역할을 하는지, 사용자가 전체 운동 히스토리를 어떤 방식으로 탐색하는지, 어떤 기준으로 세션 카드가 표시되는지를 비즈니스 관점에서 이해할 수 있도록 정리한 기능서다.

기획 아이디어나 희망사항이 아니라, 현재 코드에 연결되어 있는 실제 동작을 기준으로 작성한다.

## 2. 기능 한눈에 보기

세션 목록 화면은 저장된 운동 세션들을 월별로 묶어 보여주는 히스토리 조회 화면이다.

핵심 역할은 4가지다.

1. 현재 월부터 시작해 과거 세션을 순차적으로 보여준다.
2. 운동 부위 기준으로 로드된 세션을 필터링한다.
3. 각 세션의 날짜, 부위, 칼로리 정보를 카드로 보여준다.
4. 원하는 세션 결과 화면으로 빠르게 이동시킨다.

## 3. 사용자 흐름

```text
메인 화면의 분할 루틴 카드 헤더 셰브론
  └─ 세션 목록 화면 진입
      ├─ 현재 월 기준 초기 세션 로드 시작
      │   ├─ 저장된 완료 세션 조회
      │   └─ 같은 월의 HealthKit workout 조회
      ├─ 두 데이터를 sessionId 또는 시작 시각 근접 기준으로 병합
      ├─ 월별 그룹 렌더링
      ├─ 부위 필터 탭 선택
      │   └─ 로드된 데이터에 클라이언트 사이드 필터 적용
      ├─ 하단 근처까지 스크롤
      │   └─ 이전 월 세션 추가 로드
      └─ 세션 카드 탭
          └─ 결과 화면 이동
```

## 4. 화면 범위

| 화면 | 경로 | 역할 |
| --- | --- | --- |
| 세션 목록 화면 | `/sessions` | 전체 세션 히스토리를 월별로 조회하고 결과 화면으로 이동하는 화면 |

현재 구성 기준:

- 라우트 엔트리는 `app/sessions.tsx`가 담당한다.
- 화면 본문은 `SessionListScreen`이 담당한다.
- 월별 세션 로드는 `useInfiniteSessions`와 `loadSessionsByMonth`로 처리한다.
- 부위 필터는 `FilterTabs`와 `filterSessions`가 담당한다.
- 세션 목록 화면은 조회와 이동만 담당하며, 메모 수정이나 세션 삭제는 하지 않는다.

## 5. 화면별 기능

### 5.1 세션 목록 화면 진입

사용자는 메인 화면의 분할 루틴 카드 헤더에서 셰브론을 눌러 세션 목록 화면으로 들어온다.

현재 동작 기준:

- 상단에 뒤로가기 버튼과 `"세션"` 제목을 표시한다.
- 진입 시 현재 월부터 초기 월 묶음을 자동으로 로드한다.
- 초기 로드 동안에는 중앙에 로딩 인디케이터를 표시한다.

조회 대상:

- 현재 월부터 시작하는 저장된 완료 세션
- 같은 월 범위의 HealthKit workout 요약

### 5.2 필터 탭

화면 상단에는 운동 부위 필터 탭이 가로 스크롤 형태로 표시된다.

제공되는 필터:

- 모두
- 가슴
- 등
- 하체
- 어깨
- 팔
- 코어

동작 규칙:

- 기본 선택값은 `모두`다.
- 필터는 이미 로드된 세션 목록에 대해 클라이언트 사이드에서 적용된다.
- 특정 부위를 선택하면 해당 부위를 포함한 세션만 보인다.
- 세부 부위가 있는 기록도 상위 부위 기준으로 필터링된다.
- 부위가 비어 있는 세션은 `모두`에서만 보인다.

현재 구현 기준의 의미:

- 필터를 바꿔도 서버나 저장소를 다시 읽지 않는다.
- 사용자는 빠르게 조건을 바꿔가며 히스토리를 탐색할 수 있다.

### 5.3 월별 세션 로드

세션 목록은 현재 월부터 시작해 과거 월 방향으로 월 단위 데이터를 읽는다.

현재 동작 기준:

- 최초 진입 시 현재 월 포함 3개월을 먼저 로드한다.
- 화면 하단 근처까지 스크롤하면 이전 월 1개를 추가로 로드한다.
- 이미 로드한 월은 중복 추가하지 않는다.

데이터 로드 방식:

- 월 단위로 저장된 완료 세션을 조회한다.
- 같은 월의 HealthKit workout 요약도 함께 읽는다.
- 저장 세션을 기준으로 카드 목록을 만들고, HealthKit 데이터는 kcal 보강용으로 병합한다.
- HealthKit workout 시작 시각이 저장 세션 식별자 또는 시작 시각과 정확히 같으면 같은 세션으로 보고, 정확히 같지 않아도 5분 이내에서 가장 가까운 workout이면 같은 세션으로 간주해 병합한다.
- HealthKit 요약이 없거나 매칭되지 않으면 저장 세션에 기록된 활동 칼로리를 fallback으로 사용한다.

현재 구현 기준의 의미:

- 세션 목록은 결과 화면 이동이 가능한 저장 세션 중심으로 구성된다.
- HealthKit이 없어도 세션 목록 자체는 표시될 수 있다.

### 5.4 세션 카드 표시

각 세션 카드는 한 건의 완료 세션을 요약해서 보여준다.

표시 항목:

- 운동 부위 문자열
- 칼로리
- 운동 날짜
- 디로드 상태

계산 방식:

- 운동 부위는 저장 세션의 `bodyParts`에서 상위 부위만 중복 없이 추려 표시한다.
- 세션 목록 카드에서는 `가슴 상부` 같은 세부 라벨을 직접 표시하지 않고 `가슴`으로 표시한다.
- 부위가 없으면 `미지정`으로 표시한다.
- 칼로리는 같은 `sessionId` 또는 저장 세션 시작 시각과 가까운 HealthKit workout의 `kcal`을 우선 사용한다.
- HealthKit 값이 없으면 저장 세션의 활동 칼로리로 보강한다.
- 모든 칼로리 값이 없으면 `--`로 표시한다.
- 날짜는 `startedAt` 기준으로 `MM.DD 요일` 형식으로 표시한다.
- 저장 세션의 `isDeload`가 `true`이면 날짜 아래에 작은 `디로드` 상태를 표시한다.
- 접근성 라벨에도 디로드 여부를 포함한다.

현재 구현 기준의 의미:

- 카드의 핵심 식별자는 `sessionId`다.
- 저장 세션은 결과 화면 이동의 기준이 되고, HealthKit은 보조 지표만 제공한다.

### 5.5 세션 카드 탭 동작

현재 구현에서는 카드 전체를 누르면 결과 화면으로 이동한다.

탭 동작:

- `/workout/[sessionId]` 결과 화면으로 이동한다.
- 이동 시 `sessionId`는 URL 인코딩해서 전달한다.

현재 구현 기준의 의미:

- 메인 화면의 최근 세션 카드, 분할 루틴 리스트, 캘린더와 같은 결과 화면 계약을 공유한다.

### 5.6 빈 상태 처리

세션 목록이 비어 있거나, 필터 결과가 없으면 빈 상태 문구를 표시한다.

현재 처리 방식:

- 초기 로딩이 끝났고 렌더링할 세션 그룹이 없으면 `"데이터가 없습니다."` 문구를 표시한다.
- 전체 세션 없음과 필터 결과 없음은 같은 문구로 처리한다.

현재 제약:

- 빈 상태 원인을 구분하는 별도 문구는 없다.

## 6. 데이터 구성 방식

세션 목록 화면은 로컬 저장 세션과 HealthKit workout을 함께 사용한다.

### 6.1 로컬 저장 데이터

로컬 저장 세션에서 사용하는 정보:

- `sessionId`
- `startedAt`
- `completedAt`
- `bodyParts`
- 운동 항목별 `setCount`

역할:

- 세션 카드의 기본 데이터가 된다.
- 결과 화면 이동의 기준이 된다.
- 총 세트 수 계산의 기준이 된다.
- 부위 필터와 카드 뱃지는 상위 부위 기준으로 계산된다.

### 6.2 HealthKit 데이터

HealthKit에서 사용하는 정보:

- 월 범위의 workout 목록
- 각 workout의 `startDate`
- 각 workout의 `kcal`

역할:

- 세션 카드의 칼로리 값을 보강한다.

현재 구현 기준 제약:

- 세션 목록은 HealthKit workout을 단독 세션으로 노출하지 않는다.
- HealthKit 값은 기본적으로 `sessionId = startedAt ISO string` 계약으로 병합하고, iOS live workout이 네이티브 시작 시각을 별도로 기록해 차이가 나는 경우에는 5분 이내의 가까운 시작 시각 기준으로 보강한다.
- HealthKit 조회 결과가 비어 있으면 저장 세션의 `activeKcal`로 칼로리 값을 보강한다.

## 7. 상태와 예외 케이스

### 7.1 초기 로딩 상태

현재 구현 기준:

- 초기 월 세션을 읽는 동안 중앙 인디케이터를 표시한다.
- 초기 로딩 중에는 세션 카드 대신 로딩 상태가 우선 노출된다.

### 7.2 추가 로딩 상태

현재 구현 기준:

- 화면 하단 근처까지 스크롤하면 이전 월을 추가 로드한다.
- 추가 로딩 중에는 목록 하단에 인디케이터를 표시한다.

사용자 관점의 의미:

- 히스토리를 끝까지 내려가며 점진적으로 더 읽을 수 있다.

### 7.3 HealthKit 미연동 상태

가능한 상황:

- 권한이 없음
- iOS가 아님
- 해당 월에 매칭되는 workout이 없음

현재 처리 방식:

- 세션 목록은 저장 세션 기준으로 계속 표시된다.
- 매칭되는 HealthKit workout이 없으면 저장 세션의 `activeKcal`로 보강한다.
- HealthKit workout도 없고 저장 세션의 `activeKcal`도 없으면 칼로리를 `--`로 표시한다.

### 7.4 데이터 없음 상태

가능한 빈 상태는 다음과 같다.

- 저장된 완료 세션이 전혀 없음
- 초기 로드 범위 안에 세션이 없음
- 필터 적용 결과가 없음

현재 처리 방식:

- 모두 동일하게 `"데이터가 없습니다."` 문구로 표시한다.

## 8. 현재 제약 및 비범위

현재 세션 목록 화면에서 지원하지 않는 것:

- 세션 삭제 / 편집 / 공유
- 월별 총합 통계 표시
- HealthKit 전용 세션 단독 노출
- 전체 기간을 끝까지 자동 로드하는 보장된 완전 무한 스크롤
- 빈 상태 원인별 분기 메시지

이번 문서 범위 밖:

- 운동 실행 상세 플로우
- 결과 화면 메모 수정
- 메인 화면 요약 계산
- 캘린더 날짜 히스토리 탐색

## 9. 요약

세션 목록 화면은 “월별 세션 히스토리 + 부위 필터 + 결과 화면 이동”을 제공하는 읽기 전용 조회 화면이다.

현재 구현 기준으로 보면:

- 목록의 기준 데이터는 저장된 완료 세션
- kcal은 월 단위 HealthKit workout을 병합해 보강
- 필터는 로드된 데이터에 대해 클라이언트 사이드 적용
- 세션 카드는 전체 탭 가능하며 결과 화면으로 이동

즉 세션 목록 화면은 전체 운동 이력을 월별로 탐색하고, 원하는 세션의 상세 결과로 진입하는 히스토리 탐색 허브 역할을 한다.
