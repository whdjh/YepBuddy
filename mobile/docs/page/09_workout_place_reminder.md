# 운동 장소 도착 알림 기능서

> 현재 구현 목표의 canonical 문서.
> 범위: `운동 결과 위치 기록 → 운동 장소 자동 학습 → 150m/50m 이중 geofence → 20m 도착 확인 → 운동 시작 알림`

## 1. 기능 목적

사용자의 운동 결과 화면에 저장된 위치를 운동 장소로 자동 학습하고, 해당 장소에 실제로 도착했을 때 OS 로컬 알림으로 운동 시작을 제안한다.

이 기능은 운동 기록을 자동으로 시작하지 않는다. 알림을 누른 뒤 운동일지에서 확인 Alert를 띄우고, 사용자가 `운동 시작`을 선택해야 카운트다운으로 이동한다.

OS geofence는 앱을 깨우는 best-effort 후보 신호다. 장소마다 `150m` 외곽과 `50m` 내부 영역을 함께 등록하고, 어느 Enter 이벤트든 받으면 최대 5분간 위치를 반복 확인한다. 실제 거리와 위치 정확도가 모두 `20m` 이내인 상태를 2회 연속 확인했을 때만 알림을 보낸다.

## 2. 운동 장소 자동 학습

- 운동 시작 시 위치와 수평 정확도를 세션에 기록하고 결과 화면의 위치로 사용한다.
- 완료 세션의 결과 위치가 유효하고, 저장된 정확도가 있으면 정확도 기준을 통과한 경우에 장소 학습에 사용한다.
- 정확도 필드가 도입되기 전에 저장된 기존 결과 위치는 유효한 좌표이면 장소 학습에 포함한다.
- 앱 시작 시 기존 완료 세션 전체를 읽어 결과 위치 기준으로 장소 목록을 재구성한 뒤 장소 알림을 동기화한다.
- 새 운동 완료 시에도 결과 화면과 동일한 시작 위치를 장소 표본으로 사용한다.
- 새 표본이 기존 장소의 최신 좌표에서 `50m` 이내면 같은 장소의 방문으로 병합한다.
- 같은 장소로 병합하면 장소 좌표를 새 표본으로 갱신하고, 좌표가 달라진 경우 주소 라벨을 다시 생성한다.
- 장소 병합은 `50m`, geofence는 `150m`와 `50m`, 실제 도착 거리는 `20m`로 각각 학습, OS 후보 신호, 알림 직전 검증이라는 별도 역할을 가진다.
- 최신 좌표를 기준으로 연속 갱신하므로 각 표본이 직전 좌표에서 `50m` 이내라면 첫 표본과 마지막 표본이 `50m`보다 멀어도 같은 장소로 이어질 수 있다.
- 한 완료 세션은 한 장소의 방문 횟수를 최대 1회만 증가시킨다.
- 장소는 최근 방문 순으로 최대 20개를 유지한다.
- 기존 수동 단일 장소가 저장되어 있으면 첫 조회 시 자동 장소 목록으로 이전해 기존 사용자의 위치를 보존한다.
- 운동 결과를 삭제하면 남은 완료 세션의 결과 위치로 장소 목록을 다시 계산하고 geofence를 재동기화한다.

## 3. 설정 화면

- 기존 `현재 위치를 헬스장으로 등록` 액션은 제공하지 않는다.
- 기존 버튼 위치에는 `등록된 헬스장 위치` 버튼을 표시한다.
- 버튼을 누르면 등록된 장소를 최근 방문 순으로 보여주는 하단시트를 연다.
- 장소가 없으면 운동 결과 위치를 바탕으로 자동 등록된다는 빈 상태를 보여준다.
- 각 장소는 주소 라벨만 표시하며 좌표, 최근 방문 시각, 방문 횟수는 표시하지 않는다.
- 국가 코드가 `KR`인 주소는 `시/도 + 시/군/구 + 상세 위치명` 순서로 표시해 읍면동이 중복되지 않게 한다. 그 외 국가는 기존 역지오코딩 필드 순서를 유지한다.
- 저장된 주소 라벨의 형식 버전이 이전 값이면 역지오코딩에 성공할 때 현재 주소 형식으로 다시 생성하며, 실패하면 다음 조회에서 재시도한다.
- 사용자는 하단시트에서 장소를 삭제할 수 있다.
- 장소를 삭제하면 해당 장소의 기존 source session ID를 제외 목록에 저장해 과거 결과 재구성으로 즉시 되살아나지 않게 한다.
- 삭제 후 같은 장소에서 새 운동 결과가 저장되면 새 session ID로 다시 학습할 수 있다.
- 마지막 장소를 삭제하면 장소 도착 알림도 OFF로 전환하고 geofence를 중지한다.

## 4. Geofence 등록

- 알림이 ON이고 학습된 장소가 있으면 최근 방문 순 최대 10개를 감시한다.
- 각 장소는 반경 `150m` 외곽과 `50m` 내부의 Enter-only geofence 두 개로 등록한다.
- `Location.startGeofencingAsync()`에 장소별 고유 ID와 좌표를 전달한다.
- `TaskManager.defineTask()`는 앱 번들 로드 시 전역 scope에서 등록된다.
- 장소 알림을 OFF 하면 장소 목록은 유지하고 geofence만 중지한다.
- 앱 시작과 장소 변경 후 현재 권한과 저장 상태에 맞춰 geofence를 다시 동기화한다.
- 결과 위치 재구성에 실패하면 장소 알림을 끄고 기존 geofence를 중지한다.

## 5. 권한 원칙

- 운동 시작 위치 기록은 사용자가 운동을 시작하는 흐름에서 foreground 위치 권한을 요청할 수 있다.
- 사용자가 장소 알림 ON을 선택하면 알림 권한, foreground 위치 권한, background 위치 권한을 요청할 수 있다.
- 앱 시작, 운동 종료, 장소 학습, 자동 재동기화에서는 현재 권한 상태만 확인한다.
- 자동 경로에서 권한이 없으면 장소 목록은 유지하고 geofence를 중지한다.
- iOS에서는 background location을 위해 `Always` 권한과 `UIBackgroundModes=location`을 사용한다.

## 6. 실제 도착 확인

150m 또는 50m Enter 이벤트를 받았다고 바로 알림을 보내지 않는다.

1. 알림 enabled, 대상 장소 존재, 현재 운동 상태, 당일 알림 제한을 확인한다.
2. foreground 위치 권한이 이미 허용돼 있으면 최대 5분간 고정밀 background 위치 추적을 시작한다.
3. 각 위치 갱신마다 enabled 상태와 대상 장소 좌표를 다시 확인한다.
4. 현재 위치 정확도와 대상 장소까지의 거리가 모두 `20m` 이내인 상태를 2회 연속 확인하면 알림을 예약한다.
5. 알림 발송, 시간 만료, 장소 삭제, 설정 OFF 또는 정책 차단 시 위치 추적을 중지한다.

같은 장소의 외곽·내부 Enter 이벤트가 연속으로 와도 위치 추적은 중복 시작하지 않는다. 앱이 active인 상태에서 geofence 등록 직후 전달되는 초기 영역 상태는 실제 진입으로 처리하지 않는다.

## 7. 도착 판정과 당일 제한

다음 조건을 모두 만족할 때만 알림을 보낸다.

- 현재 위치 정확도가 `20m` 이내다.
- 현재 위치와 대상 운동 장소 사이의 거리가 `20m` 이내인 상태가 2회 연속 확인된다.
- 운동 상태가 `idle` 또는 `completed`다.
- 마지막 운동 완료일이 오늘이 아니다.
- 마지막 장소 도착 알림 발송일이 오늘이 아니다.

시간 차이는 계산하지 않는다. 사용자의 기기 로컬 날짜 `YYYY-MM-DD`가 바뀌면 다시 알림을 허용한다.

- 12일 13시에 운동 완료 → 12일 남은 시간 동안 차단
- 13일 00시부터 다시 허용
- 장소 학습 또는 기존 장소 이전은 당일 제한을 시작하지 않음
- 정상 흐름에서는 알림 예약이 성공한 경우에만 마지막 알림 시각을 갱신한다.

알림 내용:

- 제목: `운동 장소 근처에 도착했어요`
- 본문: `운동을 시작하시겠어요?`
- data: `type: "workout-place-arrival"`, 실제 장소 ID
- 주소, 좌표, 운동 기록 상세는 포함하지 않는다.

## 8. 알림 탭 동작

- 알림을 누르면 앱을 열고 운동일지 화면으로 이동한다.
- 운동일지 화면은 pending prompt를 읽고 확인 Alert를 표시한다.
- Alert의 `나중에`를 누르면 pending prompt를 삭제하고 아무 동작도 하지 않는다.
- Alert의 `운동 시작`을 누르면 pending prompt를 삭제한다.
- 진행 중 운동이 없으면 `/workout/countdown`으로 이동한다.
- 이미 진행 중인 운동이 있으면 `/workout/active`로 이동한다.

## 9. 저장 데이터

- enabled 상태
- 자동 학습된 운동 장소 목록과 주소 라벨 형식 버전
- 사용자가 삭제한 장소의 기존 source session ID 제외 목록
- 마지막 운동 완료 또는 장소 도착 알림 시각
- pending prompt
- 권한과 geofence 동기화 상태

## 10. 현재 제약

- 150m와 50m는 저장 좌표를 중심으로 한 명목상 원형 반경이며 OS가 정확히 경계에서 Enter 이벤트를 전달한다는 보장은 없다.
- Enter 이벤트가 지연되거나 누락될 수 있고, 이벤트 후 background 위치 추적도 OS에 의해 지연되거나 중단될 수 있다.
- 위치 정확도 값은 오알림을 줄이는 필터지만 실제 오차의 절대 상한을 보장하지 않는다.
- 최신 좌표를 따라가는 단순 정책이라 연속된 표본을 통해 서로 가까운 다른 운동 장소가 하나로 이어질 수 있다.
