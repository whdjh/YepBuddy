개요

YepBuddy의 알림은 앱 실행 시 권한 프롬프트 없이 저장 상태를 동기화하고, 사용자가 설정 화면에서 명시적으로 ON 한 경우에만 OS 권한 요청을 진행한다.

범위: RootLayout 초기화 → 설정 토글 → 운동 시작/종료 재동기화 → 알림 탭 라우팅

src/app/_layout.tsx

/settings
3개 알림 토글의 명시적 ON/OFF

자동 경로는 allowPrompt:false

앱 시작 동기화

루트 레이아웃은 앱 번들 로드 후 알림 응답 핸들러를 등록하고, Android 채널을 보장한 뒤 저장된 활성 상태를 기준으로 각 알림을 재동기화한다.

운동 리마인더

매일 22:00 후보

동작

  • ●설정 토글 ON은 syncWorkoutReminderAtNight({ allowPrompt:true })를 호출해 알림 권한을 요청할 수 있다.
  • ●권한이 허용되면 기존 예약 1건을 취소하고 다음 22:00 알림을 새로 예약한다.
  • ●오늘 완료 세션이 있거나 현재가 22:00 이후면 다음 날 22:00으로 미룬다.
  • ●운동 시작 카운트다운 진입 시 기존 운동 리마인더를 취소한다.
  • ●운동 종료 후에는 프롬프트 없이 다시 동기화한다.

프로틴 세일 알림

고정 세일 + 블랙프라이데이

동작

  • ●토글 ON은 requestProteinSaleNotificationPermissions로 권한을 요청할 수 있다.
  • ●권한 허용 시 기존 예약 ID를 취소하고, 현재 연도와 다음 연도의 아직 오지 않은 세일 알림을 예약한다.
  • ●예약 시각은 세일 시작일 전날 19:00이며, 블랙프라이데이는 11월 마지막 금요일 전날 19:00이다.
  • ●알림 예약/취소는 runProteinSaleNotificationTask 직렬 큐로 처리한다.
  • ●권한 거부나 예약 실패 시 enabled=false로 돌리고 예약 목록을 정리한다.

운동 장소 도착 알림

geofence 150m

동작

  • ●설정 토글 ON에서만 알림, foreground 위치, background 위치 권한을 순서대로 요청할 수 있다.
  • ●2회 이상 반복된 장소만 geofence 후보가 되고 최대 20개까지 등록한다.
  • ●권한은 허용됐지만 후보 장소가 없으면 enabled=true, operational=false, reason no-places로 남긴다.
  • ●자동 동기화에서 권한이 없으면 사용자 enabled 값은 유지하고 operational만 false로 기록한다.
  • ●Enter 이벤트만 알림을 보내며, Exit 이벤트는 마지막 이벤트 상태로만 저장한다.

권한 원칙

자동 경로

앱 시작, 운동 종료, 운동 기록 삭제 후 재동기화에서는 현재 권한만 확인한다.

allowPrompt: false

명시적 ON

설정 화면에서 사용자가 토글을 ON 할 때만 OS 권한 요청이 가능하다.

allowPrompt: true

iOS provisional

알림 권한 판단은 granted 또는 iOS PROVISIONAL을 허용 상태로 본다.

Android 위치

장소 알림의 background 위치 권한 요청 전 별도 Alert로 이유를 설명한다.

[현재 기준] 알림 기능은 3종으로 정리됨

07_notification.md의 canonical 내용 기준으로 운동 리마인더, 프로틴 세일, 운동 장소 도착 알림 3가지를 다룬다.

[코드 근거] 운동 장소 알림은 권한 실패 자동 경로에서 enabled를 보존할 수 있음

syncWorkoutPlaceArrivalReminder는 allowPrompt:false에서 권한이 없으면 geofence를 중지하고 operational=false를 저장하지만, 사용자의 enabled 의도는 enabled: !allowPrompt로 보존한다.

[제약] 운동 리마인더 알림 탭의 별도 라우팅은 현재 없음

프로틴 세일과 장소 도착 알림은 응답 핸들러가 있지만, 운동 리마인더의 kind: workoutReminder를 처리하는 전용 탭 라우팅은 현재 코드에서 확인되지 않는다.
