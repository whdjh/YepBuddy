# 캘린더 화면 기능서

> 현재 구현 기준으로 정리한 문서.  
> 범위: `캘린더 화면 진입 → 월 목록 렌더링 → 운동 날짜 확인 → 결과 화면 이동`

## 1. 문서 목적

이 문서는 YepBuddy의 캘린더 화면이 어떤 역할을 하는지, 사용자가 어떤 날짜를 누를 수 있는지, 운동한 날짜가 어떤 기준으로 표시되는지를 비즈니스 관점에서 이해할 수 있도록 정리한 기능서다.

기획 아이디어나 희망사항이 아니라, 현재 코드에 연결되어 있는 실제 동작을 기준으로 작성한다.

## 2. 기능 한눈에 보기

캘린더 화면은 사용자가 날짜 단위로 운동 이력을 확인하는 조회 중심 화면이다.

핵심 역할은 4가지다.

1. 현재 월부터 과거 월 방향으로 캘린더를 보여준다.
2. 저장된 완료 세션이 있는 날짜를 시각적으로 표시한다.
3. 오늘 날짜를 별도 스타일로 강조한다.
4. 운동한 날짜를 누르면 해당 세션의 결과 화면으로 이동시킨다.

## 3. 사용자 흐름

```text
캘린더 화면 진입
  └─ 캘린더 화면 로드 시작
      ├─ 현재 기준 날짜 계산
      ├─ 현재 월부터 과거 월 목록 생성
      ├─ 각 월별 완료 세션 조회
      │   └─ YYYY-MM-DD -> sessionId 맵 생성
      └─ 화면 렌더링
          ├─ 뒤로가기 헤더 표시
          ├─ 요일 헤더 표시
          ├─ 월별 그리드 표시
          │   ├─ 오늘 날짜 강조
          │   ├─ 운동한 날짜 링 표시
          │   └─ 미래 날짜 비활성화
          └─ 날짜 탭 처리
              ├─ 운동한 날짜 탭 → 결과 화면 이동
              └─ 미래 날짜 / 운동 없는 날짜 탭 → 동작 없음
```

## 4. 화면 범위

| 화면 | 경로 | 역할 |
| --- | --- | --- |
| 캘린더 화면 | `/calendar` | 월별 운동 날짜를 확인하고 결과 화면으로 이동하는 조회 허브 |

현재 구성 기준:

- 라우트 엔트리는 `app/calendar.tsx`가 담당한다.
- 화면 본문은 `CalendarScreen`이 담당한다.
- 월별 날짜 맵은 `useMonthWorkoutDates`로 조회한다.
- 현재 월부터 과거 월 목록은 `useInfiniteMonths`로 계산한다.
- 외부 변경 사항(운동 완료/삭제 등)은 `useCalendarRefreshSignal`로 캘린더 화면 재조회를 트리거한다.
- 진행 중인 운동이 있는 동안 캘린더 진입을 막는 `WorkoutNavigationGuard`로 진입을 보호한다.
- 캘린더 화면은 조회와 이동만 담당하며, 메모 수정이나 세션 편집은 하지 않는다.

## 4.1 OS 캘린더 일정 등록

완료 운동을 OS 캘린더 일정으로 등록하는 동작은 운동 완료 흐름에서 사용자의 캘린더 자동 저장 선호값과 현재 권한 상태에 따라 수행된다.

권한 흐름:

- 사용자가 자동 저장 동의 Alert 또는 설정 화면 토글처럼 명시적 액션을 한 경우에만 캘린더 권한을 요청할 수 있다.
- 선호값이 `enabled`이고 권한이 이미 허용되어 있으면 완료 시 자동 등록한다.
- 선호값이 `disabled`이거나 권한이 없으면 운동 완료는 유지하고 캘린더 등록만 건너뛴다.
- 잠금화면 Live Activity 종료 같은 자동 경로에서는 Alert나 권한 요청을 실행하지 않는다.

이벤트 필드:

- 제목: 운동 부위와 세트 수, 유산소 시간을 조합한 자동 생성 제목
  - 일반 세션 예: `가슴(12), 등(8) + 유산소 20분`
  - 디로드 세션 예: `(디로드) 가슴(12), 등(8) + 유산소 20분`
- 시간: 세션 시작 시각 ~ 종료 시각
- 위치: 역지오코딩으로 얻은 주소(폴백 시 좌표 문자열)
- 메모: 운동 메모 등 추가 정보

플랫폼 분기:

- iOS는 `YepBuddy` 전용 캘린더가 있으면 거기에 일정을 추가하고, 없으면 새 캘린더를 만든 뒤 추가한다.
- Android는 YepBuddy 로컬 캘린더 생성을 먼저 시도하고, 실패하면 쓰기 가능한 기존 캘린더에 일정을 추가한다.

## 5. 화면별 기능

### 5.1 캘린더 화면 진입

사용자는 메인 화면의 오늘의 운동 카드 등을 통해 캘린더 화면으로 들어온다.

현재 동작 기준:

- 진입 시 상단에 뒤로가기 버튼과 제목을 표시한다.
- 화면은 현재 날짜를 기준으로 월 목록과 오늘 날짜 강조 기준을 만든다.
- 월별 데이터는 각 월 렌더링 시 완료 세션 범위를 읽어 날짜 맵으로 변환한다.

조회 대상:

- 현재 기준 날짜
- 현재 월부터 과거 6개월 목록
- 각 월의 저장된 완료 세션

### 5.2 헤더와 요일 표시

화면 상단에는 뒤로가기 버튼과 `"캘린더"` 제목이 표시된다.

그 아래에는 월요일부터 일요일까지의 요일 헤더가 고정으로 표시된다.

동작 규칙:

- 뒤로가기 버튼을 누르면 이전 화면으로 돌아간다.
- 요일 문자열은 번역 리소스를 사용한다.
- 요일 열 폭은 7등분 고정이다.

현재 구현 기준의 의미:

- 사용자는 현재 보고 있는 화면이 날짜 기반 조회 화면이라는 점을 즉시 인지할 수 있다.
- 요일 헤더는 월별 데이터 유무와 상관없이 항상 표시된다.

### 5.3 월 목록 렌더링

캘린더 화면은 현재 월부터 시작해 과거 방향으로 월 목록을 렌더링한다.

현재 동작 기준:

- 기본적으로 현재 월 포함 6개월을 보여준다.
- 월 라벨은 `YYYY년 M월` 형태의 번역 문자열을 사용한다.
- 각 월은 별도의 `MonthGrid`로 렌더링된다.

계산 방식:

- 기준 날짜의 `year`, `month`를 읽는다.
- 현재 월부터 한 달씩 감소시키며 월 목록을 만든다.
- 월이 1월 아래로 내려가면 연도를 1 줄이고 12월로 넘긴다.

현재 제약:

- 지금 구현은 “무한 스크롤”이라기보다 현재 월 기준 고정 6개월 렌더링에 가깝다.
- 사용자가 스크롤 끝에서 추가 월을 동적으로 더 불러오지는 않는다.

### 5.4 월별 운동 날짜 조회

각 월은 저장된 완료 세션을 읽어 `YYYY-MM-DD -> 세션 요약` 형태의 날짜 맵으로 변환한다.

데이터 규칙:

- 월 시작일과 월 마지막 일을 로컬 날짜 키로 만든다.
- 해당 범위의 완료 세션을 `getStoredWorkoutSessionsInRange`로 조회한다.
- 각 세션의 `startedAt`을 로컬 날짜 키로 변환해 날짜 맵에 넣는다.
- 날짜 셀에 표시할 운동 부위는 상위 부위만 중복 없이 추린다.

예시 형태:

```ts
{
  "2026-04-03": {
    sessionId: "2026-04-03T10:00:00.000Z",
    bodyParts: ["chest", "back"],
    hasCardio: false,
    isDeload: true
  }
}
```

현재 구현 기준의 의미:

- 캘린더는 HealthKit workout을 직접 그리지 않고, 저장된 완료 세션 기준으로 운동 날짜를 표시한다.
- 같은 날짜에 여러 세션이 있으면 전체 세션 인덱스에서 최신 대표 `sessionId` 1개를 날짜 셀에 사용한다.
- 디로드 표시는 루틴의 현재 상태가 아니라 저장된 대표 세션의 `isDeload` 값을 기준으로 한다.

### 5.5 날짜 셀 표시 방식

각 날짜 셀은 날짜 숫자와 함께 운동 부위 아이콘 배지를 보여준다.

표시 규칙:

- 오늘 날짜만 채워진 원형 배경으로 강조한다.
- 운동한 날짜에는 상위 운동 부위 아이콘을 배지로 표시한다. 부위가 여러 개면 일부만 표시하고 `+N` 카운트로 추가 개수를 알린다.
- 운동 부위 배지는 상위 부위 기준으로 표시하며, `가슴 상부`와 `가슴 중부`는 모두 `가슴`으로 묶인다.
- 저장된 대표 세션의 `isDeload`가 `true`이면 날짜 셀 하단에 작은 강조색 바를 표시한다. 좁은 셀 안에는 `디로드` 텍스트를 직접 노출하지 않는다.
- 접근성 라벨에는 디로드 날짜임을 알 수 있도록 `디로드`를 포함한다.
- 셀을 롱프레스하면 해당 날짜의 부위 목록을 보여주는 툴팁이 열린다.
- 운동하지 않은 날짜는 날짜 숫자만 보인다.
- 미래 날짜는 비활성화된다.

상태 판단 기준:

- `isToday`: 현재 기준 날짜와 셀 날짜가 같을 때
- `hasWorkout`: 날짜 맵에 `sessionId`가 있을 때
- `isDeload`: 날짜 맵 대표 세션의 `isDeload`가 `true`일 때
- `isFuture`: 현재 기준 날짜보다 미래일 때
- `disabled`: `isFuture || !sessionId`

현재 구현 기준의 의미:

- 사용자는 어떤 날짜에 운동 기록이 있는지 빠르게 훑어볼 수 있다.
- 운동 이력이 없는 날짜를 눌러도 이동이 발생하지 않는다.

### 5.6 날짜 탭 동작

운동한 날짜를 누르면 해당 날짜의 세션 결과 화면으로 이동한다.

탭 동작:

- `sessionId`가 있으면 `/workout/[sessionId]`로 이동한다.
- 이동 시 `sessionId`는 URL 인코딩해서 전달한다.
- `sessionId`가 없으면 탭 동작이 없다.

현재 제약:

- 하루 여러 운동을 선택하는 UI는 없다.
- 같은 날짜에 여러 세션이 저장되는 경우를 캘린더 UI에서 구분하지 않는다.

### 5.7 날짜 변경 반영

캘린더 화면은 날짜 경계와 앱 복귀 시점에 다시 현재 기준 날짜를 계산한다.

현재 동작 기준:

- 최초 진입 시 현재 날짜를 기준으로 렌더링한다.
- 앱이 다시 active 되면 기준 날짜를 갱신한다.
- 자정이 지나면 기준 날짜와 월별 조회 트리거를 갱신한다.

사용자 관점의 의미:

- 앱을 오래 켜 두고 있어도 오늘 강조 표시와 미래 날짜 판정이 다음 날짜 기준으로 바뀐다.
- 월별 날짜 맵도 같은 시점에 다시 읽혀 최신 상태를 반영한다.

## 6. 데이터 구성 방식

캘린더 화면은 현재 구현 기준으로 로컬 저장 세션을 중심으로 동작한다.

### 6.1 로컬 저장 데이터

로컬 저장 세션에서 사용하는 정보:

- 완료 세션의 `sessionId`
- 완료 세션의 `startedAt`
- 완료 세션의 상위 운동 부위 목록
- 월 범위 안의 저장 세션 목록

역할:

- 어떤 날짜에 운동이 있었는지 판단한다.
- 날짜 탭 시 어떤 결과 화면으로 이동할지 결정한다.
- 날짜 셀에 표시할 대표 부위 뱃지를 만든다.
- 월별 날짜 맵을 만든다.

### 6.2 현재 날짜 기준 데이터

현재 시각에서 사용하는 정보:

- 현재 연도 / 월 / 일
- 오늘 날짜 여부
- 미래 날짜 여부

역할:

- 오늘 날짜 스타일을 결정한다.
- 현재 월부터 과거 월 목록을 계산한다.
- 미래 날짜 비활성화를 결정한다.

현재 구현 기준 제약:

- 캘린더의 월별 표시 자체는 HealthKit workout을 직접 읽지 않는다.
- 날짜 표시와 이동 기준은 완료 세션 저장 상태에 의존한다.

## 7. 상태와 예외 케이스

### 7.1 데이터 없음 상태

가능한 빈 상태는 다음과 같다.

- 특정 월에 저장된 완료 세션이 없음
- 전체 6개월 범위에 저장된 완료 세션이 없음

현재 처리 방식:

- 운동 없는 날짜는 일반 날짜로 렌더링된다.
- 월 그리드 자체는 계속 표시된다.
- 별도의 전체 화면 빈 상태 문구는 없다.

### 7.2 미래 날짜

현재 구현 기준:

- 미래 날짜는 탭 비활성화된다.
- 스타일은 일반 날짜와 크게 다르지 않지만 동작은 막혀 있다.

사용자 관점의 의미:

- 미래 날짜에는 결과 화면이 연결되지 않는다.

### 7.3 오늘 날짜와 운동 날짜가 겹치는 경우

현재 구현 기준:

- 오늘 날짜이면서 운동한 날짜일 수 있다.
- 이 경우 오늘 강조 스타일과 운동 링 표시가 함께 렌더링된다.

사용자 관점의 의미:

- 사용자는 오늘 운동 여부를 캘린더에서도 바로 확인할 수 있다.

## 8. 현재 제약 및 비범위

현재 캘린더 화면에서 지원하지 않는 것:

- 월 끝까지 무한히 계속 추가되는 동적 월 로딩
- 한 날짜에 여러 세션 선택
- HealthKit workout 기반 월별 통계 표시
- 세션 삭제 / 편집 / 메모 수정
- 월별 합계 시간, 칼로리, 세트 수 요약

이번 문서 범위 밖:

- 운동 실행 상세 플로우
- 결과 화면 메모 수정
- 메인 화면 오늘 요약 계산
- 세션 목록 전체 히스토리 조회

## 9. 요약

캘린더 화면은 “현재 월부터 과거 월까지의 날짜 그리드 + 운동한 날짜 표시 + 결과 화면 이동”을 제공하는 날짜 중심 조회 화면이다.

현재 구현 기준으로 보면:

- 날짜 표시 기준은 로컬 저장 완료 세션 중심
- 오늘 강조와 미래 날짜 판정은 현재 시각 중심
- 운동한 날짜만 결과 화면으로 이동 가능
- 월 목록은 현재 월부터 과거 6개월까지 고정 렌더링

즉 캘린더 화면은 월별 운동 기록을 빠르게 훑고, 특정 날짜의 세션 결과로 진입하는 히스토리 탐색 화면 역할을 한다.
