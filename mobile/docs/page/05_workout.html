개요

운동 화면은 사용자가 운동을 시작한 뒤 카운트다운, 운동 중 기록, 일시정지/재개, 저장 없는 취소, 완료 저장과 외부 연동까지 이어지는 실행 플로우입니다. 본 문서는 05_workout.md를 기준으로 하되, 현재 구현 코드에서 확인한 동작만 스펙으로 정리합니다.

범위: /workout/countdown → /workout/active → /workout/[id]

라우트

src/app/workout/_layout.tsx는 운동 스택의 헤더를 숨기고, countdown과 active 화면의 제스처 뒤로가기를 비활성화하며 fade 애니메이션을 사용합니다.

시작-완료 흐름

구현상 운동 완료는 먼저 로컬 세션을 저장하고 장소/알림 동기화를 수행한 뒤, HealthKit 종료와 운동 리마인더 재동기화를 시도합니다. 캘린더 등록은 완료 후 Alert에서 사용자가 선택했을 때 실행됩니다.

카운트다운

CountdownScreen은 3초 동안 숫자와 240px 원형 링을 표시합니다. 카운트가 끝나면 startRecording()으로 세션 ID와 시작 시각을 만들고 /workout/active로 replace합니다.

  • ●startCountdown()은 이전 진행 흔적을 초기화하고 phase=countdown으로 진입.
  • ●cancelScheduledWorkoutReminder()로 기존 운동 리마인더 ID를 취소하고 저장 키를 비움.
  • ●getWorkoutLocationOnce()는 foreground 위치 권한을 요청하고 현재 좌표를 1회 저장. 실패/거부 시 null.
  • ●카운트다운 중 저장 스냅샷은 가능하지만, active 화면은 countdown 상태면 다시 countdown으로 돌려보냅니다.

운동 중 UI

ActiveWorkoutContent는 상단 스크롤 영역과 하단 고정 드로어로 구성됩니다. 스크롤 영역에는 live metrics, 주간 루틴 추천, 운동 부위 선택, 세트 수, 메모가 순서대로 배치됩니다.

HealthKit live metrics

iOS HealthKit 중심
  • ●state.phase === "recording"일 때 startHealthKitWorkoutSync가 시작됩니다.
  • ●네이티브 WorkoutSession 이벤트를 구독하고, 이벤트가 없거나 센서 대기/오류면 10초 뒤 5초 간격 polling fallback을 시작합니다.
  • ●heartRate != null || activeKcal > 0 || totalKcal > 0일 때만 생체 지표 영역을 렌더링합니다.
  • ●심박수만 없고 칼로리가 있으면 심박수는 --로 표시합니다.
  • ●상태 문구(starting, waitingSensor, error)는 운동 중 화면에 노출하지 않습니다.

운동 부위

가슴, 등, 하체, 어깨, 팔, 코어를 가로 칩으로 표시합니다. 탭하면 기본 setCount:10으로 추가하고, 다시 탭하면 해당 상위 부위의 모든 항목을 제거합니다.

세부 부위

세부 옵션이 있는 상위 부위는 400ms long press로 세부 칩 줄을 엽니다. 세부 항목은 part + detail 조합의 별도 세트 항목으로 저장됩니다.

세트와 메모

선택된 각 항목은 Stepper로 최소 1세트까지 조절합니다. 메모는 GlassTextarea 입력값을 상태에 반영하고 스냅샷 저장 대상에 포함됩니다.

주간 루틴이 활성화되어 있으면 RoutineSessionPicker가 먼저 표시됩니다. 다음 추천 세션은 최초 렌더에서 자동 선택되어 기존 선택 부위를 추천 루틴 부위로 대체합니다.

드로어 플로우

하단 드로어는 96px 높이만 남기고 접히며, 드래그로 열고 닫습니다. 타이머는 formatElapsedMs 형식인 MM:SS.CC로 표시되고, 기록 중일 때 50ms 간격으로 갱신됩니다.

접힌 상태의 핵심 컨트롤
  • ●왼쪽 원형 버튼은 유산소 시작(figure.run)이며 기록 중이고 아직 시작하지 않았을 때만 활성화.
  • ●오른쪽 원형 버튼은 기록 중 stop.fill, 일시정지 중 arrow.clockwise.
  • ●기록 중 원형 중지 버튼을 누르면 앱 상태와 HealthKit 세션 pause를 시도하고 드로어를 엽니다.
열린 상태 버튼
  • ●템포: /(tabs)/tempo?fromWorkout=1로 이동. 진행 중 복원 허용 경로입니다.
  • ●운동 중지/재개: 원형 버튼과 같은 pause/resume 액션.
  • ●운동 종료: canEndWorkoutFromDrawer가 항상 true라 기록 중/중지 상태 모두 사용 가능.
  • ●저장하지 않고 종료하기: destructive 확인 Alert 후 HealthKit discard, 스냅샷 제거, 홈 이동.

완료 연동

completeWorkout()는 완료 세션을 만든 뒤 저장소와 장소 알림을 먼저 갱신합니다. 이후 화면 레이어에서 HealthKit 종료/저장, 운동 리마인더 재동기화, 캘린더 등록 프롬프트, 결과 화면 이동을 처리합니다.

로컬 완료 저장
  • 완료 세션 본문: yb:workout:session:{sessionId}
  • 완료 세션 ID 인덱스: yb:workout:sessions
  • 날짜 키 인덱스: yb:workout:dates
  • 날짜별 대표 세션: yb:workout:date:{YYYY-MM-DD}
외부 연동
  • HealthKit live session 종료가 성공하면 true. 실패하면 저장된 접근 상태가 enabled일 때 saveWorkout fallback.
  • 운동 리마인더는 syncWorkoutReminderAtNight({ allowPrompt:false })로 22:00 예약을 맞춥니다.
  • 운동 장소 알림은 위치가 있는 완료 세션을 120m 기준으로 장소 후보에 반영하고, geofence는 2회 이상 장소 최대 20개를 150m 반경으로 등록합니다.
  • 캘린더는 Alert에서 사용자가 추가를 선택할 때 YepBuddy 캘린더를 찾거나 생성해 이벤트를 만듭니다.
캘린더 등록 실패, HealthKit 저장 실패, 리마인더/장소 알림 동기화 실패는 운동 완료 저장을 되돌리지 않습니다. 결과 화면 이동은 캘린더 Alert 선택 이후 실행됩니다.

저장/복원

WorkoutProvider는 앱 시작 시 yb:workout:current를 읽어 상태를 hydrate합니다. hydration 이후 상태가 바뀌면 1초 디바운스로 마지막 상태를 저장하고, idle 또는 completed 상태에서는 진행 스냅샷을 삭제합니다.

  • ●복원 대상: recording, paused 상태의 진행 중 세션.
  • ●타이머는 startedAt, pausedDuration, 현재 pause 구간을 이용해 다시 계산합니다.
  • ●복원된 진행 중 운동이 허용 경로 밖에서 감지되면 /workout/active로 replace합니다.
  • ●저장하지 않고 종료하면 resetWorkout()으로 상태를 초기화하고 진행 스냅샷을 제거합니다.

스펙 ↔ 코드 갭

[제약] Apple Watch provider는 타입/스텁만 있고 실제 사용 가능 상태가 아님

watchMirroredWorkoutProvider는 isAvailable: false이며 watch_provider_unavailable 오류를 반환합니다. 현재 live metrics의 실제 경로는 iPhone native live workout provider와 HealthKit 샘플 fallback입니다.

[확인] 하루 1세션 제한은 운동 실행 화면에서 강제하지 않음

완료 세션 저장은 날짜별 대표 세션 ID를 갱신하지만, 새 운동 시작을 날짜 기준으로 차단하지 않습니다. 같은 날짜에 여러 완료 세션이 있을 수 있고 날짜 조회용 대표 세션만 별도로 관리합니다.
