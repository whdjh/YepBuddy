# 02. 운동 결과 심박수 그래프 보강

> 상태: 대기  
> 선행 문서: [`01-client-stability-audit.md`](./01-client-stability-audit.md)  
> 후속 문서: [`03-android-design-refactor.md`](./03-android-design-refactor.md)  
> 완료 판정: HealthKit 데이터가 있는 iPhone 실기기 검증 필요

## 목표

프로틴 가격 그래프와 심박수 그래프가 동일한 공용 선 그래프 컴포넌트를 사용하게 한다. 심박수 그래프는 현재 세션에 해당하는 HealthKit workout과 샘플만 사용하고 실제 측정 시각 간격을 정확히 보여준다.

## 포함 범위

- `shared/ui`의 공용 metric 그래프 컴포넌트
- 프로틴 가격·심박수 그래프의 공용 컴포넌트 적용
- 저장된 HealthKit workout UUID 우선 매칭
- UUID가 없는 과거 기록의 제한된 fallback 매칭
- 선택된 workout에 연관된 심박수 샘플 조회·정규화
- 실제 시각 비율의 X축과 최고·평균·최저 통계
- 빈 데이터, 번역, 접근성, light/dark 검증

## 제외 범위

- 운동 중 실시간 심박수 수집 방식 변경
- Android 건강 데이터 연동
- 원본 심박수 샘플의 별도 로컬·서버 복제
- zone 분석, scrubber, tooltip, 대용량 downsampling
- 도메인별 데이터 정규화·문구·색상을 공용 컴포넌트에 결합

## 표시 규칙

- 유효한 샘플이 2개 이상일 때만 그래프를 표시한다.
- 샘플이 없거나 권한이 없으면 결과 화면의 나머지 정보는 정상 표시한다.
- X축은 선택된 workout의 시작부터 종료까지이며 샘플 간 실제 시간 간격을 보존한다.
- 같은 sample UUID만 중복 제거하고, 서로 다른 원본 샘플은 같은 시각이어도 유지한다.
- 공용 컴포넌트가 카드, 유효 point 처리, 최고·평균·최저 계산과 표시, 축, 선·영역, 가이드, 양 끝 라벨을 담당한다.
- 프로틴과 심박수는 원본 데이터를 `{ x, y }` point로 바꾸고 값 단위·색상·양 끝 라벨만 전달한다.

## 순차 체크리스트

### A. 공용 컴포넌트 계약과 fixture

- [ ] `02-01` `docs/page/02_result.md`에 목표 표시 규칙을 먼저 반영한다.
- [ ] `02-02` `PriceTrendChart`와 `HeartRateChart`에서 공통 컴포넌트로 옮길 계산·표시 책임을 확정한다.
- [ ] `02-03` 공용 컴포넌트의 points, 값 formatter, 색상, 높이, area, guide, 평균 표시, 양 끝 라벨 계약을 고정한다.
- [ ] `02-04` UUID 있음·없음, 같은 날 다중 workout, 샘플 없음 fixture를 만든다.
- [ ] `02-05` 종료 결과의 workout UUID 정규화와 저장 경로를 테스트한다.

### B. 공용 metric 그래프 적용

- [ ] `02-06` `shared/ui`에 카드·통계·CartesianChart·선·영역·가이드 렌더링을 모두 소유하는 공용 컴포넌트를 만든다.
- [ ] `02-07` `PriceTrendChart`는 가격 point, 가격 formatter, 날짜 라벨과 색상만 전달하는 adapter로 줄인다.
- [ ] `02-08` `HeartRateChart`는 심박수 point, BPM formatter, 시간 라벨과 색상만 전달하는 adapter로 줄인다.
- [ ] `02-09` 프로틴 가격 그래프의 기존 표시·빈 데이터·light/dark 동작이 유지되는지 검증한다.

### C. 정확한 workout 선택

- [ ] `02-10` 저장 UUID가 있으면 해당 workout만 선택한다.
- [ ] `02-11` 저장 UUID가 있는데 찾지 못하면 시간 기반의 다른 workout으로 대체하지 않는다.
- [ ] `02-12` UUID 없는 과거 기록은 시작·종료가 각각 허용 오차 안인 후보가 정확히 하나일 때만 선택한다.
- [ ] `02-13` 후보가 없거나 둘 이상이면 심박수 데이터를 비운다.

### D. 샘플 정규화

- [ ] `02-14` 선택된 workout에 연관되고 시작~종료 구간에 포함된 샘플만 조회한다.
- [ ] `02-15` 잘못된 날짜, 숫자가 아닌 BPM, 0 이하 BPM을 제거한다.
- [ ] `02-16` sample UUID 기준 중복 제거 후 시각 기준으로 안정 정렬한다.
- [ ] `02-17` 통계와 차트가 동일한 정규화 결과를 사용한다.

### E. 심박수 차트와 화면

- [ ] `02-18` 심박수 point의 X값을 workout 시작~종료 실제 시간 비율로 전달한다.
- [ ] `02-19` 0개, 1개, 동일 BPM, 긴 공백, 긴 운동을 안전하게 처리한다.
- [ ] `02-20` 시작·종료 라벨과 최고·평균·최저 문구를 ko/en에 맞춘다.
- [ ] `02-21` 차트 접근성 요약과 디자인 토큰을 적용한다.
- [ ] `02-22` 결과 수정·삭제와 프로틴 가격 그래프의 회귀가 없는지 확인한다.
- [ ] `02-23` 실제 검증 결과로 `docs/page/02_result.md`와 shared 가이드를 최종 대조한다.

## 자동 검증 게이트

- [ ] workout 매칭 fixture 테스트가 통과한다.
- [ ] 샘플 정규화·통계·좌표 변환 테스트가 통과한다.
- [ ] 프로틴 가격과 심박수 그래프가 같은 `shared/ui` metric 그래프 컴포넌트를 사용한다.
- [ ] 두 도메인 adapter가 통계 계산, GlassSurface, CartesianChart와 Skia 렌더링을 직접 소유하지 않는다.
- [ ] `bun x tsc --noEmit`과 `bun run lint`가 통과한다.
- [ ] workout-session plugin 계약 검사와 iOS native build가 통과한다.
- [ ] Android에서 HealthKit 조회와 그래프가 실행되지 않는다.

## 실기기 검증 게이트

- [ ] 실제 iPhone HealthKit workout에서 올바른 그래프를 표시한다.
- [ ] 같은 날 여러 workout이 있어도 현재 결과의 데이터만 표시한다.
- [ ] 권한 없음, UUID 없는 과거 기록, 측정 공백을 검증한다.
- [ ] 작은 화면, light/dark, ko/en 조합을 검증한다.
