YepBuddy 프로틴 백엔드/DB 최종 설계안

NestJS 백엔드 신설, 프로틴 가격 데이터 재구성, 60일 최저가 알림까지 포함한 1차 서비스 설계 문서.

작성일: 2026-06-16 범위: Protein Backend DB: PostgreSQL API: NestJS ORM: 사용 안 함, SQL 직접 관리

1. 설계 원칙

Principle

DB는 도메인 의미 기준

기존 모바일 API 이름에 맞춰 테이블을 끌고 가지 않는다. DB는 상품, 현재가, 일별 최저가, 특징, 맛 노트, 알림 이벤트처럼 실제 의미가 다른 데이터를 분리한다.

Principle

API는 화면 요구 기준

모바일은 목록과 상세 화면만 필요하다. NestJS API는 내부 DB를 조합해서 GET /proteins, GET /proteins/:id 두 endpoint로 화면 DTO를 제공한다.

Principle

가격 판단은 백엔드 책임

단백질 g당 가격, 최근 60일 기준 가격 레벨, 최저가 알림 판단은 모두 백엔드에서 계산한다. 모바일은 계산 결과를 렌더링한다.

1차 대상 프로틴

아래 6개 프로틴만 고려한다

이번 백엔드 및 DB 설계에서는 마이프로틴, 컴뱃, 다이마타이즈 엘리트, 옵티멈 골드, 옵티멈 플래티넘, 신타6만 서비스 대상으로 고려한다. 그 외 프로틴은 1차 범위에서 제외한다.

2. 정규화 최종 점검

주제 판단 이유
proteins와 가격 테이블 분리 유지 상품 스펙은 거의 변하지 않고 가격은 계속 변한다. 상품 마스터와 가격 fact를 분리하는 것이 맞다.
현재가와 일별 최저가 분리 유지 목록/상세의 현재 가격과 그래프의 하루 최저가는 목적이 다르다. 하나의 daily 테이블에 섞으면 의미가 불명확해진다.
description 제거 분리 쉼표/줄바꿈으로 여러 특징을 저장하는 text는 정규화가 약하다. protein_feature_notes로 분리해 정렬과 개별 수정을 가능하게 한다.
brand 별도 테이블 보류 브랜드 속성이 아직 없다. 지금은 text와 check constraint가 적절하다. 로고, 정렬순서, 크롤링 정책이 생기면 protein_brands로 분리한다.
category 별도 테이블 보류 앱 필터 코드값이며 값이 작고 안정적이다. check constraint로 충분하다.
마이프로틴 맛 노트 전용 테이블 유지 모든 브랜드 공통 flavor 테이블인 척하지 않고, 실제 목적대로 마이프로틴 WPC/WPI 상세용 맛 노트임을 드러낸다.
원본 가격 관측 로그 1차 제외 현재 요구는 현재가와 일별 최저가다. 모든 관측 로그는 운영 비용이 크다. 추후 가격 변동 분석이 필요하면 protein_price_observations를 추가한다.

3. 최종 테이블 역할

Master

proteins

가격을 추적하는 상품 단위다. 마이프로틴은 대표 추적 맛을 tracked_flavor에 저장하고, 상세에서는 별도 맛 노트를 함께 보여준다.

Content

protein_feature_notes

일반 특징 카드에 보여줄 사람이 작성한 상품별 특징 문구다. 기존 description을 정규화한 테이블이다.

Fact

protein_current_prices

상품별 최신 관측 가격 1개만 가진다. 목록/상세의 현재 가격과 구매 URL은 이 테이블을 기준으로 한다.

Fact

protein_daily_low_prices

KST 기준 상품별 하루 최저가다. 그래프 전체 히스토리와 최근 60일 가격 레벨 계산의 기준 데이터다.

Content

myprotein_flavor_notes

마이프로틴 WPC/WPI 상세 화면에서 보여줄 맛 이름, 개인 맛 티어, 호불호, 노트다.

Notification

protein_price_alert_events

현재 관측 가격이 최근 60일 기준 신규 최저가를 갱신했을 때 생성되는 도메인 이벤트다. 실제 push 전송과 분리한다.

4. 60일 최저가 알림 정책

정의

현재 관측 가격이 KST 기준 오늘을 제외한 최근 60일의 protein_daily_low_prices.lowest_price 최솟값보다 낮으면 신규 60일 최저가로 본다.

동률은 가격 배지에는 저점으로 볼 수 있지만, 알림은 보내지 않는다. 이렇게 해야 같은 가격이 며칠 유지될 때 반복 알림이 생기지 않는다.

1. 가격 관측 워커가 상품의 현재 가격, URL, 관측 시각을 얻는다.
2. 기준 최저가 조회 오늘을 제외한 최근 60일 daily low의 최솟값과 표본 수를 조회한다.
3. 가격 저장 현재가를 upsert하고, 오늘 daily low를 낮은 가격 기준으로 upsert한다.
4. 알림 이벤트 표본 수가 충분하고 현재가가 기존 60일 최저가보다 낮으면 alert event를 만든다.

알림 중복 방지

  • 상품별 KST 날짜당 alert event는 하나만 만든다.
  • 같은 날 더 낮은 가격이 다시 관측되면 event row를 더 낮은 가격으로 갱신한다.
  • push delivery는 별도 테이블에 기록해 같은 event를 같은 디바이스에 중복 전송하지 않는다.
  • 초기 데이터가 부족할 때 알림이 남발되지 않도록 최소 표본 수를 둔다. 권장값은 30일이다.

7. SQL 초안

아래 SQL은 새 스키마 초안이다. 기존 테이블에 바로 덮지 말고, 새 DB 또는 백업 후 적용한다. 기존 데이터 이전은 별도 INSERT INTO ... SELECT ... 또는 seed SQL로 진행한다. 

create table proteins (
  protein_id bigint generated by default as identity primary key,
  brand text not null,
  name text not null,
  category text not null,
  tracked_flavor text not null,
  package_weight_g integer not null,
  serving_size_g numeric(6,2) not null,
  protein_per_serving_g numeric(6,2) not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint proteins_brand_check check (
    brand in (
      '마이프로틴',
      '컴뱃',
      '다이마타이즈 엘리트',
      '옵티멈 골드',
      '옵티멈 플래티넘',
      '신타6'
    )
  ),
  constraint proteins_category_check check (
    category in ('wpc', 'wpi', 'wpcwpi', 'creatine', 'beta-alanine')
  ),
  constraint proteins_positive_specs_check check (
    package_weight_g > 0
    and serving_size_g > 0
    and protein_per_serving_g > 0
    and protein_per_serving_g <= serving_size_g
  ),
  constraint proteins_unique_variant unique (
    brand,
    name,
    category,
    tracked_flavor
  )
);

create table protein_feature_notes (
  feature_id bigint generated by default as identity primary key,
  protein_id bigint not null references proteins(protein_id) on delete cascade,
  body text not null,
  sort_order integer not null default 0,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint protein_feature_notes_body_check check (length(trim(body)) > 0),
  constraint protein_feature_notes_sort_order_check check (sort_order >= 0)
);

create table protein_current_prices (
  protein_id bigint primary key references proteins(protein_id) on delete cascade,
  price integer not null,
  url text,
  observed_at timestamptz not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint protein_current_prices_price_check check (price > 0)
);

create table protein_daily_low_prices (
  protein_id bigint not null references proteins(protein_id) on delete cascade,
  observed_date date not null,
  lowest_price integer not null,
  lowest_url text,
  lowest_observed_at timestamptz not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  primary key (protein_id, observed_date),
  constraint protein_daily_low_prices_price_check check (lowest_price > 0)
);

create table myprotein_flavor_notes (
  flavor_id bigint generated by default as identity primary key,
  protein_id bigint not null references proteins(protein_id) on delete cascade,
  name text not null,
  taste_tier text,
  polarizing boolean not null default false,
  note text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint myprotein_flavor_notes_tier_check check (
    taste_tier is null or taste_tier in ('T1', 'T2', 'T3')
  ),
  constraint myprotein_flavor_notes_name_check check (length(trim(name)) > 0),
  constraint myprotein_flavor_notes_unique_name unique (protein_id, name)
);

create table protein_price_alert_events (
  alert_event_id bigint generated by default as identity primary key,
  protein_id bigint not null references proteins(protein_id) on delete cascade,
  alert_type text not null default 'sixty_day_low',
  observed_date date not null,
  observed_at timestamptz not null,
  price integer not null,
  reference_low_price integer not null,
  window_days integer not null default 60,
  sample_count integer not null,
  url text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint protein_price_alert_events_type_check check (
    alert_type in ('sixty_day_low')
  ),
  constraint protein_price_alert_events_price_check check (
    price > 0 and reference_low_price > 0
  ),
  constraint protein_price_alert_events_window_check check (window_days > 0),
  constraint protein_price_alert_events_sample_count_check check (sample_count >= 0),
  constraint protein_price_alert_events_unique_daily unique (
    protein_id,
    alert_type,
    observed_date
  )
);

create table notification_devices (
  device_id uuid primary key default gen_random_uuid(),
  expo_push_token text not null unique,
  platform text not null,
  low_price_alert_enabled boolean not null default true,
  last_seen_at timestamptz not null default now(),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint notification_devices_platform_check check (
    platform in ('ios', 'android')
  ),
  constraint notification_devices_token_check check (
    length(trim(expo_push_token)) > 0
  )
);

create table protein_price_alert_deliveries (
  alert_event_id bigint not null references protein_price_alert_events(alert_event_id)
    on delete cascade,
  device_id uuid not null references notification_devices(device_id) on delete cascade,
  status text not null default 'pending',
  sent_at timestamptz,
  error_message text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  primary key (alert_event_id, device_id),
  constraint protein_price_alert_deliveries_status_check check (
    status in ('pending', 'sent', 'failed', 'skipped')
  )
);

8. 핵심 쿼리 초안

단백질 g당 가격 계산

round(
  price::numeric
  / (package_weight_g * (protein_per_serving_g / serving_size_g))
) as price_per_protein_gram

가격 관측 저장

-- 1. 현재가 upsert
insert into protein_current_prices (protein_id, price, url, observed_at)
values ($1, $2, $3, $4)
on conflict (protein_id) do update
set price = excluded.price,
    url = excluded.url,
    observed_at = excluded.observed_at,
    updated_at = now();

-- 2. KST 기준 일별 최저가 upsert
insert into protein_daily_low_prices (
  protein_id,
  observed_date,
  lowest_price,
  lowest_url,
  lowest_observed_at
)
values (
  $1,
  ($4 at time zone 'Asia/Seoul')::date,
  $2,
  $3,
  $4
)
on conflict (protein_id, observed_date) do update
set lowest_price = case
      when excluded.lowest_price < protein_daily_low_prices.lowest_price
      then excluded.lowest_price
      else protein_daily_low_prices.lowest_price
    end,
    lowest_url = case
      when excluded.lowest_price < protein_daily_low_prices.lowest_price
      then excluded.lowest_url
      else protein_daily_low_prices.lowest_url
    end,
    lowest_observed_at = case
      when excluded.lowest_price < protein_daily_low_prices.lowest_price
      then excluded.lowest_observed_at
      else protein_daily_low_prices.lowest_observed_at
    end,
    updated_at = now();

60일 최저가 alert event 생성

with reference as (
  select
    min(lowest_price) as reference_low_price,
    count(*)::int as sample_count
  from protein_daily_low_prices
  where protein_id = $1
    and observed_date >= (($4 at time zone 'Asia/Seoul')::date - interval '60 days')
    and observed_date < (($4 at time zone 'Asia/Seoul')::date)
),
eligible as (
  select
    reference_low_price,
    sample_count
  from reference
  where sample_count >= 30
    and reference_low_price is not null
    and $2 < reference_low_price
)
insert into protein_price_alert_events (
  protein_id,
  observed_date,
  observed_at,
  price,
  reference_low_price,
  window_days,
  sample_count,
  url
)
select
  $1,
  ($4 at time zone 'Asia/Seoul')::date,
  $4,
  $2,
  reference_low_price,
  60,
  sample_count,
  $3
from eligible
on conflict (protein_id, alert_type, observed_date) do update
set price = least(protein_price_alert_events.price, excluded.price),
    observed_at = case
      when excluded.price < protein_price_alert_events.price
      then excluded.observed_at
      else protein_price_alert_events.observed_at
    end,
    url = case
      when excluded.price < protein_price_alert_events.price
      then excluded.url
      else protein_price_alert_events.url
    end,
    reference_low_price = excluded.reference_low_price,
    sample_count = excluded.sample_count,
    updated_at = now()
returning *;

9. 실제 서비스 작업 순서

1. SQL 연습 새 DB 또는 백업 DB에서 create table과 seed를 직접 실행한다.
2. 조회 검증 목록, 상세, 60일 가격 레벨, 전체 히스토리 SQL을 psql/Supabase SQL editor에서 확인한다.
3. Nest 연결 pg Pool로 DB에 연결하고 repository에서 SQL을 그대로 호출한다.
4. 모바일 전환 Supabase 직접 호출을 제거하고 Nest endpoint 두 개로 교체한다.

주의

기존 운영 테이블을 바로 drop하지 않는다. 새 테이블 생성, 데이터 이전, 조회 검증, API 전환, 모바일 검증이 끝난 뒤 마지막에 제거한다.
