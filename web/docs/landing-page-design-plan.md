# YepBuddy 랜딩페이지 설계 계획서

## 1. 목표와 고정 조건

- 동아시아권 사용자가 기능뿐 아니라 사용 맥락까지 이해할 수 있는 단일 랜딩페이지를 만든다.
- 기존 `/privacy`, `/support` 페이지와 접근 링크는 삭제하거나 축소하지 않는다.
- API 키가 필요한 서비스는 사용하지 않는다.
- 아이콘은 새로 제작하지 않는다. 내비게이션, 버튼, 기능 설명은 텍스트와 레이아웃으로 해결한다.
- 색상은 모바일 앱의 토큰을 단일 기준으로 사용한다.
- 라이트모드와 다크모드를 모두 설계한다.
- 초기 설계 기준은 `landing-components.html`이다.

## 2. 디자인 토큰 기준

원본:

- `mobile/src/tokens/primitive.json`
- `mobile/src/tokens/semantic.json`
- `mobile/src/tokens/component.json`

주요 라이트 토큰:

- Background: `#FAF7F2`
- Surface: `#FFFFFF`
- Foreground: `#3A2A1A`
- Secondary text: `#876B45`
- Accent: `#9B7E56`
- Border: `#DDD2BF`

주요 다크 토큰:

- Background: `#1C1C1E`
- Surface: `#2C2C2E`
- Foreground: `#FFFFFF`
- Secondary text: `#EDE4D6`
- Accent: `#D4883A`
- Border: `#5A472D`

운동 진행 화면의 전용 색상 `#231E17`, `#C4A87E`는 랜딩페이지 전역 테마가 아니라 운동 화면 이미지와 해당 스토리 장면에서만 사용한다.

## 3. 작업 순서

### 1단계. 컴포넌트

목표: 개발 전에 사용할 HTML 컴포넌트 시트를 확정한다.

- 라이트/다크 토큰
- 타이포그래피 위계
- 텍스트 전용 내비게이션
- 주요 CTA 버튼 한 종류와 텍스트 링크
- Hero
- 공통 섹션 헤더와 편집형 기능 리스트
- 원본 스크린샷 프레임
- AI iPhone cover 프레임
- 스크롤 스토리 장면
- 최종 CTA
- Privacy Policy와 Support 푸터

산출물: `landing-components.html`

### 2단계. 이미지 소스 직접 스크린샷

아래 목록을 앱에서 직접 촬영한다. 실제 개인정보 대신 샘플 데이터를 사용한다.

| ID | 필수 화면 | 촬영 상태 | 랜딩페이지 용도 |
|---|---|---|---|
| S01 | 홈/대시보드 | 오늘의 루틴과 주간 운동 기록이 채워진 상태 | Hero 대표 이미지 |
| S02 | 운동 진행 | 운동명, 현재 세트, 휴식 또는 타이머가 함께 보이는 상태 | 스크롤 장면 1 |
| S03 | 운동 결과 | 운동 시간, 종목, 세트 등 결과 데이터가 충분한 기록 | 스크롤 장면 2 |
| S04 | 기록/캘린더 | 한 달 또는 한 주의 운동 기록이 비어 있지 않은 상태 | 스크롤 장면 3 |
| S05 | 루틴 구성 | 5~7개 운동이 들어간 실제적인 루틴 | 루틴 소개 이미지 |
| S06 | 단백질 탐색 | 검색 결과나 상품 카드가 여러 개 표시된 상태 | 단백질 탐색 소개 이미지 |

라이트/다크 준비 범위:

- 기본안: S01~S06을 라이트와 다크 각각 촬영해 총 12장을 준비한다.
- 운동 진행 화면이 앱에서 항상 전용 다크 테마라면 S02는 한 장만 사용한다.
- 일정이 빠듯하면 우선 라이트 6장을 완성하고 다크 이미지는 구현 단계에서 추가한다.

촬영 규칙:

- 같은 iPhone 기종과 같은 화면 해상도로 통일한다.
- PNG 원본으로 전달한다.
- 리사이즈, 기기 프레임, 그림자, 배경을 적용하지 않는다.
- 상태바 표시 여부와 상태바 시간, 배터리 상태를 전부 통일한다.
- 터치 표시, 디버그 메뉴, 개발용 배너가 보이지 않게 한다.
- 실명, 실제 위치, 개인 일정, 이메일은 샘플 데이터로 바꾼다.
- 텍스트가 잘리지 않고 차트와 카드가 충분히 채워진 상태를 선택한다.

파일명:

```text
S01-home-light.png
S01-home-dark.png
S02-active-workout.png
S03-result-light.png
S03-result-dark.png
...
S06-protein-dark.png
```

## 4. AI로 iPhone cover 제작

목표: 원본 UI를 바꾸지 않고 iPhone 하드웨어 외형만 입힌 투명 PNG를 만든다.

필수 조건:

- 입력 스크린샷의 UI, 글자, 색상, 숫자를 수정하지 않는다.
- 화면 위에 반사광을 강하게 넣지 않는다.
- 기기 외형만 추가하고 배경은 투명하게 만든다.
- 모든 결과물에서 동일한 iPhone 모델, 베젤 두께, 카메라 영역을 사용한다.
- 본체 색상은 뉴트럴 블랙 또는 내추럴 티타늄 한 종류로 통일한다.
- 기기 그림자는 이미지에 굽지 않는다. 그림자는 웹 조합 단계에서 CSS로 적용한다.
- 긴 변 기준 최소 2000px PNG로 출력한다.

기본 구도:

- Hero용 S01: 정면에서 3~5도만 기울인 구도
- S02~S04: 정면, 왼쪽 6도, 오른쪽 6도 구도를 번갈아 사용
- S05~S06: 정면 또는 일부가 잘린 보조 구도

AI 작업 프롬프트 초안:

```text
첨부한 앱 스크린샷의 UI와 모든 텍스트를 픽셀 단위로 그대로 유지한다.
화면을 변경하거나 새 요소를 추가하지 않는다.
스크린샷 바깥에 동일한 최신 iPhone의 뉴트럴 블랙 하드웨어 프레임만 추가한다.
얇고 현실적인 베젤, 정면에 가까운 [각도] 구도, 투명 배경 PNG로 제작한다.
기기 그림자와 장식 배경은 추가하지 않는다. 긴 변 기준 2000px 이상으로 출력한다.
```

AI 결과 검수:

- 원본과 AI 결과의 화면 텍스트가 동일한가
- 버튼, 카드, 차트의 형태가 변형되지 않았는가
- 화면 비율이 늘어나거나 눌리지 않았는가
- 모든 이미지의 iPhone 모델과 베젤이 일치하는가
- 투명 배경 가장자리에 흰색 또는 검은색 테두리가 남지 않았는가

## 5. 조합

페이지 순서와 이미지 배치:

1. Navigation: YepBuddy 텍스트와 메뉴, CTA
2. Hero: S01 iPhone cover 한 대와 핵심 카피
3. 사용 흐름: S02 → S03 → S04를 스크롤 순서로 배치
4. 기능 소개: 루틴에는 S05, 단백질 탐색에는 S06 사용
5. Final CTA: 앱 다운로드 또는 출시 안내
6. Footer: Privacy Policy, Support

조합 규칙:

- 한 장면에서 주인공이 되는 iPhone은 한 대를 기본으로 한다.
- 여러 기기를 겹칠 때 최대 세 대를 넘지 않는다.
- 배경과 그림자는 CSS로 구현해 라이트/다크에 맞춰 변경한다.
- 앱 스크린샷 안의 색은 웹 테마에 맞춘다는 이유로 임의 보정하지 않는다.
- 촬영 체크리스트와 `IMAGE 01` 같은 표시는 실제 배포 페이지에서 제거한다.

## 6. 애니메이션 적용

이미지와 문구가 확정된 뒤 적용한다.

- Hero: 카피가 먼저 나타나고 iPhone cover가 짧게 상승한다.
- 사용 흐름: 섹션을 sticky로 고정하고 S02, S03, S04를 스크롤 진행률에 따라 교체한다.
- 이미지 교체: opacity와 작은 scale만 사용하고 과도한 회전은 피한다.
- 기능 리스트: 뷰포트 진입 시 제목과 설명에 짧은 순차 등장 효과를 적용한다.
- CTA: 버튼 hover와 focus에 색상 및 1~2px 이동만 적용한다.
- 모바일: sticky 구간을 줄이고 장면을 일반적인 세로 흐름으로 단순화한다.
- 접근성: `prefers-reduced-motion` 사용자는 이동 애니메이션을 제거하고 즉시 전환한다.

## 7. 완료 기준

- 컴포넌트가 라이트와 다크에서 같은 정보 위계를 유지한다.
- 아이콘 없이도 모든 메뉴와 CTA의 의미가 분명하다.
- 모바일 앱 토큰 이외의 임의 브랜드 컬러를 추가하지 않는다.
- 모든 스크린샷은 샘플 데이터만 포함한다.
- AI 결과가 원본 앱 UI를 변경하지 않는다.
- 데스크톱과 모바일에서 이미지가 잘리거나 글자가 겹치지 않는다.
- `/privacy`, `/support`가 모든 테마에서 접근 가능하다.
